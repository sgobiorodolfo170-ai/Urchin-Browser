# ADR-024 · 双库发布与国内镜像（GitHub 真源 + AtomGit 下载）

- 日期：2026-11-18。
- 状态：采用（stable 与 dev 双库发布）。
- 授权：用户明确指令（2026-11-18）：「以后推送默认 GitHub，发布（稳定版、开发版）双库发布」；同时要求核查 AtomGit 自动同步设置。

## 1. 背景与约束

国内用户从 GitHub 下载 318 MB 级安装包不稳定。实测 AtomGit（与 GitCode 同源）项目可承载整包：

- 单文件 333,138,071 B（317.71 MiB）上传 176–184 秒，公开下载 57–86 秒，SHA-256 与本地一致。
- Gitee 社区版限制单附件 100 MB、单仓库附件总量 1 GB，318 MB 整包必须分卷，故不采用。
- AtomGit 账号登录名（如 `gcw_t5fqBPf3`）由系统生成且不可修改；命名空间诉求通过组织 `daichuanmu` 满足。

## 2. 决策

1. **GitHub 是唯一真源**：代码、标签、Issue、Pull Request、CI 以 GitHub 为准；日常提交与推送只走 GitHub（`origin`）；应用内自动更新以 GitHub 为兜底源，国内优先 AtomGit（见 §2.4）。
2. **AtomGit 是只读镜像与国内下载入口**：仓库 <https://atomgit.com/daichuanmu/Urchin-Browser> 由平台 Pull 镜像同步 GitHub 的分支与标签，不手工推代码（首次全量镜像除外），不接受 Issue / PR。平台未公开自动同步周期；实测新提交 20 分钟内未自动出现，故发布流程要求在推送标签后**显式触发一次同步**并核对引用（见 §3.1）。
3. **发布双库**：稳定版（`X.Y.Z`）与开发版（`X.Y.Z-dev.NNN`）均同时在 GitHub 与 AtomGit 创建 Release；两侧上传同一组资产——安装包、`*.blockmap`、对应通道清单（stable 为 `latest.yml`，dev 为 `dev.yml`）。AtomGit Release 正文标注「自动更新：国内优先 AtomGit，GitHub 兜底」。
4. **自动更新国内优先、GitHub 兜底**：国内用户（系统语言 `zh*` 或时区为中国大陆）先查 AtomGit 国内 Release；国内无更新、接口失败或资产缺失时自动回退 GitHub。`electron-builder.yml` 的 `publish` 段保持 GitHub 配置，作为运行时默认源与兜底源；AtomGit 源在检查时动态切换（generic provider），不写进安装包配置。
5. **令牌治理**：AtomGit 令牌只从环境变量 `ATOMGIT_TOKEN` 读取，不写入仓库、脚本、日志或文档；令牌一旦在会话/终端中明文出现，应轮换。
6. **失败处置**：GitHub 发布为主，AtomGit 上传失败不回滚 GitHub，但必须在 [打包核查清单 §10](../打包核查清单.md#10-核对记录) 记录失败与处置。

注意：Pull 镜像只同步代码与标签，**不同步 GitHub Releases**；Release 与资产仍需单独发布（见 §2.3）。

### 3.1 手动触发同步

平台文档只说明 Push 镜像在每次提交后自动触发，未给 Pull 镜像的同步周期；实测 2026-11-18 20:03 推送到 GitHub 的提交，到 20:25 仍未出现在 AtomGit（`repo_remote_mirror.last_update_at` 停在 19:48:31）。可用 API 显式触发：

```powershell
$h = @{ 'PRIVATE-TOKEN' = $env:ATOMGIT_TOKEN; 'Accept' = 'application/json' }
Invoke-RestMethod -Method Post -Headers $h `
  'https://api.atomgit.com/api/v5/repos/daichuanmu/Urchin-Browser/sync_remote_mirror'
# -> {"message":"202 Accepted"}

# 轮询状态与引用，确认同步完成
Invoke-RestMethod -Headers $h `
  'https://api.atomgit.com/api/v5/repos/daichuanmu/Urchin-Browser/repo_remote_mirror' |
  Select-Object update_status, last_update_at, number_of_failures
git ls-remote https://oauth2:$env:ATOMGIT_TOKEN@atomgit.com/daichuanmu/Urchin-Browser.git
```

本次触发后约 20 秒完成（`last_update_at` = 20:28:44），`main` 从 `b58d59f` 前进到 `9bf2192`，19 个 refs 与 GitHub 差异 0。发布 AtomGit Release 前必须先确认目标标签已在镜像中，否则 Release 会因标签不存在而失败。

**频率限制**：同一仓库短时间内重复触发会返回 `403`，错误信息 `Sync too frequently, please try again later`（2026-11-18 20:32 在上次成功 4 分钟后再触发即被拒）。每个发布版本只触发一次，若被拒先等待冷却，不要密集重试；冷却时长平台未公开，实测以「上次成功时间 + 数十分钟」为安全起点。

### 3.2 应用内更新源选择（2026-11-18）

代码位置：`apps/desktop/src/main/update/update-source.ts`（纯选择逻辑）+
`update-service.ts`（`preferDomestic` 分支）。规则：

1. **是否国内**：`app.getLocale()` 为 `zh*`，或系统时区属于 `Asia/Shanghai`、`Asia/Chongqing`、`Asia/Harbin`、`Asia/Urumqi`；否则直接用 GitHub（原行为不变）。
2. **选国内 feed**：匿名拉取 AtomGit 公开 Release 列表（4 秒超时，无令牌），按当前通道挑选：
   - stable → 最新正式版且资产含 `latest.yml`；
   - dev → 最新预发布版且资产含 `dev.yml`；
   - 图标齐全才算可用，避免选中「Release 已建但资产未传完」的条目。
3. **切换方式**：把该 tag 的下载目录
   `https://atomgit.com/daichuanmu/Urchin-Browser/releases/download/<tag>`
   设为 electron-updater 的 generic feed，再执行原有「dev → latest」两段检查。
4. **兜底**：以下任一情况都会恢复包内 `app-update.yml` 的 GitHub 源并再查一次——国内 Release 列表拉取失败、无当前通道 Release、feed 检查抛错、国内判定为「无更新」（镜像落后于 GitHub 时 GitHub 仍可能已有新版）。因此**AtomGit 落后不会让用户漏掉更新**。
5. **下载同源**：更新检查在哪个源命中，`downloadUpdate()` 就沿用该源的 provider 与资产 URL，不再二次选择。

已知限制：AtomGit 匿名 API 有频率限制（大量用户同时检查可能 403），触发兜底后不影响结果；国内 Release 必须上传 `latest.yml` / `dev.yml`，否则该版本不会被国内源选中。定向单测：`update-source.test.ts` + `update-service.test.ts` 共 38 例通过（2026-11-18）。

## 4. 已否决方案

- **Gitee 作为主下载源**：单附件 100 MB / 总量 1 GB，318 MB 整包需分卷，用户体验与维护成本都不可接受。
- **GitHub Actions 推送 AtomGit**：令牌需进入 GitHub Secrets，318 MB 流量经 CI 出口更慢且易受网络波动影响；本地发布脚本更直接、凭证边界更小。
- **手工双推代码**：两套远端长期必然漂移；改用平台 Pull 镜像后只需维护 GitHub。
- **AtomGit 作为唯一更新源**：GitHub 不可达时国内用户将完全失去更新（镜像可能落后、资产可能缺失、匿名 API 有限流）；采用「国内优先 + GitHub 兜底」后收益保留、单点风险消除（见 §3.2）。
- **继续使用个人命名空间 `gcw_t5fqBPf3`**：登录名不可改且不适合对外；组织 `daichuanmu` 提供稳定、可读的命名空间。

## 5. 风险与限制

- **旧链接不保证重定向**：仓库改名/转移/删除后，已发出的下载 URL 可能直接 404；发布新地址时需同步更新 README 与发布说明。
- **配额未公开**：单文件 318 MB 已实测通过，但账号/组织总配额无公开数字；建议只保留最近 3 个 stable 的附件，按实际用量清理。
- **WAF 行为**：伪造浏览器 UA + 大 Range 请求会被 CloudWAF 返回 418；发布校验使用常规客户端并带重试，发布后人工点一次下载。
- **镜像延迟**：平台未公开 Pull 镜像的自动同步周期；实测新提交 20 分钟内未自动同步，手动触发 `sync_remote_mirror` 后约 20 秒完成。发布流程不得以「已开启镜像」代替验证，必须触发同步后用 `git ls-remote` 比对引用。
- **只读边界**：AtomGit 上的 Issue / PR 不会被处理，README 与 Release 正文需明确指回 GitHub。
