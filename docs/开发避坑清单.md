## 一、构建 / 配置 / 字节一致性

1. `.gitattributes` — 保持 `text=auto eol=lf`。Windows 的 autocrlf 会改写 checkout 字节，造成「本地没问题、CI 判不一致」。换行策略改动前先对齐 `.editorconfig` 与 `.prettierrc.json`（`endOfLine: lf`）三处。
2. `.lintstagedrc.js` — ESLint 9 对被 ignore 的文件会直接报 `No files matching`（不是"跳过"），所以 config 类文件必须用函数过滤掉、只走 Prettier，否则每次提交必红。
3. 根 `package.json` — 不要用 `packageManager` 字段"伪装 traversal"绕过 pnpm 限制；`overrides` 里的 9 条 pin 是为修 `mcpStructuredContentSchema` 导出缺失，升级 earendil / pi 系依赖时必须重验。
4. `apps/desktop/vite.config.ts` — 为规避 `node:sqlite` 顶层 require 崩溃而加的桩别名，必须同时出现在 `alias` 里且优先级高于 `external`；pi 源码别名要指向 `src` 跳过 dist，否则改源码不生效。
5. `scripts/build-pi-web.mjs` — 必须在 desktop `build:main` **之后**执行，否则会清空刚产出的构建窗口。
6. `apps/desktop/ico/process-icon.ps1` — 依赖 `System.Drawing`；PowerShell 5.1 保存该脚本必须带 UTF-8 BOM，否则中文注释解析失败。`build/` 不入库，打包前需先生成图标。

## 二、Electron 进程与视图边界

7. `apps/desktop/src/main/tabs/tab-manager.ts` — 主进程是 tab 状态唯一权威源；`TabSnapshot` 必须剔除 `webContents` / `view`（不可序列化且会泄漏），跨 IPC 只传快照。
8. `create-browser-view.ts` 与 AI 侧 BrowserView — **不要注入 preload**：会阻塞网页加载。需要的信息一律走主进程注入或事件。
9. `apps/desktop/src/main/index.ts` — 数据目录遵循 DD1；`URCHIN_DISABLE_GENOFFICE` 是 GenOffice 总开关；EPIPE 错误风暴防护与事件循环 watchdog 都是踩过坑后加的护栏，别当冗余删掉。
10. `worker-threads-polyfill.ts` — 纯副作用模块（无导出），必须**最先**加载；晚于其它模块则会因 `worker_threads` 已被引用而失效。
11. AI 域 `register-handlers.ts` — `ai.agent.start` 强制 `enableTools=false`（SEC-2026-08-14：coding 工具等于任意命令执行），恢复条件是把对话迁回 utility 子进程；`OPENAI_COMPATIBLE_API` 的 api 形态必须是 `openai-completions`。
12. `apps/desktop/scripts/launch.mjs` — 直接 `electron .` 未设 `NODE_ENV=production` 会走 dev 分支连 vite dev server，表现是**白屏**；生产启动一律走 `pnpm start`。

## 三、数据 / 持久化 / 迁移

13. `mail-storage.ts` — SQLite 布尔存的是 INTEGER，出参必须转 `boolean`；漏转会导致 zod 出参校验失败，症状是"列表空了"而不是明确报错。
14. `data-location.ts` — 开发态数据根是 `apps/desktop/data`，打包态是 `userData/data`；pi 数据固定 `userData/pi` 且**不可配置**。测试要隔离时用 `URCHIN_TEST_USER_DATA` + `URCHIN_TEST_DATA_DIR` 双变量。
15. `secret-store.ts` — 密钥只经 safeStorage 加密落盘（`secrets/<providerId>/<keyName>.enc`），任何"明文存 SQLite"都是回归；路径参数走白名单防穿越。
16. `storage-layer.ts` — 分库策略：主库 `urchin.db` + AI 库 `ai.db` + per-provider / per-extension 独立库；连接池上限是代码常量（见 [事实登记表](./事实登记表.md) F7），改数值改代码，不回改决策文档。

## 四、集成边界（dsh / pi-web / GenOffice / 传输）

17. `deepseek-harness/launcher.ts` — 必须用**便携 node.exe** 拉起 dsh：`node-addon-require-builtin` 拒绝 Electron 的 V8 指纹。`STARTUP_TIMEOUT_MS=120s`、`--no-open` 防拉系统浏览器、`DSH_HOME=userData/deepseek-harness`。
18. dsh 的 `register-handlers.ts` — launch 超时给到 180s；默认 30s 会让渲染层先放弃，症状是"点了没反应 / 开不出标签"。
19. pi-web 的 launch handler — 超时 90s 且必须大于冷启动 60s，否则冷启动期必然判失败。
20. dsh 的 `tab-lifecycle.ts` — 与 pi-web **语义不同**：关掉前端标签即停 dsh 后端。改生命周期前先确认是哪一套。
21. GenOffice `sheets` 编辑器 — 必须传 `includeAiHandlers=false`（GF6），否则 `ai:get-settings` 二次注册冲突导致崩溃。
22. GenOffice `home-handlers.ts` — 单一 `genoffice:home` invoke + 事件推送；文件名必须过 `isPlainName` 防路径穿越；CLI 不随包分发。
23. `packages/pi-web-host` — 零 Electron 依赖、可起真端口做单测；`auth.ts` 的 token 只存内存、重启即换，不要持久化。

## 五、前端渲染 / UI

24. `FileViewer.tsx` — Markdown 禁止渲染 raw HTML，链接协议仅放行 `http/https/mailto/#`；json/txt 走 React 文本节点。文件读取上限 2MB（超限提示"文件过大"，不要整读）。
25. `workspace-colors.ts` — 色值必须写字面量：Tailwind 走静态扫描，动态拼接的 class 不会被生成，症状是"颜色时有时无"。
26. `favicon-service.ts` — 拒绝 SVG（XSS 面）、单图标 ≤1MB、TTL 7 天、缓存 ≤4096；改上限时多处一起改。
27. `install-shortcuts.ts` — F12 由主进程拦截；侧栏面板里的输入框按 F12 会**关闭面板**（已知行为，不是 bug）。
28. `status-bar-overlay.ts` — 用透明 `BrowserWindow` 规避 Windows DWM/TDR；状态权威在主渲染进程，覆盖窗只做展示。
29. `view-integration.ts` 与 `App.tsx` — AI 是独立 `urchin://ai` 标签；左侧栏默认折叠宽度两处必须同步改。

## 六、脚本 / 门禁 / 发布

30. `scripts/build-version.mjs` — 遵循 [ADR-012](./decisions/ADR-012-发布通道与版本号治理.md) 单版本线：新版本低于或等于既有 stable 直接失败；**不要在别处复述** version → 通道映射。版本号从 CHANGELOG **表尾行**解析——并行会话追加行不按时间序/写成 GBK 乱码会静默盖错版本戳（2026-11-10 dev.174 事故），打包前先 `node scripts/build-version.mjs` 核对解析值。
31. `scripts/check-before-push.mjs` + `mark-verify-ok.mjs` — push 前比对 `.git/urchin-verify-ok` 的内容指纹。正确顺序是**先 `prettier --write` → 再 `pnpm verify` → 再提交**；先 verify 后格式化会让 lint-staged 二次改写内容，指纹对不上而被拦（这是门禁正确行为，不是误报）。
32. `scripts/check-commit-trace.mjs` — 提交信息必须含 `Model:` / `Trigger:` / `Loop:` 三行；merge / revert 提交豁免。
33. `scripts/after-pack-dsh-peers.cjs` — 除补齐 peer-only 依赖外还做 **MAX_PATH 剪除**（相对路径 >188 删除，>195 直接打包失败）：NSIS `--updated` 事务式卸载把旧文件 Rename 到 `%TEMP%\nsX.tmp\old-install`，暂存目标 >259（MAX_PATH）即 MoveFile 必败 → 卸载器 `Abort`（退出码 2）→ 报「Failed to uninstall old application files ... : 2」，重试 5 次全败（2026-11-10 dev.175 事故，详见[打包核查清单](./打包核查清单.md) §8 F12）。新增依赖若带超长文件路径，打包日志必须出现 `MAX_PATH 剪除 N 个` 且残余为 0。
34. 自动更新安装模式 — dev.176 起用**可见安装向导**（`quitAndInstall(false, true)`）。静默装（`true`）在 NSIS 就地解压的 1-2 分钟内无任何进度参照，用户会以为没反应而手动点击图标启动应用 → 半装树启动 → 主进程报 `Cannot find module 'better-sqlite3'`（uncaughtException 弹窗，且发生在 logger 初始化之前、无日志留痕）。改回静默前先解决进度反馈与重复启动两道问题。
35. 主进程里的原生模块依赖 — `better-sqlite3` 在两处**按需 `await import()`**，都不要改回静态导入：`import/firefox-profiles.ts`（书签导入）与 `storage/sqlite-factory.ts` 的 `loadSqliteFactory()`（2026-11-11 dev.185 补齐）。静态导入会让主进程共享 chunk 顶层 `require('better-sqlite3')`，原生模块瞬时不可用（安装半装/杀软锁文件）即全应用启动崩溃；按需加载把故障面收敛到可捕获的调用点——storage 侧由 `bootstrap/native-module-guard.ts` 兜成「安装文件不完整，请重新运行安装包」提示 + 退出码 1。**安装树是否完整的硬指标**（267 个 node_modules / better-sqlite3 / genoffice+node+native+wasm / 卸载器）见[打包核查清单](./打包核查清单.md) §8 F14；另外静默安装 `/S` 拷贝 54k 文件在 Defender 下要 ~10 分钟，期间安装目录可能长时间无变化，**别据此判卡死**。
36. `webContents.savePage(path, 'MHTML')` — **文件先创建、内容后写入**。E2E 用 `existsSync` 轮询命中后立刻 `readFileSync` 会读到 0 字节（2026-11-10 clipper.spec `--repeat-each=5` 复现 1 次，报 `Expected substring "MIME-Version"，Received ""`）。判据必须是「内容满足格式断言」（见 `tests/e2e/helpers/clipper.ts` 的 `waitForClipFile`），不要用「文件存在」。
37. 项目脚本不要自建 GUI 弹窗 — 2026-11-10 起 E2E 选择改由 AI 会话内的复选/问答工具完成，`scripts/e2e-select.mjs` 只算推荐与执行，**不得再引入 PowerShell/WinForms 窗口**。如果未来确有脚本弹窗需求（非本流程）：本机没有 `pwsh` 7，只有 Windows PowerShell 5.1，`.ps1` 必须写 **UTF-8 BOM**（无 BOM 时按 ANSI 解码，中文全乱码），且中文文案不要经 `-Command` 内联传递。
38. `git status --porcelain -z` 的重命名条目 — 格式是 `R  new\0old`，解析时必须跳过紧随其后的旧路径，否则「旧路径」会被当成改动、触发无关 spec；未跟踪文件另用 `git ls-files --others --exclude-standard` 取。参考 `scripts/e2e-select.mjs` 的 `collectChangedFiles`.
39. GenOffice CI 缓存 — `ci.yml` 的 `genoffice-...-vN-...` key 只哈希 `vendor/genoffice/package-lock.json` + `scripts/genoffice-build.mjs`。升级 vendor 上游时若**只改源码未改 lock**，必须手动把 key 里的版本号递增，否则 CI 会一直用旧产物（`--check-only` 只验证齐全，不验证新鲜度）。**v2（2026-11-10）**：缓存路径必须包含 `vendor/genoffice/apps/*/node_modules`——pdf 的 `harfbuzzjs/hb-subset.wasm` 是嵌套安装，只缓存根 `node_modules` 会让 `--check-only` 报 MISS（run 42800787236 实测）。
40. `vendor/genoffice/package-lock.json` — 与 `vendor/genoffice/**/package.json` 必须同步。2026-11-10 实测：`apps/urchin-embed` 的 electron 已写 `^43.8.0`，但 lock 仍钉 43.3.0；本机因 `node_modules` 已存在不会触发 `npm ci`，CI 干净环境直接 `npm error EUSAGE ... Missing: electron@43.8.7 from lock file`。**凡是升级 vendor 依赖，必须在 `vendor/genoffice` 下跑一次 `npm install --package-lock-only` 并提交 lock**；验证用 `npm ci --dry-run`（不应有 MISSING）。
41. vendor/genoffice 干净安装的 `npm ci` — 必须加 **`--ignore-scripts`**：根 `postinstall: install-electron` 需要根 `node_modules/electron` 的 bin，而 npm 把 electron 嵌套安装到 `apps/*/node_modules`，CI 会报 `'install-electron' is not recognized`。忽略脚本后构建（electron-vite + cargo + notices）不需要 Electron 二进制。
42. vendor/genoffice 构建的主版本 — electron-vite 优先读 `ELECTRON_MAJOR_VER`，否则 `require.resolve('electron/package.json')`；根包不存在会 `Cannot find module 'electron/package.json'`。`genoffice-build.mjs` 已默认注入 `ELECTRON_MAJOR_VER=43`（与上游 pin 的 `^43.8` 对齐）；升级 Electron 大版本时同步改这里。

## 七、划词翻译结果卡（悬浮子窗口）

43. `translate/selection-rect.ts` — 选区行数必须按 client rect 的**行中线去重**计数：同一行内的 `<b>`/`<a>` 等内联节点各返回一个 rect，按 `top` 直接计数会把单行误判成多行、卡片高度随之虚高。几何只在 `context-menu` 事件里读一次（此时选区还在页面里）；等菜单点击后再读，选区可能已被页面脚本清空。
44. `translate/selection-card-overlay.ts` — 卡片尺寸 = 译文尺寸与**选区几何**取并集（`resolveTextSize`），只按译文自身排版会把短译文折叠成小方块（2026-11-10 用户反馈）。高度上限由 `maxCardHeightFor` 按内容区高度放大（默认 `MAX_CARD_HEIGHT` 264 / 硬上限 560），改上限别只改 `MAX_CARD_HEIGHT`。

## 八、退出与托盘

45. 退出清理 · **子进程不会随主进程自动消失**（Windows 尤其如此）：`utilityProcess` / `spawn` 出的 pi-web-host、dsh（node.exe 及其孙进程）、AI Provider、GenOffice sidecar 都必须在退出流程显式回收。`lifecycle/cleanup.ts` 的顺序不能改反——**先 `snapshotChildPids` 快照 PID，再 dispose**（`disposeHost` / `killChild` 会先清空启动器引用，事后取不到 PID），宽限期后由 `terminateChildProcesses` 用 `taskkill /PID <pid> /T /F` 兜底强杀并复核。新增子进程启动器时，务必把 `status().pid` 接进 `snapshotChildPids`，否则它会成为残留进程。`runCleanupAndExit` 的 10s 硬超时是防「清理挂死 → 窗口没了进程还在」的最后保险，不要改成无限等待。
46. 托盘驻留 ≠ 正常关闭：`ui.minimizeToTray` 开启时窗口 close 被 `preventDefault + hide`，**不得**进入 `performCleanup`（否则 pi/dsh/GenOffice 子进程会被杀掉，用户下次唤回后功能全失效）；只有托盘菜单「完全退出」或 `app.quit()` 才走清理。托盘图标创建失败（空图标/异常）时必须放弃隐藏、按正常关闭退出——否则窗口隐藏后无入口，进程被锁死。

## 九、本地文件关联与打开路由（默认应用 / 打开通道）

47. `main/index.ts` 的命令行解析必须传 `app.getAppPath()`：开发模式与 `pnpm start` 都是 `electron <appDir> "%1"`，`argv[1]` 是**应用目录**而不是用户文件。只跳过 `argv[0]` 会把目录交给查看器，表现为「右键用本浏览器打开图片/视频一律报错」（2026-11-11 R1）。改命令行解析时用 `parseOpenArgs(argv, app.getAppPath())`，不要手写 `argv.slice(1)`。

48. `file-association/associations.ts` — **不要写 `HKCU\Software\Classes\.ext` 的默认值**。那是静默劫持：不可回滚、Win10/11 有 `UserChoice` 时直接失效，还会改坏 `.bat`/`.js` 等系统关键关联（旧模型就是这么把 `双击 .bat` 变成不执行的）。正确模型是 `Applications\<exe>` + `Capabilities\FileAssociations` + `OpenWithProgids`，让用户在系统里确认（见 [ADR-020](./decisions/ADR-020-文件关联注册模型.md)）。可注册格式以 `ASSOCIABLE_EXTENSIONS` 白名单为准，**不要**按 `EXT_KIND` 全量登记。

49. 状态查询读 `Capabilities\FileAssociations`，不要读 `.ext` 默认值：后者与系统实际默认（`UserChoice`，带 hash）无关，会把「改过默认值」误报成「已关联本应用」。旧实现还按扩展名逐个起 `reg.exe`（50 个扩展 ≈ 1~3 秒），现在固定 2 次。另：PDF 内联渲染依赖主窗口 `webPreferences.plugins: true`，关掉就只触发下载。

50. 打开文件的通道**由入口决定，不由格式决定**（[ADR-021](./decisions/ADR-021-打开文件职责划分.md)）：外部入口（文件关联 / 命令行 %1 / Ctrl+O / 拖放）走浏览器通道，唯一例外是 docx/pptx/xlsx 直进 GenOffice；GenOffice 主页入口才走编辑器，且打不开的格式转交浏览器。**不要在任何地方再写一份 kind→通道映射**——真源是 `src/shared/file-routing.ts` 的 `resolveOpenTarget(kind, name, origin)`；渲染层也不许自己 `file.stat` 判类型后拼 `urchin://` 地址，统一 `invoke('file.openPath', { path, windowId })` 交给主进程 `openLocalEntry`（目录 → 浏览页 / 文件 → 路由）。历史教训：主进程与 `App.tsx` 各有一份 `genofficeAppByKind`，文件关联与侧栏打开同一文件落到不同通道。
51. 「最近打开」是否记入由**扩展名能力表**决定（`GENOFFICE_EDITABLE_EXTENSIONS`），**不要用 kind**：`kind='text'` 同时覆盖 `.txt/.json/.csv`（该记）与 `.js/.sh/.ps1/.css`（不该记），按 kind 判会把临时脚本塞满列表。GenOffice 将来新增图片/音视频编辑器时只在该表追加扩展名，路由与 recents 同时生效；但**不要**顺手把新 kind 加进 `EXTERNAL_GENOFFICE_KINDS`（外部例外只保留 Office 三类，否则图片阅读会被 GenOffice 抢走）。

## 十、vendor 升级与依赖治理

52. 升级 `@deepseek-ai/dsh` 主版本必须**连同 `node_modules/.pnpm/lock.yaml` 虚拟存储快照一起移走**再全量重装：pnpm 每次都从该快照恢复旧 peer 变体，只重生成主 lockfile / `pnpm install --force` / 剪条目重装均无效（2026-11-12 dev.193 整改实测：主 lockfile 与快照 md5 一致、1,139,808 字节，升级后依赖树纹丝不动，这就是「改了版本号但依赖树没变」的机制）。正确顺序：改 `apps/desktop/package.json` 版本（唯一真源）→ `pnpm sync:dsh` 同步 vendor → 移走主 lockfile 与快照 → `pnpm install --no-frozen-lockfile` → `pnpm check:dsh` 三源一致 → `node scripts/prune-foreign-platform-packages.cjs --dry-run` 应 0 待删 → 打包看 `[dsh-gate]` 版本分布单一且冒烟 `stderr=0B`。
