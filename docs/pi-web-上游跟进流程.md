## 三、五步跟进流程

1. **更新真源**：对照库 fetch/checkout 到目标版本 → F9 登记新基线（版本 + 日期）。
2. **只读 diff 分类报告**：对 `server/` 与 `web/`（含协议 `protocol.ts`、依赖清单）做基线间 diff，按「业务功能 / 引擎相关 / 平台壳」三分类列新增、修改、删除，每项标注相关度（在用功能面 / 已裁引擎面 / 主权层冲突）。
3. **逐项决策表**：每行 = 上游变更 → 影响的本地文件 → 建议【采纳 / 参考 / 跳过 / 需用户决策】→ 理由；引擎代码一律预标「跳过」，主权层冲突一律预标「需决策」。
4. **分批执行**（经用户确认后）：每批 = 复制/适配 + 引擎再裁剪 + 本地定制重放 + 独立提交；涉及依赖或打包产物变化时按[打包核查清单](./打包核查清单.md) §9 核对。
5. **门禁与留痕**：verify + pi-web 前后端测试 + `pi-web-host.spec` E2E；台账登记新基线与裁剪差异；CHANGELOG 行。

## 四、三场景提示词模板

### 场景 A · 纯参考（只想看上游更新了什么）

```text
【上游参考】pi-web-ui：对照库（F9）当前基线 0.118.0，请更新到 <目标版本/tag> 并重新登记基线。
然后只读 diff 上游 0.118.0..<目标> 的 server/ 与 web/，产出变更报告：按「业务功能 / 引擎相关 /
平台壳」三分类列新增、修改、删除；对每项标注与本项目的相关度（我们在用的功能面 / 我们裁掉的
引擎面 / 与主权层冲突）。本任务不改任何代码，报告落盘供我决策。
```

### 场景 B · 定向移植（要上游某个具体新功能）

```text
【上游定向移植】目标功能：<功能名>。
阶段一（只读）：① 在对照库定位该功能的完整实现面——server 文件 + web 前端文件 + 协议消息
（protocol.ts）+ 新增依赖；② 逐项检查与裁剪边界（pi 单引擎；dsh_ 前缀组件是否 pi 共用）、
结构决策（pi-web-测试交接-2026-11-08 §3：tsconfig/eslint 排除项不要回退）、主权层
（鉴权/入口/就绪行）的冲突；③ 列出会被覆盖的本地定制清单；④ 产出移植方案（复制哪些、
改哪些、补哪些测试），停下等我确认。
阶段二（经我确认后）：按方案执行，其他引擎代码不得带入；pnpm verify + pi-web 相关测试 +
pi-web-host.spec E2E 全绿后按台账留痕提交。
```

### 场景 C · 基线升级（整体跟版）

```text
【上游基线升级】目标：pi-web-ui 基线 0.118.0 → <目标版本>。严格执行两阶段：
阶段一（只读）——更新对照库并登记 F9 新基线候选；全量 diff 产出逐项决策表（每行：上游变更 →
影响的本地文件 → 建议【采纳/参考/跳过/需我决策】→ 理由），其中其他引擎代码一律预标「跳过」、
主权层冲突一律预标「需决策」，未经我逐项确认不得动任何文件。
阶段二——按我确认的清单分批执行：每批 = 复制/适配 + 引擎再裁剪 + 本地定制重放 + 独立提交；
涉及依赖或产物变化时按打包核查清单 §9 核对；收尾全量门禁 + pi-web 测试 + E2E，台账登记
新基线，CHANGELOG 留痕。
```
