## 2. 一期目标（完成定义，可机器判定）

1. **F12** 打开/关闭「检视列」（右侧第三列，网页保持可见）；列宽可拖拽，BrowserView bounds 实时联动。
2. 点击「开始检视」→ 对目标标签 `webContents.debugger.attach('1.3')` + `Network.enable` / `Runtime.enable` / `Log.enable`，面板状态显示 `attached`。
3. 页面网络请求、`console.*` 输出、未捕获异常进入面板展示；DT7 性能策略落地（批处理 + 环形缓冲）。
4. 面板内可执行表达式（`Runtime.evaluate`），显示返回值/异常。
5. 目标标签关闭、原生 DevTools 打开、应用退出 → 会话自动 detach，状态回 `detached`。
6. 内部页（`urchin://**`）与 GenOffice 标签（`viewKind=genoffice`）明确拒绝检视（`unavailable` + 原因），不 attach。
7. `pnpm verify` 全绿（typecheck + lint + 单测含新增用例）；`pnpm e2e` 含新增 spec 通过；`pnpm run build` + `pnpm start` 人工验收。

## 3. 已确认决策（DT9-DT13，2026-10-25 用户确认）

## 4. 架构与数据流

```
tab.webContents.debugger ──message──▶ DevtoolsManager（主进程，Map<tabId, Session>）
                                         │  Network/Console 聚合 + RingBuffer(1000) + 200ms batch
                                         ▼  sendToMainWindow('devtools:event', payload)
                                主窗口 React（window.urchin.on 订阅）
                                         │  invoke('devtools.*' / 'ui.layout.setState')
                                         ▼
                              右侧第三列 DevToolsPanel（Network / Console / 求值）
```

- 主进程模块：`apps/desktop/src/main/devtools/`（结构见 §6）。
- 采集事件 → 会话内聚合为 `NetworkEntry` / `ConsoleEntry` → 环形缓冲（FIFO 淘汰 + dropped 计数）→ 200ms 定时合并为 `devtools:event` 批推送（经 `sendToMainWindow` 广播）。
- 渲染层持有镜像状态：面板打开/绑定目标时先订阅事件、再 `devtools.network.list` / `devtools.console.list` 拉快照，批事件增量合并（依据条目 `seq` 去重，见 §7.2）。
- 事件推送通道命名沿用冒号惯例（`tab:event` / `translate:progress` / `update:event`）：`devtools:event`（数据批）与 `devtools:toggle`（F12 触发）。

## 5. IPC 契约设计（契约 B 新增通道）

zod schema 落于 `packages/ipc-contract/src/schemas/ipc-schema.ts`（单一真源）；事件通道常量由 `@urchin/ipc-contract` 导出（主进程与渲染层共用，防字面量漂移）。

| 通道 | req | res | 说明 |
|---|---|---|---|
| `devtools.attach` | `{ tabId }` | `{ state, reason?, target? }` | 开始检视；幂等（已 attached 直接返回状态） |
| `devtools.detach` | `{ tabId }` | `{ ok: true }` | 停止检视（flush 尾批后 detach） |
| `devtools.status` | `{ tabId }` | `{ state, reason?, target? }` | 状态查询 |
| `devtools.network.list` | `{ tabId }` | `{ entries, dropped }` | 全量快照（环形缓冲内容） |
| `devtools.network.clear` | `{ tabId }` | `{ ok: true }` | 清空网络缓冲 |
| `devtools.console.list` | `{ tabId }` | `{ entries, dropped }` | 全量快照 |
| `devtools.console.clear` | `{ tabId }` | `{ ok: true }` | 清空控制台缓冲 |
| `devtools.evaluate` | `{ tabId, expression(≤8KB), awaitPromise? }` | `{ ok, result?, exception?, error?, truncated? }` | `Runtime.evaluate`（returnByValue） |

- `state`：`detached | attached | unavailable`（v2 修订：删除 `attaching` 瞬态——Electron `debugger.attach` 为同步调用，该状态无真实存在的时间窗口，减少状态机与测试矩阵）。
- `reason`（`unavailable` 时）：`internal-page` / `genoffice-tab` / `already-attached` / `target-closed`。
- `target`：`{ tabId, title }`（DT12 目标标识，供面板头部显示）。
- `devtools.network.list` / `devtools.console.list` 对**无会话**的 tabId 返回 `{ entries: [], dropped: 0 }`（不报错）：渲染层仅在 attached 态主动查询，schema 不做会话存在性校验，避免「快照查询成为第二状态源」。
- 事件通道常量（`DEVTOOLS_EVENT_CHANNEL` / `DEVTOOLS_TOGGLE_CHANNEL`）由 `@urchin/ipc-contract` 导出。**与既有惯例的差异说明**：现状（`translate:progress` / `update:event`）是主进程模块导常量、渲染层写字面量字符串，存在漂移风险；本期在共享契约包内给事件通道名单一真源，属对局部惯例的主动偏离，理由是消除一处已知的一致性债务。
- 事件通道（send-only，不走 ipcSchema）：
  - `devtools:event`：判别联合 `{ type: 'state', tabId, state, reason?, target? }` / `{ type: 'network.batch', tabId, entries }` / `{ type: 'console.append', tabId, entries }` / `{ type: 'cleared', tabId, scope: 'network' | 'console' }`。
  - `devtools:toggle`：F12 触发的开/关通知（主进程键盘拦截 → 渲染层唯一状态源）。
- `ui.layout.setState` 增补字段 `devtoolsWidth?: number（0-900）`，res 同步增补（向后兼容的加法变更）。

## 6. 数据模型与主进程模块

### 6.1 目录结构（新建 `apps/desktop/src/main/devtools/`）

| 文件 | 职责 |
|---|---|
| `types.ts` | `NetworkEntry` / `ConsoleEntry` / `DevtoolsState` / `DevtoolsEventPayload`（判别联合）/ 会话接口 |
| `ring-buffer.ts` | 泛型 `RingBuffer<T>`：`push / toArray / clear / size / dropped` |
| `cdp-client.ts` | `webContents.debugger` 薄封装：`attach('1.3')` / `send<T>(method, params)` / `onMessage` / `onDetach` / 错误归一（`already-attached` / `target-closed` / `canceled-by-user` → DevtoolsError） |
| `devtools-manager.ts` | `DevtoolsManager`：会话注册表、域启用、事件聚合、批处理定时器、list/clear/evaluate、`dispose()`；依赖注入 `tabManager`（取 webContents）与 `notify`（事件推送） |
| `register-handlers.ts` | §5 中 8 个通道的 `registerHandler` 适配层（业务全部委托 Manager） |
| `index.ts` | barrel 导出（对齐 `tabs/index.ts` 惯例） |

### 6.2 数据模型

- `NetworkEntry`：`seq`（会话内单调递增，条目创建时分配）、`requestId`、`url`（≤8KB 截断）、`method`、`status?`、`mimeType?`、`resourceType?`、`size?`（encodedDataLength）、`durationMs?`、`startedAt`、`finishedAt?`、`errorText?`、`responseHeaders?`（**v2 修订截断策略**：剔除 `Set-Cookie`（隐私 + 体量——Cookie 不属于页面调试信息），其余头累计 ≤16KB 超出丢弃并置 `headersTruncated: true`）。请求/响应体不采集（已知限制，§12）。
- `ConsoleEntry`：`seq`、`level`（`error/warning/info/log/debug`）、`text`（≤8KB 截断）、`source`（`console-api/exception/network/other`）、`url?`、`lineNumber?`、`timestamp`、`stackTrace?`（≤10 帧）。
- **来源映射（v2 修订——发现契约 G §5 伪码技术错误）**：
  - `Runtime.consoleAPICalled` → ConsoleEntry（`source: 'console-api'`，**`console.log/warn/error/info/debug` 的唯一来源**）。契约 G §5 伪码只订阅 `Runtime.exceptionThrown` + `Log.entryAdded`，捕获不到任何 console API 输出——该伪码从未实现验证过，实施时同步修正契约 G（见 §11.1）。args 格化：`value ?? description ?? '<type>'`，对象无 by-value 载荷时仅显示 `RemoteObject.description`（不发起 `Runtime.getProperties` 额外往返，展开对象列入后续版本）。
  - `Runtime.exceptionThrown` → ConsoleEntry（`source: 'exception'`）。
  - `Log.entryAdded` → ConsoleEntry（`source: 'network' | 'other'`，浏览器级消息：网络错误、CSP 违规、存储异常等）。
  - `Network.requestWillBeSent / responseReceived / loadingFinished / loadingFailed` → NetworkEntry（同一 `requestId` 的多次事件**就地去重合并**：会话维护 `requestId → 条目` 索引叠加在 FIFO 容量之上，淘汰按插入序；v2 修订——v1 未定义过渡事件如何合并，批 flush 只推「自上次 flush 以来被更新过的条目」（脏集），脏集内同 requestId 聚合为最新态后推送）。

### 6.3 会话生命周期

- attach：`getTab` → 判 `viewKind`/`url`（内部页、genoffice 拒绝）→ `debugger.isAttached()` 检查 → **同步** `attach('1.3')` → 异步发 `Network.enable` / `Runtime.enable` / `Log.enable`（不等待其完成——enable 仅影响事件推送起点，会话建立即可响应 evaluate）→ push `state=attached`。
- detach：flush 尾批（含脏集聚合）→ detach → push `state=detached`。触发点：用户停止、tab removed、webContents destroyed、`debugger` 的 `detach` 事件（如原生 DevTools 抢占、目标崩溃——push `state=unavailable` + 原因）、`dispose()`（应用退出）。
- dispose 钩子挂入 `app quit` 清理链（对齐 `disposeTranslateManager` 既有模式）。

## 7. 健壮性与安全

1. **幂等与并发**：attach 已存在会话 → 原样返回状态；attach/detach 全路径 try/catch，`getTab` 与 `attach` 之间 webContents 销毁 → `unavailable(target-closed)`。
2. **竞态（快照 vs 增量）——v2 修订为「state 重置 + 幂等合并」双机制**：
   - 主进程保证推送顺序：flush 完尾批后才推 `state` 事件（同通道 FIFO，无旧批晚于 state 到达）；detach→attach 的会话重置由 state 事件显式标记。
   - 渲染层：收到 `state=attached` → 清空镜像 → 拉列表快照；此后批事件增量合并。合并是幂等的：Network 按 `requestId` upsert（批快照乱序到达不重复不丢失），Console 按 `seq` 集合去重（seq 仅在会话内单调，不跨会话比较——重置由 state 事件驱动，避免「重新 attach 后 seq 归零被误判为过期」）。
   - 广播批按 `tabId` 过滤：渲染层只消费自己目标会话的条目。
3. **尺寸上限**：表达式 ≤8KB（schema 层拒绝）；evaluate 结果（含异常 description）JSON 序列化截断 256KB（`truncated: true`）；URL/文本截断 8KB；堆栈 ≤10 帧；响应头策略见 §6.2。IPC 单消息上限远未触及。
4. **隐私（遵守 agents.md §六 特化审查点）**：URL、标题、控制台文本、请求头**不写 INFO 及以上日志**；主进程日志只记录 `tabId/state/条数` 等计数。consoleRetention 不落盘（内存环形缓冲，随会话销毁）。
5. **安全边界**：`devtools.*` 走既有 `registerHandler` zod 双向校验；preload 暴露面不变（仍只 `invoke/on`，主窗口受信来源白名单已有）；`Runtime.evaluate` 等同 DevTools console 权限（一期接受，理由：用户显式手势 + 页面本可执行自身脚本）；不提供 `Runtime.releaseObject` 之外的 debugger 域方法。
6. **多窗口现状**：`sendToMainWindow` 广播所有窗口；v0.1 单窗口无影响，多窗口未来接入时同一会话数据全窗口镜像（写入已知限制，多窗口检视归 v0.5+，与契约 G §12 既有演进一致）。

## 8. 性能策略（DT7 延续）

- 环形缓冲 1000 条（Network 与 Console 各一），FIFO 淘汰 + `dropped` 计数，UI 显示「已丢弃 N 条」。Network 侧为「requestId 索引 + FIFO 容量」的有序去重结构（见 §6.2）。
- **批合并（v2 修订）**：flush 前把脏集按 requestId 聚合为最新态（同一请求的三次状态演进只推最终一条，减少 IPC 消息大小）；**定时器边缘触发**——仅有 pending 脏条目时才挂 200ms 定时器， flush 后卸载，会话空闲产生零消息（v1 的常驻定时器空转已否决）；detach 前 flush 尾批。
- 渲染层长列表：一期不做虚拟化（1000 条 × 行高可控），用 CSS `content-visibility: auto` 降低屏外渲染成本（v2 修订：替代 v1 的「简单窗口化」——窗口化滚动位置跟踪复杂度与收益不成比例）；详情按需展开不预渲染。
- 检视列拖宽逐 pointermove `notifyLayout`（与右侧栏拖宽同模式，`refreshAllViewBounds` 复用既有强制刷新通道）。

## 9. 入口与交互

- **F12**：主进程对每个 tab webContents 与主窗口 webContents 挂 `before-input-event`，命中 F12 → `preventDefault()` + `sendToMainWindow('devtools:toggle')`；渲染层为面板开合唯一状态源。安装/卸载复用 `installZoomControl` 模式：`tabManager.on('created')` 挂新标签 + **install 时遍历存量标签补挂**（v2 补：v1 漏写存量路径）+ 主窗口单独挂载；dispose 时反注册。
- **左侧栏图标**：调试图标按钮（设置按钮旁），与 F12 等价（DT8 的「命令面板」入口以侧栏按钮替代——命令面板未实现，登记为后续）。
- 面板头部：目标标题 + 状态徽标 + 开始/停止检视 + 绑定当前标签 + 清空；中部 Network/Console/求值 三视图切换。

## 12. 非目标与已知限制（一期不做）

- AI 分析（DT6）、自定义 Panel 注册开放（DT4）、Elements/Sources/DOM 检视、性能瀑布图（CDP Tracing）、HAR 导出——按契约 G §12 演进。
- attach 时刻之前发生的请求不回放（CDP `Network.enable` 语义）；页面内刷新可重新采集。
- 请求/响应体不采集（体量与隐私权衡）；后续版本按需加 `Network.getResponseBody` 白名单。
- **响应头剔除 Set-Cookie**（隐私）：网络调试可能因此看不到 Cookie 设置链路，列入已知限制（可接受——Cookie 不属页面调试信息）。
- **F12 在面板求值输入框按下会关闭面板**（before-input-event 主进程拦截优先于渲染层 keydown，无法 stopPropagation）：与 Chrome 行为不同，接受为已知限制；后续可改命令面板/侧栏按钮入口避免。
- **evaluate 长时间运行无主动取消**：页面死循环时 evaluate promise 不返回，依赖 `registerHandler` 默认 30s IPC 超时兜底（同 DevTools 既有问题），重复 evaluate 会堆积——已知限制。
- **F12 在渲染层未就绪时丢失**（F12 在主窗口 mount 前按下）：极低频，接受。
- 多窗口同屏多会话（v0.5+，对齐契约 G 多 tab 检视演进）。
- 命令面板入口（未实现的功能，独立议题）。
