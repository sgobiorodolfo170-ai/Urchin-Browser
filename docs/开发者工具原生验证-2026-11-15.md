## 可复现步骤

1. 在干净基线使用 pnpm 9.12.0 执行 `pnpm build`。记录 `git rev-parse HEAD` 和运行中的 `process.versions`。
2. 用空临时根目录设置 `URCHIN_TEST_USER_DATA` 与 `URCHIN_TEST_DATA_DIR=<根>/data`，不要预建 data 子目录；生产模式启动。Playwright 隔离探针同时设置 `PLAYWRIGHT=1`、`NODE_OPTIONS=''`；显示服务认证由当前环境提供，勿硬编码本机认证路径到项目。
3. 通过壳已有 `tab.create` 创建活动 fixture：`data:text/html,<title>ADR022 fixture A</title><h1 id="fixture">Native probe</h1><script>window.fixtureValue=42</script>`；主进程按该 URL 查找本次创建的网页 webContents，仅该目标调用 `openDevTools({mode:'detach'})`。本探针的 URL 查找仅用于隔离 fixture，不能成为产品目标选择器。
4. 从真实桌面核实工具标题、DOM 与 Console 求值结果；分别将焦点放在壳与工具 Console 后按 F12，记录实际行为。不要把主进程直接调用 openDevTools 算作产品 F12 验收。
5. 独立运行最小 Electron 主进程：创建一个 BrowserWindow，添加一个隔离 BrowserView 并加载 fixture；不使用 Playwright、不调用 debugger.attach。每轮先订阅一次 opened，再 open；收到事件后断言 opened=true；再订阅 closed、close 并等待。每个等待设置 10 秒超时，循环 20 轮，检查最终 tool 引用和 debugger 状态；退出时销毁 view 与 owner。
6. 在该最小进程创建独立隔离 BrowserWindow host，调用 `target.setDevToolsWebContents(host.webContents)`，再 open 并等待 opened，记录 host/tool id、标题与 opened 状态；无论结果均显式销毁 host 和 target。此次重现的是该 host/mode 组合，不能推导所有嵌入方式都失败。

环境临时脚本与完整日志位于工作目录，不是后续执行前提；以上步骤与结果为持久记录。产品回归测试应在 P0-B/C 按实际控制器与入口编写。
