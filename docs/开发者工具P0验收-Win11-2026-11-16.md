## 1. 平台与边界

用户明确要求本轮只验收本机 Windows 11；Windows 10 延期候补，不作为本轮 P0 阻断项，也不记为已通过。用户确认的本机为 Windows 11；Electron 报告内核版本 `10.0.26300`、Electron `43.8.8`、Chromium `150.0.7871.250`。注册表 ProductName 仍返回 Windows 10 Pro，保留这一原始字段差异，不据此冒称已验收 Win10。

使用独立临时 userData 和 data 根，不操作日常安装版。普通网页无 app preload / Node / IPC；只读诊断计数只导出在可信主进程模块，不增加网页 IPC、CDP 透传或生产调试端口。Playwright 自身的临时调试连接属于测试 harness，不作为产品能力。

本轮首版承载方式仍为原生独立窗口，无嵌入模式。P1 增强未启动。

## 4. 资源与已知观察

[20 轮原始数据](./验收证据/开发者工具-P0-Win11/resources-20cycles.json)：测量场景为一个受控普通网页，先完成 A/B 归属测试再关闭额外标签。最后一轮逐轮峰值 798.445 MB，稳定采样最小值 748.375 MB；斜率 -0.3550 MB/轮、R²=0.1023，未检出持续线性增长。最终 sessions=0、timers=0、tabInputs=1、windowInputs=1、extraInputs=1、原生工具数=0，与对应基线一致。单测进一步验证完整 dispose 后所有映射、监听、计时器归零。

判据预先固定为 4 轮预热后测量 20 轮；持续增长识别为斜率 ≥1 MB/轮且 R²≥0.8。绝对回归线未提高：本机800 MB / CI750 MB；最终判定严格沿用 ADR-019 的静置后3次采样最小值，20轮逐轮峰值另行披露，不把瞬时峰值另设为新门禁。既有十主页 perf 测试仍按其原定义执行，500 MB 目标线仍仅告警。

补充容量观察不隐去：[保留两张网页时的原始数据](./验收证据/开发者工具-P0-Win11/resources-two-targets-observation.json)峰值约877 MB，高于单目标测试线，但前后基本持平（斜率 -0.0234 MB/轮），映射/监听均回基线。不能据此宣称任意数量或内容的网页组合都小于800 MB；项目既有绝对内存门禁场景是十个主页标签，本轮另加的单目标开关场景通过。多普通网页的静态容量优化继续作为性能观察，不冒称消除了 Chromium 的页面与工具运行成本。

## 5. 最终验证与退出

**本轮15条需求均通过，按用户限定的本机 Win11 范围，P0 完成。** Windows 10 仅延期候补，未记通过。源码基线 f2d896ef，本报告所在提交为本轮交付；迭代 v0.3.0-dev.244，开发包 package.json 版本0.1.0，框架版本见 §1。

- `pnpm verify` exit 0：桌面165文件/1904测试、pi-web-host82文件/1723测试、pi-web132文件/1489测试通过；桌面行覆盖率73.54%；类型、源码入库、lint（0 error/8存量warning）、格式、覆盖率、文档、manifest24/24、DSH三源门禁通过。受限上下文写 verify 指纹遇到 `.git/objects` 权限失败，脚本如实告警；质量检查本身全绿。
- `pnpm build` 完整构建通过，随后生产模式隔离验收实例启动供用户测试。
- 用户选择的11组最终回归 **24 passed / 0 failed / 0 skipped**，清单估算23，实际收集24；不是把不同时点的通过项拼成单次全绿。[最终回归输出](./验收证据/开发者工具-P0-Win11/final-regression.txt)。最终整组中的原生资源稳定采样最小值740.879 MB，逐轮峰值770.137 MB，计数/监听回基线；[原始数据](./验收证据/开发者工具-P0-Win11/resources-final-regression.json)。
- 关闭/焦点修复后原生矩阵 `--repeat-each=3` **6 passed**，包含三轮20次资源采样和工具打开时正常 quit，相关实例 PID 全部退出；[三轮原始数据](./验收证据/开发者工具-P0-Win11/resources-stress-three-runs.json)。三轮稳定采样最小值749.141/750.340/748.375 MB，均低于800 MB本机回归线；逐轮峰值802.836/785.758/798.445 MB保留，不冒称瞬时值从未超线。
- 既有十主页内存回归结果 643.3 MB（3次采样最小值），800 MB回归线通过，500 MB目标线告警仍保留。

一次旧关闭路径发生进程退出，没有原生崩溃栈可供精确归因；已消除在销毁中的前端执行清理脚本，并将焦点恢复延迟到原生关闭事件之后。修后重复矩阵与最终整组均通过，未通过忽略异常、删除断言或开启 retries 来掩盖失败。跨工作区关闭工具明确按需求返回绑定网页；目标已消失/变内部页/替换 webContents 则只回所属窗口。

中途失败保留在开发规划台账：本机 VM 模块读取适配、面板英文文本假设、初始多网页绝对内存超线；质量门禁捕获设置页 toast 在卸载后仍更新的问题。已增加 mounted 防护、替换旧 timer、卸载清理及真实回归测试；没有忽略 unhandled error 或下调门槛。

## 6. 复现

1. 构建：`pnpm build`。
2. 本地 UI fixture：`node scripts/serve-devtools-fixture.mjs`，打开其输出的127.0.0.1 URL；仅监听回环地址。
3. 在隔离验收档案使用 F12，按 §2 的按钮与面板步骤操作。使用普通按键输入算术表达式，保留 DevTools 自带粘贴保护。
4. 自动化：`pnpm --filter @urchin/desktop exec playwright test tests/e2e/devtools-native.spec.ts`，读取 test-results 下的 devtools-resources.json；依赖 GenOffice 产物，已在 manifest 登记。
5. 对照质量门禁：`pnpm verify`。本机 Electron dist ACL 经前轮用户授权添加 ALL APPLICATION PACKAGES 读取/执行权限；测试在桌面执行上下文运行，未关闭 Electron 沙箱。

Windows 10 后续候补项：复跑同样的系统输入、原生七面板、归属/生命周期/资源矩阵和门禁；分别登记系统与版本，不能将本机 Win11 结果复制过去。
