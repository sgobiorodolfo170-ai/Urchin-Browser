# 打包核查清单（Windows x64 · NSIS）

> 本清单是**打包操作核对表**，不是新的事实真源：版本号规则真源为 [ADR-012](./decisions/ADR-012-发布通道与版本号治理.md) + `scripts/build-version.mjs`；依赖版本真源为 `pnpm-lock.yaml`；通道/清单真源为 `electron-builder.yml` 的 `publish` 段。本文件只负责「照单核对 + 留痕」，出现与本清单不一致时以真源为准并回改本文件。

- 建立日期：2026-11-07
- 适用产物：Windows x64 NSIS 安装包（`Urchin-Browser-<version>-x64.exe`）
- 适用命令：`pnpm package:win`（= `pnpm --filter @urchin/desktop package:win`）
- 记录要求：**每次打包**开始前按 §9 逐项核对，结束后在 §10 追加一行记录（日期时间 + 版本 + 通道 + 结果 + 异常），失败也要记录。

**为什么需要这份清单**（2026-11-07 事故）：`0.3.0-dev.158` 首次打包「构建成功、校验通过」，但安装后 DeepSeek Harness 启动即退出——打包器只沿 `dependencies` / `optionalDependencies` 建图，把 25 个 `peerDependency` 漏在包外。原有校验只检查文件名与通道，没有覆盖「运行时模块是否可解析」。本清单据此补齐了「依赖闭包」与「运行时冒烟」两节。

## 2. 打包流水线与产物

`pnpm package:win` 依次执行（任一步非零退出即整条失败）：

| 步骤 | 命令 | 产物 | 说明 |
| --- | --- | --- | --- |
| 1 | `pnpm run icon:build` | `apps/desktop/build/icon.ico`、`build/icon.png` | 由 `apps/desktop/ico/build-ico.cjs` 从多尺寸 PNG 合成 6 档 ico，并把 512px PNG 复制为 `icon.png` |
| 2 | `pnpm run build:main` | `apps/desktop/dist/main/` | Vite `--mode main`，CJS + Node 环境；同时写入 `{"type":"commonjs"}` 标记 |
| 3 | `pnpm run build:preload` | `apps/desktop/dist/preload/` | Vite `--mode preload`，CJS |
| 4 | `pnpm run build:renderer` | `apps/desktop/dist/renderer/` | Vite `--mode renderer`，React ESM 前端 |
| 5 | `pnpm run build:provider` | `apps/desktop/dist/providers/openai-compatible.js` | esbuild 单文件 CJS（Provider 子进程入口） |
| 6 | `pnpm run build:pi-web` | `apps/desktop/dist/main/pi-web-host.js`、`dist/pi-web/` | 必须在 build:main 之后（main 构建会清空 `dist/main`） |
| 7 | `node scripts/genoffice-build.mjs` | `vendor/genoffice/apps/*/out/**`、`scheme-privileges.json`、`THIRD-PARTY-NOTICES.txt` | 7 个 app（markdown/pdf/html/docs/slides/sheets/shell）+ 嵌入包 + 许可声明 |
| 8 | `node scripts/fetch-node.mjs` | `apps/desktop/build/node/node.exe` + `.node-version` | 便携 Node（当前 v24.22.0），版本匹配则跳过 |
| 9 | `node scripts/clean-release.mjs` | 删除 `apps/desktop/release-*` | 删除失败只告警不阻断（会留下旧目录，见 §8 F1） |
| 10 | `node scripts/package-win.mjs` | `apps/desktop/release-v24/` | electron-builder 打包 + `afterPack` 依赖补齐 + 产物校验 |

**electron-builder 内部顺序**：组装 `win-unpacked` → `afterPack`（`apps/desktop/scripts/after-pack-dsh-peers.cjs`：补齐 peer-only 依赖 + **MAX_PATH 剪除**（2026-11-10 起，剪除相对路径 >188 的文件并对 >195 直接失败，防自动更新卸载器 Rename 超 MAX_PATH，见 §8 F12））→ 生成 NSIS 安装包 → 生成 blockmap 与更新清单 → `validateArtifacts` 校验。

> **安装耗时整改（dev.191 起）**：`electron-builder.yml` 的 `files` 新增 4 条排除规则（node_modules 下的 `.ts` / `.cts` / `.mts` / `.md`），在**组装期**就不收类型声明、npm 包附带的 TS 源码与文档（dev.190 基线：26,388 个文件 / 171 MB，占全树 48.3%）。排除项会同步进入 `nodeModuleFilePatterns`，因此 `app.asar` 索引与 `app.asar.unpacked` 实体文件同步减少；**不得改用 afterPack 剪除替代**——只删实体会留下 asar 内的幽灵索引条目（目录可见、打开报 ENOENT）。合规文件（LICENSE / NOTICE / THIRD-PARTY-NOTICES.txt）保留。**注意 `afterPack` 的 peer 补齐是另一条路径**：钩子用 `cpSync` 直接复制 25 个 peer-only 包，不经过 `files` 过滤；dev.191 起在同一钩子内按同口径过滤非运行时文件（日志 `过滤非运行时文件 N 个`），MAX_PATH 剪除器保持原样。耗时根因与实测数据见 §8 F13/F14（NSIS 解压到 `%TEMP%` 后再 CopyFiles 到安装目录，两遍全树写入）。验收按 §9 D 核对文件数与非运行时文件残留。
>
> **安装耗时整改第二批（dev.192，B1+B2）**：① `electronLanguages: [zh-CN, zh-TW, en-US]`——locales 55→3 个 .pak（约 -43 MB）；② `files` 排除 renderer-only 包实体副本（react / react-dom / lucide-react / @radix-ui / clsx / tailwind-merge / marked / turndown / defuddle，2,344 文件，lucide-react 占 2,180）——依据：vite 已把它们打进 asar（dist 产物 grep 无 require/import 字面量，主进程 external 仅 better-sqlite3），dsh 依赖闭包实测不含。⚠ **B1 与 afterPack 补齐存在机制冲突**：钩子的「闭包有、产物无 = 漏打」检测会把 files 有意排除的包复制回来（首打实测 6 包 2,255 文件被补回、B1 收益被抵消殆尽）——钩子内的 `INTENTIONALLY_EXCLUDED` 清单必须与 files 排除**同口径维护**，改任一侧须同步另一侧（zod / postal-mime 保守保留：主进程源码有 import）。**实测安装耗时**（/S 静默、C 盘 NVMe、双 env 沙箱、同机同盘 A/B）：dev.190 54,592 文件 ≈10 分钟（F14 经验值）→ dev.191 28,908 文件 **329.4s**（11.4 ms/文件）→ dev.192 26,508 文件 **203.5s**（7.7 ms/文件，较 dev.191 **-38.2%**）。剩余杠杆：代码签名（降 Defender 逐文件扫描，证书未采购暂挂 CON-07）、本机 Defender 排除项（用户自行操作）、NSIS 写放大 ×2（A3 zip 载荷实验已证伪，见 §8 F15）。
>
> **平台裁剪（2026-11-12 dev.193 体积事故教训 · 本项目只打包 Windows x64）**：重打包后安装包 **295.20 MB → 646.66 MB（+119%）**，解压态 1,153 → 2,344 MB，文件数 26,509 → 37,241，功能零新增。根因是依赖树里 6 组包把各平台二进制写成 `optionalDependencies`——`libreoffice-kit`（5 平台，**837 MB**，真正需要的 win32-x64 仅 192 MB）、`sharp`（25 个变体）、`ripgrep`（13 个）、`sherpa-onnx`（6 个）、`node-addon-require-builtin`（9 个）、`koffi`（15 个）；根 `package.json` 未配 `pnpm.supportedArchitectures`，pnpm 全平台安装，`electron-builder` traversal 与 `afterPack` 的 `cpSync` 又只剔 `.ts/.md/.map`、**不看平台**，原样收进 `app.asar.unpacked`。以前没爆是因为 `libreoffice-kit@0.1.5` 只有 win32-x64 一个平台包，`0.2.2-rc.2` 的 `dsh-office-kit` 升到 `0.2.3` 后 5 平台并存才显现。**三层修法**：① 根 `package.json` 的 `pnpm.supportedArchitectures = {os:[win32], cpu:[x64]}`（治本，pnpm 只在 resolution 阶段生效——改完若 `pnpm install` 输出 `Lockfile is up to date / Already up to date` 则**不会**自动剥离已装包，须先手工删掉 `.pnpm` 里不匹配平台的目录再 install，可用「删完重装、确认 0 重建」验证配置真的生效）；② `electron-builder.yml` 的 `files` 负向规则（组装期不收，与 B1 同口径）；③ `afterPack` 的 `FOREIGN_PLATFORM_RULES`（前缀+保留后缀判定，拦住 `cpSync` 补齐路径，并兜底删除产物内已落盘的非目标平台包）。**两处规则必须同步维护**（files 与 afterPack），改一侧不改另一侧会重演 B1 的抵消问题。**判据**：日志出现 `平台裁剪 N 个（非 win32-x64）`，且产物 `app.asar.unpacked/node_modules` 下 `ls -d *darwin* *linux* *win32-arm64* *wasm*` 无命中。注意 `@img/sharp-` 前缀会吃掉 `@img/sharp-libvips-win32-x64`，规则必须按前缀长度降序匹配；`sherpa-onnx-node` 是不带平台后缀的主包，须显式保留。

> **平台裁剪补丁（2026-11-13 · 包名不带平台后缀的漏网包）**：上述三层都靠「目录名里的平台词」匹配，对**包名本身不带 `darwin` / `linux` / `win32` 等词、只靠 `package.json` 的 `os` 字段声明平台限制**的包完全失效。实测漏网一个：`@deepseek-ai/dsh-experimental-cua-macos`（**os: `["darwin"]`**，`dsh-cua-bundle` 的 `optionalDependency`，3.6 MB，内含 macOS `.app` 长路径），它在 #16 那次打包里原样进了产物——上一轮清 `.pnpm` 用的匹配词是 `darwin` / `linux`，而这个包用的是 `macos`，于是既没被清理、也没被任何前缀规则命中。**第四层修法**：① `electron-builder.yml` 的 `files` 加**精确路径**负向规则（组装期不收）；② `after-pack-dsh-peers.cjs` 加 `EXPLICIT_FOREIGN_PACKAGES` 精确名单，并新增 `manifestTargetsOtherPlatform()`——对 `@deepseek-ai/*` 的包读 manifest，按 npm 语义判定 `os` / `cpu`（支持 `!win32` 这类否定写法），非 Windows x64 一律剔除，作为新增同类包的自动兜底；③ 新增 `scripts/prune-foreign-platform-packages.cjs`，按同一套 manifest 判定清扫 `.pnpm` 里**所有**面向其他平台的包实体（不再依赖手写目录名 pattern），修复「补了排除规则但忘了删本地残留」这个反复出现的动作缺口。判定顺序也调整了：非目标平台包在 `afterPack` 循环里**优先于版本择优**判定，避免它先被 `packaged.has(name)` 分支跳过、留下需要靠兜底删除收拾的局面。实测该脚本首轮清出 19 个（koffi 系 10、node-addon-system 系 4、cua-macos、其余平台变体），`pnpm install` 后**0 重建**。

## 8. 常见失败对照

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| F1 | `EBUSY: resource busy or locked, unlink '...app.asar'` | 旧产物被其他进程打开（实测：Gitool.exe 持有 `app.asar` 句柄） | 用 `handle64.exe -nobanner app.asar` 定位 PID → 关闭该进程 → 删除 `release-*` → 重跑打包；**不要**靠改输出目录绕过 |
| F2 | 安装版 dsh 启动即退出 `code=1`；直跑报 `ERR_MODULE_NOT_FOUND` | peer-only 依赖未打包（本次事故） | 确认 `afterPack` 日志有 `补齐 peer-only 依赖 N 个` 且含报错包名；`N=0` 时检查钩子是否被 `electron-builder.yml` 引用 |
| F3 | `file source doesn't exist ... THIRD-PARTY-NOTICES.txt` | notices 步骤未执行 | 重跑 `node scripts/genoffice-build.mjs`（3.6 步骤会生成并复制）；确认 `vendor/genoffice/THIRD-PARTY-NOTICES.txt` 存在 |
| F4 | 通道错配（dev 构建产出 `latest.yml`） | `publish.channel` 被删或版本形态不符 | 版本号必须为 `x.y.z-dev.NNN`；不要删除 `publish.channel`；以 `app-update.yml` 为准核验 |
| F5 | `resources/node/node.exe` 缺失 | 未跑 `fetch-node` 或版本戳不匹配 | 删除 `build/node/.node-version` 后重跑步骤 8；或设置 `URCHIN_NODE_DIST_URL` 指定源 |
| F6 | Electron / 二进制下载失败 | 镜像缺失或网络受限 | 恢复 `.npmrc` 镜像；`fetch-node.mjs` 会自动回退官方源 |
| F7 | 版本解析失败 | `CHANGELOG.md` 表尾行格式错误 | 按 `| vX.Y.Z[-dev.NNN] | YYYY-MM-DD | 摘要 |` 修正 |

## 11. 维护约定

- 本清单随打包链路变更同步更新：新增产物必须同时更新 §3（输入）、§7.1（产物）与 §9（核对项）。
- 新增/升级 `@deepseek-ai/dsh` 后：先跑 `pnpm check:dsh`，再打包，并确认日志中 peer 补齐数量与 §4.5 的变化（清单文字可滞后，日志是准）。
- **平台唯一性（硬规则，2026-11-12 dev.193 体积事故后确立，2026-11-13 补强）**：本项目只发布 **Windows x64**，产物内不得出现任何非目标平台的二进制包。新增依赖若带平台拆分的 `optionalDependencies`，必须在 `electron-builder.yml` 的 `files` 负向规则与 `after-pack-dsh-peers.cjs` 的 `FOREIGN_PLATFORM_RULES`/`EXPLICIT_FOREIGN_PACKAGES` **同时登记**——只改一处会重演 dev.193 的「补齐机制抵消排除规则」（§8 F16）。禁止用「加白名单」的方式让体积/版本异常通过门禁（§8 F17）。
- **判断「跨平台包」只看包名是不够的**：包名可以不带任何平台词（如 `dsh-experimental-cua-macos` 用 `macos` 而非 `darwin`），权威依据是 `package.json` 的 `os` / `cpu` 字段。新增依赖后若不确定，直接读 manifest 或用 `node scripts/prune-foreign-platform-packages.cjs --dry-run` 扫一遍，不要凭包名猜（§8 F18）。
- **清理 `.pnpm` 残留一律用脚本，不要手写目录名 pattern**：手写 pattern 会随命名变化漏项（dev.193 实测：清 `darwin`/`linux` 漏掉了用 `macos` 命名的包）。统一用 `scripts/prune-foreign-platform-packages.cjs`，它按 manifest 判定、只删包实体（`lstat` 非 symlink），并支持 `--dry-run` 预演。
- **升级 dsh 依赖后必须清 `node_modules` 残留**：仅替换 lockfile 不足以移除旧 peer 变体目录，`.pnpm` 里会残留上一版本的目录（实测 345 个），被打包器顺链接带入产物。判定：`ls -d node_modules/.pnpm/*<旧版本号>*` 有输出即需清理，清理后 `pnpm install` 应 **0 重建**。
- **升级 dsh 主版本必须连同 `node_modules/.pnpm/lock.yaml` 虚拟存储快照一起清（2026-11-13 固化，见避坑清单 #52）**：该文件是 pnpm 的虚拟存储快照，升级后即使全量重生成主 lockfile，pnpm 仍从快照恢复旧 peer 变体——`pnpm install --force` 与「剪掉主 lockfile 中 dsh 条目后重装」均无效（dev.193 整改实测，主 lockfile 与快照 md5 完全一致）。正确做法：主 `pnpm-lock.yaml` 与该快照**同时移走**后再 `pnpm install --no-frozen-lockfile`。
- 本文件不复制「覆盖率阶梯 / 版本号映射 / 通道规则」等已有真源内容，只写操作步骤与核对项，避免制造新的漂移副本（`pnpm check:docs` 会检查命令与阶梯类漂移）。
