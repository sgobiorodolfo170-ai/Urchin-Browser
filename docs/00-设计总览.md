# 00 · 设计总览

> 状态：Draft  · 日期：2026-07-27  · 决策来源：开发文档讨论首轮

## 1. 项目定位

Urchin Browser 是一款基于 Electron 的 **AI 原生 + 开发者友好** 桌面浏览器。

| 锚点 | 值 |
|---|---|
| 内核 | Electron 内置完整 Chromium（Blink + V8） |
| 首版平台 | 仅 Windows |
| 差异化定位 | ① AI 原生（Side Panel、页面摘要、上下文记忆）<br>② 开发者友好（内置 DevTools 增强、Chrome 扩展兼容、可脚本化 hooks） |
| 首版范围 | MVP 最小闭环，6-8 周工期（含 per-provider 强隔离） |

## 2. 设计原则

继承 AGENTS.md §一总纲，本项目强调的几条：

1. **Single Source of Truth**：主进程是 Tab/Window/Setting/Permission 的权威源，渲染进程只持镜像；AI 流式 token 不走状态树，走 MessagePort + transient updates。
2. **进程隔离优于性能**：第三方代码（Provider 插件、扩展）跑在独立进程或独立 webContents，crash 不带倒主进程。
3. **类型化边界**：所有 IPC 用 zod schema 双向校验；Provider 契约用 `apiVersion` 硬匹配；扩展权限用白名单 + Backend 二次校验。
4. **可序列化优先**：跨进程状态必须可 JSON 序列化，Zustand store 内禁止塞 Map/Set/Function。
5. **TDD + Closed Loop**：验收信号必须由 Vitest/Playwright/lint 给出，不接受 AI 自评。
6. **生产级标准**：本项目以生产级标准开发与验收（声明见 [../agents.md](../agents.md)「项目声明」，2026-08-17 确立）——生产级是**自 v0.1 起的全过程标准**而非 v1.0 目标，本条 1-5 与全局约束、每版验收准则（[05-路线图 §2](./05-路线图.md#2-每版验收准则可机器判定)）均为该标准的落点；任何版本阶段只缩小范围，不降低标准。

## 4. 全局约束

- **进程数量预算**：主进程 1 + 渲染进程（每窗口 1 + 每 tab 1 BrowserView）+ AI Orchestrator 1 + 每 Provider 1 子进程 + 每 extension 1 webContents。雪崩场景需做上限保护（v0.2+ 引入 tab 进程合并到上限）。
- **包体预算**：v0.1 不设硬上限（Electron 基础 ~100MB），v1.0 目标 ≤180MB（含 1 个官方 Provider SDK 与本地 fallback）。
- **隐私底线**：默认不上报任何遥测。Crashpad 本地存 minidump，上传需用户主动开启。
- **可逆性约束**：用户书签/历史/标签会话的删除操作必须有"撤销"窗口（v0.3+，与 FR-PERSIST-09 一致）；扩展卸载必须清理其存储 namespace。
