# ADR-023 · 本地日历与预备工具边界

- 日期：2026-11-16。
- 状态：采用（P0 + P1 本地增强）。
- 授权：用户要求按智能日历方案施工，并明确 AI 助手目前占位，不替助手开发作架构或方向决定。

采用速记页内原生 Dialog，主库 migration 5 创建日历、事件、幂等响应与审计表；Service 统一时间语义，typed IPC 双向 Zod 校验，调用限定受管主窗口。关闭日历不卸载笔记页面，不新建 BrowserWindow。

用户进一步确认本次实现 P0 + P1 本地增强：多日历、周/日视图、完整重复与例外、持久提醒、业务引用和备份恢复。删除为可恢复软删除，无自动清除；版本检查与审计同事务。系统时区仅作为默认值，事件保留自己的 IANA 时区。重复按需展开，月末/闰日和 DST 不存在时刻跳过；单次例外独立保存，此后操作拆分系列。提醒采用持久去重与最近 24 小时启动补偿，进程完全退出期间不承诺通知。备份恢复事务执行、保留最近 3 份恢复前快照并提高版本号，阻止旧编辑器覆盖恢复数据。现有笔记/任务已连接；缺少独立模块或统一解析入口的业务对象只保存引用，不另建这些模块。

日历导出独立的 8 个工具契约及 Mock 调用测试。它们不是已注册插件，不定义 AI 助手的 Registry/Gateway、上下文注入或对话架构。未来助手开发者决定接入方式。禁止为本模块另造日历 Agent 或改动占位助手。

未采用把事件写入 notebook.state（不适于结构化查询、事务与版本检查）、ai.db（并非 AI 会话数据）或直接 Renderer 数据库访问（越过现有进程边界）。

实现细节和限制见 [契约 L](../contracts/L-智能日历.md)，P1 本地能力以建设进度与测试为准；真实助手集成和 P2/P3 不描述成已交付。
