二丫应作为浏览器的原生助手，帮助用户理解信息、决定下一步并完成获准的操作。此设计稿把“知道二丫看了什么、准备做什么、已经做成什么、怎样让它停下”作为最重要的体验。版本为 v0.7，日期为 2026-11-17；布局与参数均为待评审建议，交互原型只使用演示数据。

## 产品入口与信息结构

用户已选定“地址栏输入模式＋两个独立可拖动消息气泡”为二丫的主交互，设置页“AI 助手”更名为“二丫”，集中放置全部二丫设置。地址栏最右侧现有AI占位按钮启用为输入模式开关；不新增长驻聊天侧栏、底部输入条或默认独立任务标签。Pi保持独立身份。以下为v0.7待实施设计，替代v0.6及此前关于默认侧栏/任务页的建议；旧HTML和四方案探索不等于本方案已实现。

| 区域 | 职责 | 主要操作 |
| --- | --- | --- |
| 地址栏二丫模式 | 输入提示词、选择附件与上下文、显示目标身份 | 左侧“＋”、输入、右侧发送；显式返回地址模式 |
| 用户气泡 | 当前选定会话的用户消息流，与回复分开 | 独立拖动、选择复制、查看发送状态、隐藏/恢复 |
| 二丫气泡 | 当前选定会话的回复、步骤、核验、产物与审批 | 独立拖动、停止/暂停、具体审批、隐藏/恢复 |
| 设置→二丫 | 全部配置与管理的统一入口 | 模型与凭据、权限/外发、消息/任务、记忆/容量、弹窗气泡、预算/通知、数据与恢复 |

设置页用清晰分组和按需展开容纳全部配置；任务/消息和记忆管理可在该页进入详情，不默认常驻占用阅读空间。气泡中“二丫设置”直接定位对应分组，不另造第二套模型/权限设置。更名只改产品标签，不把Pi或供应商模型配置并入二丫。

## 核心交互路径

以“比较已选的三个网页，把结论整理到学习笔记”为例：

1. 二丫复述目标，列出三个页面的标题和来源、将读取的内容类型；页面之外的书签、邮件、文件不进入范围。

2. 显示读取授权和云端处理授权。两者分别勾选，明确服务商、发送内容、任务有效期；未同意云端处理时，提供本地模型或手动输入路径。原型中的“模拟在线模型”不代表已选定供应商。

3. 阅读后展示“结论、依据、未知项”。建议以具体条件解释，不显示没有校准依据的“可信度 98%”。每个来源可定位到页面或摘录。

4. 生成计划：提取信息、比较、拟稿、写入指定笔记、重新读取核对。计划展示预计操作次数与预算上限；修改目的地或写入正文后重新确认。

5. L2 下展示写入确认：工作区、笔记本、标题、正文预览、创建或覆盖、是否可撤销。默认创建新笔记；覆盖已有笔记必须额外显示差异。

6. 获得确认后执行并验证。分开显示“操作已提交”和“已核对成功”，不可仅凭模型回复宣称完成。

7. 展示产物入口和完成记录，再提出可选记忆候选。任务内容不会因为完成而全部永久保存。

原型可体验授权、计划、写入确认、执行、完成、停止和撤销。演示结果均在原型内产生，不读取真实网页、不调用模型、不写入真实笔记。

## 权限的易懂表达

| 等级 | 给用户看的名称 | 解释                                         |
| ---- | -------------- | -------------------------------------------- |
| L0   | 只聊天         | 只处理用户主动输入，不读取浏览器资源         |
| L1   | 允许查看       | 查看被授权的页面或模块，不修改内容           |
| L2   | 操作前问我     | 在可读范围内工作，具体写入需逐次确认         |
| L3   | 范围内自动做   | 只在指定时间、资源和额度内自动执行低风险操作 |

首版只实现 L0 至 L2。L3 是后续方案预览，需通过独立验收后才开放。等级选择只是配置草稿，点击清楚标明范围的授权按钮才生效。L3 不是无限权限；付款、对外发送、不可逆删除、权限修改等高风险动作仍逐次确认。用户可单独禁止某个模块，拒绝优先于默认允许。授权页始终展示工作区、资源、动作、到期时间、剩余额度与撤销入口。

“停止任务”和“撤销授权”分别解释：停止阻止该任务继续，撤销阻止后续使用该授权。已经完成的外部行为不声称已撤销；存在不可中止请求时显示“已停止后续操作，正在核对最后一步”。只在存在可靠补偿方法时提供“撤销已完成操作”，并先解释影响。

## 记忆中心与主动建议

记忆条目显示内容、来源、最近确认时间、有效期与用途。用户可以纠正事实、关闭某类记忆、固定必要偏好或删除条目。自动推断显示“推测，待确认”，与用户明确提供的信息区分；纠正后使旧摘要及索引失效。

容量面板分别显示长期记忆条数、逻辑内容大小、磁盘占用和本次上下文预算。不要将磁盘容量画成智力等级。达到上限时优先整理过期和重复内容，再请求用户处理固定条目；容量变更前展示会受影响的内容，不静默删除固定记忆。原型中的 100 条、80 KiB 与 2K tokens 仅用于展示界面，不是系统容量决策。

删除提供可追踪状态：立即停止检索、正在清理派生内容、已完成；备份的清除时间单独说明。无痕任务不写入长期记忆，也不读取历史长期记忆；界面明确显示无痕状态，退出时清理临时内容。用户希望保存时，应退出无痕，另开普通任务并主动提供需要保存的内容，再确认保存；不把无痕内容自动搬入普通任务。

自动触发的主动建议属于后续方案预览，首版只在用户当前任务内提出下一步建议。后续可使用轻量提示，文案包含触发原因，例如“你正在比较三个方案，要我按预算整理差异吗？”默认不自行执行。用户可以关闭此类建议、设置安静时段、降低频率；拒绝建议不会降低正常功能。敏感页面和无痕任务不触发后台主动采集。

## 状态与异常文案

| 状态           | 显示与行为                                                  |
| -------------- | ----------------------------------------------------------- |
| 空状态         | 简短示例、当前可用能力；不要求先填写复杂配置                |
| 缺少授权       | “需要查看这 3 个页面”，提供范围预览，不诱导授予全部浏览记录 |
| 等待确认       | 明确等待哪一次操作，等待期间不继续后续步骤                  |
| 运行中         | 当前步骤、已完成步骤、停止入口；不展示隐藏推理过程          |
| 模型断网或超时 | 保留任务与未提交草稿，说明最后确认的状态                    |
| 页面已变化     | 展示需要重新读取的来源；旧确认失效，不静默改参数继续        |
| 部分完成       | 逐项列明成功、失败、结果未知，避免整条任务被标为成功        |
| 预算达到上限   | 停止新增调用，展示已消耗额度与继续的明确代价                |
| 记忆容量不足   | 展示整理建议或增加容量的选项，不暗示必须购买                |
| 用户撤销权限   | 阻止后续动作，核对在途操作结果，保留最小完成状态            |

## 速记 日历与邮箱的交互设计

以下为B/C批文字原型，扩展可点击演示由UX-INT完成；上方原演示仍覆盖基础闭环。

| 场景      | 入口与上下文                                           | 确认与结果                                                        |
| --------- | ------------------------------------------------------ | ----------------------------------------------------------------- |
| 笔记/任务 | 速记页选择笔记本、对象或选区后发送给二丫；显示范围标签 | 笔记差异、任务文本/完成状态逐项确认；回读后打开对象               |
| 画布      | 选择文字便签，显示对象数量；只读选中项                 | 文本和布局分开预览；移动显示目标位置；并发变更保留双方内容        |
| 日历      | 复用速记页原生日历弹层；选日历/范围/事件后交给二丫     | 明确日期/时区/全天/提醒；重复范围三选；冲突给备选；回读后定位事件 |
| 邮箱      | 选定邮件交给二丫；附件逐项选，不预选全部邮件           | 摘要→可编辑草案→确认保存；发送另卡展示账号/To/CC/BCC/正文/附件    |
| 跨模块    | 邮件来源卡与目标笔记本、日历可见                       | 每项独立状态和打开入口；部分完成只重试安全的未完成项              |

范围标签可移除；打开二丫不自动授予读取。日历空闲说明本地覆盖范围，参会者不显示“已邀请”。草稿未保存显示“草案”；发送结果未知显示“发送结果待核实”，不放普通重试按钮。重复修改确认必须明确这次、以后或全系列。新流程沿用键盘操作、焦点回退、停止常驻与亮暗主题验收。

## F12诊断的交互设计

DT-00复用二丫现有输入框，用户粘贴报错后显示“根据你提供的文本分析”；不监视剪贴板。自动采集入口只放在二丫已有任务界面，显示“诊断这个网页”，不新增原生F12侧栏图标、绑定当前标签按钮、快捷键、命令面板或自定义Panel。

采集前展示目标网页、工作区、数据类型、时长、条数/字节上限和云端发送范围。确认后常驻采集中状态与停止按钮；用户按提示重现，二丫不擅自刷新。结束后先给脱敏证据预览，再展示事实、候选原因和验证步骤。Console/网络证据卡含来源、时间、覆盖缺口和“已截断”标识，不把HTTP状态直接写成根因。

F12可由用户照常打开，并始终绑定原网页；助手诊断目标切换需结束旧采集后重新选择。导航或调试连接中断显示“采集已停止，需重新选择范围”，不显示假成功。冲突时给人工复制报错路径，不要求关闭F12。

隔离预览单独显示“副本效果，不改原网页”，审批展示有限CSS差异、视口和验证判据；取消/结束清理副本。不提供没有实现的线上修复或工程保存按钮。以上为文字设计；可点击诊断原型纳入UX-INT随DT任务交付，原演示不冒充新功能。

## 任务反馈与通知增量设计（v0.5）

参考上游事件表现方式，具体实现证据见00。以下是文字设计；现有HTML原型未扩展本节演示，不代表界面已实现。

| 可信状态                 | 展示示例                         | 用户可操作项                   |
| ------------------------ | -------------------------------- | ------------------------------ |
| planning                 | 正在比较你选中的三个页面         | 看来源、停止                   |
| awaiting_approval        | 草稿已准备好，等你确认写入       | 打开完整确认卡、取消           |
| running                  | 正在创建笔记；第2步，共3步       | 看步骤、停止后续动作           |
| verifying                | 已提交，正在回读核对             | 看回执、停止后续动作           |
| paused + outcome_unknown | 无法确认是否写入，已停止后续操作 | 查看已知结果、回查；不直接重发 |
| completed                | 已核对完成，点击打开笔记         | 打开产物、查看证据             |
| cancelled / failed       | 已取消后续步骤 / 此步骤确定失败  | 查看已完成部分与可行恢复办法   |

并行步骤显示当前活动列表或“另有N步进行中”，不把单个工具返回当作完成。部分完成放在摘要内；不新增任务状态。仅对无关紧要的动画/进度切换合并刷新，审批、核验失败、结果未知、撤权和取消立即反映；状态不能因动画未播完而延迟。多任务明确当前选中的任务及工作区，不自动跳到另一任务。所有表现都有文字等价项，关闭动效后仍能操作。

通知分为当前任务提醒和后续主动建议，两者独立设置。目标二丫气泡正在前台可见且持有焦点时优先就地提示；气泡隐藏或窗口失焦后仍须按通知许可与勿扰设置决定是否发系统通知。多个窗口由统一协调器去重；在用户看着任务的另一个窗口时不重复弹出。默认遵守勿扰，待审批可留应用内未读标记，不自动绕过勿扰。通知只写通用状态与待处理数量，不含目标网页标题、邮件内容、笔记正文或收件人。

点击通知先校验档案、工作区和任务可见性，再聚焦可信窗口与目标任务；目标已删除/无权访问时给出通用说明，不跳到别的同名对象。点击待审批通知只打开确认卡，不消费票据或执行工具。通知被关闭不等于取消任务；隐藏气泡不等于撤销已有许可。

二丫回复气泡中的任务摘要每次只突出一条主要提示（不限制两角色各自的消息流）：当前选中任务的待审批/异常优先于普通进度，普通进度优先于装饰性话语；其他任务通过未读数量进入列表，不覆盖正在操作的确认卡。若后续加入二丫形象，先试少量表情，提供关闭与减少动态效果选项；模型挑选的表现动作不得遮挡停止按钮、伪装系统审批或表示未经核验的业务成功。

## 可访问性与验收

正文保持可读字号，功能不依赖颜色或悬停。按钮使用完整动词，输入项有标签；键盘可以到达全部关键动作，焦点可见。状态变化通过读屏通知，但流式输出不逐字打断。弹出确认层时，生产实现需将焦点移入并可返回触发按钮。

验收建议：在 320、736、1024 像素宽度和亮暗主题下，无横向溢出、遮挡及无法点击的关键按钮；所有关键操作能仅用键盘完成。首次进入未默认勾选读取或云端授权；改变等级不立即获得真实授权；L1 无写入路径；L2 未确认前零写入；L3 范围外动作重新申请；停止后没有新增步骤；页面变化导致重新确认；无痕状态不新增长期记忆。

此页对应 ER-001 至 ER-009，并体现 ER-011 的预算可见性。生产权限和停止行为需由第 09、10、11、12 份文档的后端控制与测试共同验证，界面按钮本身不构成安全保证。

## 全能力交互补充（v0.6）

[13 全能力接入设计](./13-二丫全能力接入设计.md)要求能力目录按原生/网页/工作台、平台和状态筛选，显示已验收、需批准、需人工接管、不可用及原因；未知能力不显示为可调用。浏览器全局覆盖与本期进度分开，不以单一“全功能”开关表达权限。

网页操作面板固定目标窗口/工作区/标签/origin及可用frame，展示最近观察时间、截断与目标失效。点击/填表前可定位到当前唯一目标，歧义时让用户选择；提交卡显示最终账号、站点、字段、附件和后果，隐藏凭据。目标或内容变化必须重新观察/确认，不能让模型将旧截图当当前状态。

人工接管卡说明登录/验证码/系统确认等原因、已完成部分和继续条件；任务paused，用户可“我已完成，重新检查”或取消。恢复按钮先重检目标、账号、资源与许可，不直接重放旧动作；用户在原生窗口工作时停止该目标的自动输入。网页提交结果未知时禁止提供无条件“一键重试”。

全局多任务队列显示每项正在使用的资源、等待用户/冲突/预算原因及停止入口；跨任务同时改同一对象需协调，不阻塞正常浏览。涉及退出、安装或数据迁移时显示会中断的任务、草稿保存和恢复点。全能力文字设计尚未进入HTML原型，不能将既有演示当成S20—S27已实现。

## 地址栏模式与“＋”输入规则（v0.7）

| 状态/动作 | 界面与行为 |
| --- | --- |
| 默认navigation | 保持现有网址/搜索行为；二丫输入框不常驻、不自动抢焦点 |
| 点击现有AI按钮 | 切到erya模式并聚焦；左侧显示“＋”，右侧显示发送图标；可见“二丫”模式标记，输入提示“给二丫下达指令…” |
| 输入/发送 | Enter发送，中文输入法composition期间Enter只上屏；空白且无有效附件不能发送；图标具备可访问名称 |
| 返回地址输入 | 再点二丫按钮、显式返回地址按钮或Ctrl+L退出二丫模式；Ctrl+L继续保持浏览器地址栏语义；二丫草稿留在原窗口/工作区，不作为网址提交 |
| Escape | 先关闭“＋”菜单/子层，再退出二丫模式；不清空未发送草稿，不取消已发送任务 |
| 失焦/切标签/导航 | 失焦不自动导航、不丢草稿；切换只影响显式目标绑定，不把新页面静默变成原任务上下文；URL更新不得覆盖二丫草稿 |
| 发送后 | 提示词作为用户消息进入左/用户气泡，回复进入另一气泡；输入保持二丫模式，可继续发送；退出模式不改变任务状态 |

网址输入与提示词使用两个独立缓冲及提交路径。二丫模式关闭搜索/历史补全及搜索建议请求，不能把提示词外发给搜索引擎；即使文本看起来是URL也只作为消息。navigation模式仍按原搜索/导航实现；不能恢复已删除的旧AI/Pi混用逻辑。发送按钮只在任务请求被可靠接收后清空本次草稿；失败保留原文/附件引用与可重试状态，重试沿用消息幂等键，不能重复派发写入。成功发送保留当前二丫输入焦点，气泡出现不转移焦点；窗口/工作区切换不自动载入他处草稿。

首版“＋”菜单承接已有可用的：用户显式选定的当前/多个标签、选区、选定笔记/邮件/日历引用、文件及截图。菜单只显示已接入且可用项；截图或文件入口缺少适配时说明不可用，不假装已支持。菜单选择表示加入本次上下文候选，不等于批准读取全部页面、上传云端或长期记忆。发送前用范围标签显示对象数、来源、附件大小与移除入口，说明实际模型和数据去向；读取、云端外发、上传与长期记忆分别按既有授权控制。麦克风等后续能力不因有“＋”自动启用。

单行地址栏不因长提示词把浏览器工具栏撑高；长文可从“＋→展开编辑”进入临时受控编辑层，提交仍走相同草稿及发送路径，不形成新的默认聊天入口。二丫模式明显区别于地址模式，但保留浏览器身份/安全状态可见提示，不伪装成正在访问的网页地址。

## 两个独立气泡的布局与消息流（v0.7）

固定两个角色容器：user与assistant，分别维护消息流、显示/隐藏、滚动位置和布局偏好。不是每条消息新增一个浮窗，不把用户提示词和回复合并在同一气泡。默认展示当前选定会话；消息携带conversationId/taskId/messageId与序号，角色气泡可查看该会话历史。后台其他会话只增加未读计数，不能切换或覆盖用户正在阅读的会话；查看/切换会话从可信气泡菜单或设置→二丫的任务/消息管理进入。

每个气泡有短标题/拖动把手、角色、当前工作区/会话、隐藏按钮；二丫气泡在有活动任务时提供停止/暂停入口。拖动仅作用把手，正文仍可选中/复制、点击链接、滚动和操作审批。鼠标/触屏pointer capture及取消均有清理，pointerup才提交最终位置，过程可节流预览；键盘用户可在气泡菜单移动/归位，不依赖拖拽。两个位置互不联动，点击只将该气泡提升到受控层级，不遮挡原生窗口按钮、地址栏输入与关键确认控件。

位置以宿主可用内容区DIP坐标及归一化锚点保存，不用网页DOM坐标、CSS滚动位置或裸屏幕像素。按profile＋workspace＋稳定窗口布局角色＋bubbleRole独立记忆；不以短命BrowserWindow ID作为持久键，多窗口不抢同一条写入。首次用默认边缘位置，窗口变窄、DPI/屏幕变化、最大尺寸调整或内容增长时重新夹取到可用区；至少保留标题、隐藏和停止操作可见。两个气泡可由用户部分重叠，默认错位不覆盖；设置提供分别重置位置和全部恢复默认，旧位置越界时自动归位。窄窗口改为可见区内错位/纵向排列，不扩到屏幕外。

尺寸按内容自适应：少量文字紧凑显示，长行换行，高度增长到各自上限后正文内部滚动，不裁掉正文或把审批按钮挤出可见区。用户与二丫最大宽/高分别可调，实际尺寸受“设置上限与当前可用区”共同限制；不声称最大尺寸就是固定尺寸。流式输出合并布局刷新、避免每token反复跳动；用户未在底部时不强制滚到底部，提供新消息标记。设置变化只调整布局，不截断消息、不清空历史、不触发新模型请求。

## 弹窗气泡设置与自动隐藏（v0.7）

下表为拟配置schema与试用默认值，数值尚待目标Windows与不同缩放实测；两角色独立，主进程和界面共同校验。上限用DIP，计时用秒；相同字段不在其他文档重复定义数值。

| 拟设置键 | 试用默认值/范围 | 行为 |
| --- | --- | --- |
| bubbles.user.maxWidthDip | 360；240—960 | 用户气泡最大宽；可用区更小时继续夹取 |
| bubbles.user.maxHeightDip | 240；120—800 | 用户气泡最大高，正文超限滚动 |
| bubbles.assistant.maxWidthDip | 480；240—960 | 二丫回复气泡最大宽 |
| bubbles.assistant.maxHeightDip | 420；120—800 | 回复最大高，任务操作区始终可用 |
| bubbles.user.hideAfterSeconds | 8；0—3600 | 用户气泡静止后的隐藏时长，0表示不自动隐藏 |
| bubbles.assistant.hideAfterSeconds | 30；0—3600 | 回复完成后的隐藏时长，0表示不自动隐藏 |

“自动消失”仅是隐藏气泡，不删除消息、不取消任务、不撤销权限，也不自动把内容存入长期记忆。用户消息在可靠接收后显现；二丫消息在首个有效片段/新消息显现，不因每个token或事件重放反复弹出。普通计时从消息完整显示且进入静止状态后开始；新消息重置对应角色计时，不影响另一角色。鼠标悬停、键盘焦点、文字选择、滚动阅读、拖动、展开详情及流式生成期间暂停，交互结束后按完整时长重新计时。

待审批、需要用户接管、发送失败和结果未知/关键错误不能被普通自动隐藏悄悄略过；关键卡固定可见直到处理，用户仍可显式隐藏，任务保持等待并在地址栏二丫入口显示未处理标记。隐藏/计时到期从不产生同意、取消或重试。用户手动隐藏当前流式消息后，同messageId的后续token不再强制弹回；下一条真正的新消息再次自动显示。新消息只显示所属角色气泡，不抢焦点、不强切工作区/窗口、不发声音；后台/无痕/敏感会话遵守身份与通知策略，仅留通用未读标记，回到对应窗口/工作区后展示授权可见内容。

地址栏入口的未读/任务标记在两个气泡隐藏或退出输入模式后仍可见；菜单可分别“显示用户消息”“显示二丫回复”“显示全部”，无需发新提示词。隐藏界面与删除聊天、清理附件、忘记长期记忆是不同操作，设置→二丫中分别说明。首次输入附加范围、读取、云端外发和写入审批仍通过可信界面完成，不用“已打开气泡”代替许可。

## 二丫设置页与资料管理（v0.7）

设置导航和页标题由“AI 助手”改为“二丫”；模型与密钥、权限/数据外发、消息与任务管理、记忆与容量、弹窗气泡、预算与通知、数据位置与备份均在此页分组管理。气泡菜单只提供定位到该页或打开当前任务详情，避免出现多份互不一致的配置。显示erya目录的实际解析位置、容量分类与恢复入口；配置偏好单独可恢复默认，不能顺带清空会话、任务和记忆。

当前HTML原型仍是旧基础闭环演示，未实现地址栏双模式或双气泡；后续UX-OMNI/UX-BUBBLE须据本节更新交互原型并真实实现后验收。浏览器源码中占位入口的事实保留为待开发现状，不把本轮文档变更写成按钮已经启用。

补充可达性：入口菜单可由二丫按钮的右键/键盘菜单打开，也可由二丫模式“＋”菜单底部的“消息与任务”进入；恢复气泡、切会话、停止任务和定位设置均不依赖悬停。新审批/接管/关键错误产生稳定的新pendingAction标识，只显现一次，重放旧事件不反复弹出；审批卡来自网关真实记录，不由模型正文伪造。
