# 06 · 需求文档

> 状态：草案  · 日期：2026-07-27
> 本文档只描述项目需求，不涉及技术选型、实现方式与工具选型。所有需求的措辞以「可被验证」为基准。
> 需求编号规则：FR-{域}-{序号}（功能性需求）/ NFR-{类}-{序号}（非功能性需求）/ CON-{序号}（约束条件）。

---

## 1. 项目定位与目标

### 1.1 产品定位

Urchin 浏览器是一款面向知识工作者与开发者的桌面浏览器，以两条差异化定位为核心：

- **AI 原生**：浏览器内置 AI 助手始终在侧，能感知用户当前浏览的页面内容，无需用户复制粘贴到外部 AI 服务即可完成摘要、追问、改写等任务。
- **开发者友好**：浏览器内置开发者工具增强层，兼容主流扩展生态，并允许用户自带 AI 提供方而非被绑定到某一服务。

### 1.2 项目目标（v0.1 → v1.0）

| 目标 | 度量标准 |
|---|---|
| 提供可日常使用的浏览器基础能力 | 安装即可用于网页浏览、书签管理、历史检索 |
| 提供「感知当前页面」的 AI 助手 | 用户在任意页面打开侧边面板，AI 回复与当前页面内容相关 |
| 提供「不绑定单一 AI 提供方」的能力 | 用户可自行接入至少一类第三方 AI 服务，且不修改浏览器代码 |
| 提供兼容主流扩展生态的能力 | v0.1 至少 1 款、v0.2 起至少 3 款主流 Chrome 扩展能零修改安装并运行核心功能 |
| 保证第三方代码崩溃不影响主浏览器 | 任意第三方 AI 提供方或扩展崩溃，主浏览器与已打开的标签不受影响 |
| 保证用户敏感数据不外泄 | AI 提供方的鉴权凭据在静态存储与传输过程中均处于受保护状态 |

## 2. 用户角色与典型场景

### 2.1 用户角色

| 角色 | 描述 |
|---|---|
| 知识工作者 | 长时间阅读长文、研究报告、技术文档，希望快速抽取要点 |
| 前端/全栈开发者 | 需要查看页面 DOM、网络请求、控制台输出，并希望借助 AI 解析异常 |
| AI 应用开发者 | 希望把浏览器作为信息采集前端，结构化抽取页面内容供下游使用 |
| 隐私敏感用户 | 拒绝数据默认外发，希望自行选择本地或自托管 AI 服务（v1.0+ 满足） |

### 2.2 典型场景（v0.1 覆盖）

- **场景 1**：用户阅读一篇长文章 → 打开 AI 侧边面板 → 点击「摘要当前页」→ AI 流式返回结构化摘要 → 用户继续追问细节。
- **场景 2**：开发者调试页面 → 打开开发者工具增强层 → 发现 3 个控制台错误 → 点击「AI 总结所有错误」→ AI 输出根本原因推测与修复路径建议。
- **场景 3**：用户加载一个第三方 AI 提供方 → 在警告对话框中明确确认 → 该提供方崩溃 → 浏览器其他功能不受影响 → 用户得到清晰提示并可选择重试或卸载。
- **场景 4**：用户关闭浏览器时打开了 10 个标签 → 重启后标签列表与对应 URL 自动恢复。

## 3. 功能性需求

### 3.1 浏览器主体（FR-BROWSE）

| 编号 | 需求 |
|---|---|
| FR-BROWSE-01 | 浏览器应支持多窗口创建、关闭、最大化、最小化、全屏切换。 |
| FR-BROWSE-02 | 浏览器应支持单窗口内多标签的创建、关闭、切换、重排。 |
| FR-BROWSE-03 | 每个标签应独立持有自己的页面、导航栈与崩溃隔离——一个标签崩溃不得影响其他标签或主浏览器。 |
| FR-BROWSE-04 | 每个标签应支持前进、后退、刷新、强制刷新（忽略缓存）操作，且各操作的可用状态实时反映到界面。 |
| FR-BROWSE-05 | 浏览器应提供地址栏，接受 URL 或搜索关键词输入，并自动识别输入类型：URL 直接导航，搜索词转发至默认搜索引擎。 |
| FR-BROWSE-06 | 地址栏应提供输入补全建议，v0.1 数据源限定为本地历史记录。 |
| FR-BROWSE-07 | 浏览器应提供书签管理，支持创建、删除、移动、文件夹分组、按位置排序。 |
| FR-BROWSE-08 | 浏览器应提供访问历史记录，支持按域名、按时间范围检索。 |
| FR-BROWSE-09 | 浏览器应提供隐私模式（隐身窗口），在该模式下不记录历史、不缓存表单输入、不持久化 Cookie。 |
| FR-BROWSE-10 | 浏览器应提供「主页」与「新标签页」入口，v0.1 可为空白页或固定 URL。 |
| FR-BROWSE-11 | 浏览器应提供下载管理器，支持下载进度显示、暂停、取消、打开下载文件所在目录。 |
| FR-BROWSE-12 | 浏览器应提供菜单栏与命令面板（快捷键触发的全键盘操作入口），常用操作均可通过命令面板完成。 |

### 3.2 AI 原生能力（FR-AI）

| 编号 | 需求 |
|---|---|
| FR-AI-01 | 浏览器应内置 AI 侧边面板，默认在主窗口侧边可见，可折叠展开。 |
| FR-AI-02 | 侧边面板应与当前激活的标签关联——切换标签时，侧边面板切换到该标签对应的对话上下文。 |
| FR-AI-03 | 每个标签可持有独立的 AI 对话历史，标签关闭后对话进入「孤儿」状态保留一段可配置时间，超时后清理。 |
| FR-AI-04 | 侧边面板应支持用户发送文本消息并接收 AI 流式回复，回复过程中可被打断（中止按钮）。 |
| FR-AI-05 | 侧边面板应支持 Markdown 渲染，至少包括：标题、列表、代码块（含语法高亮）、链接、引用。 |
| FR-AI-06 | 代码块应提供「复制到剪贴板」按钮。 |
| FR-AI-07 | 侧边面板应提供「重试上次回答」「清空当前对话」「查看消息元数据（令牌用量、完成原因等）」操作。 |
| FR-AI-08 | 用户应能从任意标签页触发「摘要当前页」动作——浏览器自动抽取当前页面正文，作为 AI 上下文，生成摘要。 |
| FR-AI-09 | 用户在触发任何「向 AI 发送当前页面内容」的动作前，浏览器必须显式告知用户「即将发送页面内容到 {提供方名称}」并征求明确同意；用户同意后可保存偏好，不再重复询问相同提供方。 |
| FR-AI-10 | 抽取的页面正文长度超出模型上下文窗口时，浏览器应自动截断并在界面中标记「内容已截断」警告。 |
| FR-AI-11 | 当页面正文抽取算法失败时（如纯前端渲染的应用），浏览器应回退到整页文本作为上下文，并标记「使用了降级抽取方式」警告。 |
| FR-AI-12 | 侧边面板应在 AI 回复出错时显示可读的错误描述，并标注「是否可重试」。 |
| FR-AI-13 | 侧边面板应支持在标签 URL 变化时提示用户「当前对话是否针对新页面继续」——v0.1 简化为「自动保持」，v0.2+ 给用户选择。 |

### 3.3 AI 提供方管理（FR-PROVIDER）

| 编号 | 需求 |
|---|---|
| FR-PROVIDER-01 | 浏览器不得绑定任何特定的 AI 提供方——所有提供方以可插拔形式接入。 |
| FR-PROVIDER-02 | 浏览器应提供「提供方注册表」界面，列出所有已安装的提供方及其状态（已就绪/初始化中/不可用/已禁用）。 |
| FR-PROVIDER-03 | 用户应能从本地路径或包名安装第三方提供方。 |
| FR-PROVIDER-04 | 安装第三方提供方前，浏览器必须显示明确的风险告知，至少包含：「第三方代码将以独立进程运行，崩溃不影响浏览器，但来源可信度需用户自行判断；当前版本未做签名校验。」用户必须主动输入确认文本（如「我确认」）方可继续。 |
| FR-PROVIDER-05 | 提供方应通过明确的契约版本与浏览器协商——版本不匹配时浏览器应拒绝加载并给出可读原因。 |
| FR-PROVIDER-06 | 提供方应声明自身能力（如：是否支持流式、是否支持工具调用、是否支持图像输入、是否为本地推理）。浏览器应基于能力声明决定是否暴露对应功能。 |
| FR-PROVIDER-07 | 提供方应声明自身速率限制；浏览器据此做主动节流，避免提供方被限流或拒绝服务。 |
| FR-PROVIDER-08 | 提供方应通过统一的「鉴权凭据存储」访问 API Key 等敏感数据，不得自行读取或绕过——每个提供方只能访问属于自己的凭据。 |
| FR-PROVIDER-09 | 提供方应拥有独立的私有持久化存储命名空间，不得读写其他提供方或浏览器主存储的数据。 |
| FR-PROVIDER-10 | 提供方应能响应「中止」信号——用户中止生成后，浏览器应在合理时间内（建议 100ms 量级）停止接收该提供方的流式输出。 |
| FR-PROVIDER-11 | 提供方出现的错误应被结构化分类（如「鉴权失败」「限流」「网络异常」「内容超长」「内容被拒」「内部错误」「用户取消」），并标注「是否可重试」。 |
| FR-PROVIDER-12 | 浏览器应对「网络异常」「限流」类错误自动重试，重试采用指数退避策略，最多 3 次；对「鉴权失败」「内容超长」「内容被拒」等不重试，直接上报用户。 |
| FR-PROVIDER-13 | 提供方子进程在长时间空闲后应被自动回收，释放系统资源。 |
| FR-PROVIDER-14 | 提供方崩溃后，浏览器应标记该提供方不可用并通知用户；下次用户调用时自动重新启动该提供方，不丢失浏览器其他状态。 |
| FR-PROVIDER-15 | 用户应能在设置中卸载提供方，卸载时应同时清理该提供方的私有存储与凭据。 |

### 3.4 开发者友好（FR-DEV）

| 编号 | 需求 |
|---|---|
| FR-DEV-01 | 浏览器应内置 Chromium 开发者工具，可通过标准快捷键打开。 |
| FR-DEV-02 | 浏览器应在 Chromium 开发者工具之上附加「增强层」，提供至少 2 个自定义面板：网络请求摘要、控制台异常聚合。 |
| FR-DEV-03 | 网络请求摘要面板应展示当前被检视页面发起的所有请求列表，至少包含：URL、方法、状态码、MIME 类型、大小、耗时。 |
| FR-DEV-04 | 网络请求摘要面板应支持按状态码（错误优先）、耗时（慢请求优先）筛选与排序。 |
| FR-DEV-05 | 控制台异常聚合面板应展示运行时异常与应用层日志，至少包含：级别、来源、文本、调用栈。 |
| FR-DEV-06 | 用户应能对网络请求与控制台异常条目执行「AI 分析」动作——将该条目作为上下文发送给当前激活的 AI 提供方，流式返回分析结论与建议。 |
| FR-DEV-07 | 用户应能批量选中所有控制台错误执行「AI 总结根本原因」动作。 |
| FR-DEV-08 | 用户应能在开发者工具增强面板中「右键 → 发送到侧边面板」任意条目，将条目内容作为侧边面板对话的额外上下文。 |
| FR-DEV-09 | 开发者工具增强层应在高频事件场景下保持流畅——事件采集不得阻塞被检视页面或浏览器主界面。 |
| FR-DEV-10 | 开发者工具增强层应通过命令面板与快捷键 F12 触发切换。 |
| FR-DEV-11 | 浏览器应提供扩展加载能力，兼容主流扩展生态的标准清单文件格式（v0.1 兼容 Manifest V3）。 |
| FR-DEV-12 | 扩展应能调用主流扩展生态的标准 API 子集，v0.1 至少包含：标签管理、扩展运行时、扩展本地存储、窗口管理、受限的脚本注入。 |
| FR-DEV-13 | 扩展应跑在与主浏览器隔离的环境中——一个扩展崩溃不得影响其他扩展、主浏览器或标签页。 |
| FR-DEV-14 | 扩展的权限应在安装时校验：未知权限拒绝安装；不支持的权限字段应在界面中明确标注「不支持」而非静默接受。 |
| FR-DEV-15 | 扩展脚本注入（向页面注入 JavaScript 的能力）在 v0.1 仅允许针对用户在清单文件 `host_permissions` 字段中声明的白名单域名执行，不得对任意页面注入。 |
| FR-DEV-16 | 扩展应拥有私有本地存储命名空间，与其他扩展、与浏览器主存储互相隔离。 |
| FR-DEV-17 | 扩展后台脚本崩溃后浏览器应自动重启该扩展后台，连续 3 次崩溃后标记禁用并通知用户，由用户决定是否手动重新启用。 |

### 3.5 隐私与安全（FR-SEC）

| 编号 | 需求 |
|---|---|
| FR-SEC-01 | 浏览器不得默认向任何外部服务发送用户浏览数据、页面内容或 AI 对话内容；任何外发动作必须有用户明确同意或用户主动触发的动作作为前提。 |
| FR-SEC-02 | 浏览器不得默认上报遥测、崩溃报告或使用统计；此类数据收集在 v1.0 引入时必须默认关闭，由用户主动开启。 |
| FR-SEC-03 | 浏览器在静态存储任何敏感凭据（如 AI 提供方 API Key）时必须使用操作系统提供的加密机制。 |
| FR-SEC-04 | 浏览器不得将敏感凭据明文写入日志、配置文件或导出文件。 |
| FR-SEC-05 | 浏览器在导出用户数据（书签、历史、设置等）时，必须排除所有敏感凭据。 |
| FR-SEC-06 | 用户页面内容、扩展代码与第三方提供方代码三者应处于相互隔离的执行环境——任意一方不得直接访问另一方的内存或执行上下文。 |
| FR-SEC-07 | 所有跨执行环境的调用须经浏览器中转层，中转层对入参与出参做契约校验，未知字段或格式不符的调用应被拒绝。 |
| FR-SEC-08 | 浏览器应防止路径穿越攻击：用户提供方/扩展访问命名空间存储时，名称仅允许安全字符集。 |
| FR-SEC-09 | v0.2+ 引入网络拦截能力后，用户应能配置拦截规则（如 hosts 列表、域名模式），被拦截的请求应被静默拒绝并记录可关闭的统计信息。 |
| FR-SEC-10 | 浏览器应明确告知用户「加载第三方提供方/扩展的风险」并在用户确认前不执行加载。 |
| FR-SEC-11 | 卸载提供方或扩展时，必须彻底清理其遗留的存储数据与凭据，不得残留。 |

### 3.6 持久化与会话恢复（FR-PERSIST）

| 编号 | 需求 |
|---|---|
| FR-PERSIST-01 | 浏览器关闭后重启，应恢复上次的窗口布局与标签列表（URL 与标题）。 |
| FR-PERSIST-02 | v0.1 仅恢复 URL 与标题，不恢复滚动位置、表单输入、会话存储——v0.5+ 升级为完整会话恢复。 |
| FR-PERSIST-03 | AI 对话历史应在浏览器关闭时持久化，重启后可继续之前的对话。 |
| FR-PERSIST-04 | v0.1 AI 对话历史在关闭时一次性落盘；v0.2+ 升级为实时落盘以避免崩溃丢失。 |
| FR-PERSIST-05 | 书签与访问历史应在每次变更后即时持久化。 |
| FR-PERSIST-06 | 用户设置应在变更后即时持久化，跨重启保持一致。 |
| FR-PERSIST-07 | v0.2+ 应提供书签与历史的导出能力（HTML/JSON 格式）。 |
| FR-PERSIST-08 | v0.3+ 应提供完整数据备份与恢复（含设置与 AI 对话历史，不含凭据）。 |
| FR-PERSIST-09 | v0.3+ 删除书签、历史、AI 对话时，应提供 5 秒撤销窗口。 |

### 3.7 设置与个性化（FR-SET）

| 编号 | 需求 |
|---|---|
| FR-SET-01 | 浏览器应提供设置界面，支持修改：默认搜索引擎、主页与新标签页 URL、下载目录、外观主题（亮色/暗色）、AI 提供方默认选择、快捷键自定义（v0.2+）。 |
| FR-SET-02 | 设置项应采用「默认值 + 用户覆盖」分层模型——浏览器升级引入新默认值时，用户未自定义的项跟随新默认，用户自定义的项保持不变。 |
| FR-SET-03 | 设置变更应跨浏览器内多个窗口立即同步，不需重启。 |
| FR-SET-04 | 浏览器应提供命令面板（Ctrl+Shift+P 触发），支持通过键盘搜索并执行任意命令。 |
| FR-SET-05 | 浏览器应提供基础可访问性支持：键盘可达所有操作、对比度满足 WCAG AA 级（v1.0+）。 |
| FR-SET-06 | v0.1 内置中文与英文两套界面文案；v1.0+ 开放用户可自定义语言包的国际化机制。 |

## 4. 非功能性需求

### 4.1 性能（NFR-PERF）

| 编号 | 需求 | v0.1 目标 | v1.0 目标 |
|---|---|---|---|
| NFR-PERF-01 | 冷启动时间（从启动到主窗口可见且可交互） | P95 ≤ 3 秒 | P95 ≤ 3 秒 |
| NFR-PERF-02 | 10 标签场景内存占用 | P95 ≤ 500 MB | P95 ≤ 500 MB |
| NFR-PERF-03 | 50 标签场景内存占用 | 不强制 | P95 ≤ 1.5 GB |
| NFR-PERF-04 | 界面操作响应延迟（点击/输入到视觉反馈） | P95 ≤ 100 毫秒 | P95 ≤ 50 毫秒 |
| NFR-PERF-05 | AI 流式令牌到达后到界面渲染可见的延迟 | P95 ≤ 50 毫秒 | P95 ≤ 30 毫秒 |
| NFR-PERF-06 | 标签切换延迟（点击标签到页面可见） | P95 ≤ 100 毫秒 | P95 ≤ 50 毫秒 |
| NFR-PERF-07 | 开发者工具增强面板的高频事件采集不得造成被检视页面可感知的卡顿 | 帧率下降 ≤ 5% | 帧率下降 ≤ 2% |

### 4.2 可靠性（NFR-REL）

| 编号 | 需求 |
|---|---|
| NFR-REL-01 | 任意单一组件崩溃（标签渲染、扩展后台、AI 提供方子进程、AI 调度器）不得导致主浏览器退出。 |
| NFR-REL-02 | AI 调度器崩溃后，浏览器应自动重启该子系统，用户感知为「AI 功能暂不可用 5 秒内」，对话历史与配置不丢失。 |
| NFR-REL-03 | 标签渲染进程崩溃后，浏览器应展示错误页而非自动重载，由用户决定是否重试——避免循环崩溃。 |
| NFR-REL-04 | v0.2+ 浏览器应集成崩溃报告本地存储能力（小型转储文件），上传为可选且默认关闭。 |
| NFR-REL-05 | v0.3+ 浏览器应提供自动更新能力，更新前校验签名完整性。 |
| NFR-REL-06 | 跨进程调用必须设置超时，默认 30 秒，超时后调用方收到明确错误而非永久阻塞。 |
| NFR-REL-07 | 数据库写入应支持并发读写不阻塞主浏览器界面。 |

### 4.3 安全（NFR-SEC）

| 编号 | 需求 |
|---|---|
| NFR-SEC-01 | 用户页面内容与浏览器主进程的执行环境必须严格隔离——页面 JavaScript 不得直接访问 Node 接口、文件系统或浏览器内部状态。 |
| NFR-SEC-02 | 扩展代码与页面 JavaScript 必须处于不同的执行上下文，扩展对页面的访问须经明确的脚本注入机制，且 v0.1 仅限白名单域名。 |
| NFR-SEC-03 | 第三方提供方代码必须运行在与主浏览器、与其他提供方相互隔离的独立进程，只通过契约定义的接口访问浏览器资源。 |
| NFR-SEC-04 | 所有跨执行环境的调用边界必须做契约校验，校验失败时调用被拒绝并记日志。 |
| NFR-SEC-05 | 所有外部输入（用户输入、提供方响应、扩展请求、网页消息）必须被视为不可信，使用前必须经过校验或转义。 |
| NFR-SEC-06 | 敏感凭据的存储文件权限应限定为仅当前用户可读写（类 Unix 系统下 0600，Windows 系统下 ACL 受限）。 |
| NFR-SEC-07 | v0.4+ 第三方提供方加载前应校验其签名，未签名的提供方一律拒绝加载。 |
| NFR-SEC-08 | v1.0 发布前应通过依赖漏洞扫描（含传递依赖），无严重级漏洞。 |

### 4.4 兼容性（NFR-COMPAT）

| 编号 | 需求 | v0.1 | v0.4+ |
|---|---|---|---|
| NFR-COMPAT-01 | 目标操作系统 | 仅 Windows 10/11 64 位 | + macOS（最近两个主版本）+ Linux（主流发行版） |
| NFR-COMPAT-02 | 扩展生态兼容性（清单文件格式） | Manifest V3 | V3 + 部分 V2 兼容期 |
| NFR-COMPAT-03 | 扩展生态兼容性（API 子集覆盖率） | 至少支持标签/扩展运行时/扩展本地存储/窗口/受限脚本注入 | 完整主流子集 |
| NFR-COMPAT-04 | 真实扩展可用性 | 至少 1 款主流扩展（如 JSON 查看器类）核心功能可用；v0.2 起至少 3 款（广告拦截、开发者工具、JSON 查看器类） | 90% 主流扩展零修改可用 |
| NFR-COMPAT-05 | AI 提供方接入兼容性 | 至少 1 款官方预装提供方 + 用户自行加载的第三方提供方 | + 本地推理提供方（v1.0） |

### 4.5 可维护性与可测试性（NFR-MAINT）

| 编号 | 需求 |
|---|---|
| NFR-MAINT-01 | 浏览器各子系统应有清晰边界与契约，单一子系统的内部变更不应迫使其他子系统同步修改。 |
| NFR-MAINT-02 | 所有跨子系统调用应有类型化契约定义，契约变更应可通过类型检查发现影响范围。 |
| NFR-MAINT-03 | 所有关键决策应有决策留痕文档，包含「否决方案及理由」，便于未来回顾。 |
| NFR-MAINT-04 | 测试覆盖率应分阶段达标：v0.1 ≥60% → v0.2 ≥65% → v0.3 ≥70% → v0.4 ≥75% → v1.0 ≥80%（数值以 [03-技术栈 §4](./03-技术栈.md#4-测试覆盖率适配门槛) 为单一真源）。 |
| NFR-MAINT-05 | 工具类与纯函数（如 URL 解析、提示词拼装、路径校验）测试覆盖率 ≥95%。 |
| NFR-MAINT-06 | AI 提供方契约边界测试覆盖率 ≥90%（v0.1 ≥80%）。 |
| NFR-MAINT-07 | 端到端测试应覆盖核心用户路径：启动、开标签、导航、AI 摘要、关闭——v0.1 每路径至少 1 条正向用例；v1.0 全覆盖。 |
| NFR-MAINT-08 | 提交前应运行 lint、类型检查、单元测试、覆盖率检查，任一失败则拒绝提交。 |
| NFR-MAINT-09 | 提交信息应结构化，包含变更类型（新增/修复/重构/文档/杂项）与简短描述。 |
| NFR-MAINT-10 | 每次发布应在版本迭代文档中记录一行摘要，版本号遵循语义化版本规则。 |

### 4.6 可访问性与国际化（NFR-A11Y）

|---|---|---|---|
| NFR-A11Y-01 | 键盘可达性 | 所有操作可通过键盘完成 | + 自定义快捷键 |

## 5. 约束条件

| 编号 | 约束 |
|---|---|
| CON-01 | 项目首版发布前开发资源为小型团队规模，所有功能优先级以「最小可验证闭环」为准。 |

## 6. 范围排除（v0.1 明确不做）

下列功能虽属产品远期愿景，但 v0.1 明确排除，不纳入验收：

- macOS 与 Linux 平台支持
- 移动端伴侣应用
- 同步能力（书签/历史/AI 对话跨设备同步）
- 本地大模型推理（如 ollama/llama.cpp 集成）
- 完整的网络请求拦截与广告过滤（v0.2+ 引入）
- 完整的扩展生态 API 覆盖（如 cookies/history/webRequest/declarativeNetRequest）
- 标签跨窗口拖拽
- 完整会话恢复（含滚动位置与表单状态）
- 自动更新机制
- 用户账号系统
- 遥测与崩溃报告上传
- Urchin 原生扩展 API（与 Chrome 兼容层并行演进，留待 v2.x+）
- 多 AI 提供方智能路由（按用户偏好/能力自动选提供方）
- 历史 AI 对话浏览抽屉
- 单标签多对话
- 团队协作功能
- 页内查找（Ctrl+F）、页面缩放、打印、证书错误页自定义（基础浏览器能力，v0.2+ 评估纳入）

- 加载 3 款主流 Chrome MV3 扩展，核心功能可用。

- 测试覆盖率达到 NFR-MAINT-04 的 v1.0 标准（≥80%）。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| AI 提供方 | 为浏览器提供 AI 能力的可插拔模块，可能封装某个云端 API 或本地推理引擎 |
| 侧边面板 | 浏览器主窗口侧边的 AI 助手面板 |
| 开发者工具增强层 | 在浏览器原生开发者工具之上附加的、由本项目实现的额外面板与功能 |
| 扩展 | 来自主流扩展生态、可零修改加载到本浏览器中的第三方功能包 |
| 标签 | 浏览器窗口内独立加载一个页面的单元 |
| 隐私模式 | 不记录历史与表单的浏览模式 |
| 命名空间隔离 | 不同提供方/扩展拥有互相独立的存储区域，无法读写对方数据 |
| 契约 | 不同执行环境之间调用的格式约定，包含输入输出字段与校验规则 |
| Manifest V3 | 主流扩展生态的当前标准清单文件格式 |
| 长文摘要 | AI 读取当前页面正文并输出结构化摘要的能力 |
| 流式回复 | AI 输出以增量方式逐段到达界面，而非一次性返回完整结果 |
