# ADR-019 · 内存回归线环境分线（CI 750MB / 本机 800MB）

> 状态：Accepted · 决策日：2026-11-10 · 关联决策：ES2
> 关联：[ADR-008 v0.1 范围与工期](./ADR-008-v0.1范围与工期.md) · [ADR-018 E2E 按需选择](./ADR-018-E2E按需选择.md) · [E2E 用例选择表](../E2E用例选择表.md) · [perf.spec.ts](../../apps/desktop/tests/e2e/perf.spec.ts)

---

## 1. 背景

`apps/desktop/tests/e2e/perf.spec.ts` 用 `app.getAppMetrics()` 测 10 标签总工作集。2026-10-27 起采用双线：

- **目标线 500MB**：ADR-008 的 v0.1 验收值（当时实测 358MB）。此后新增 GenOffice 六编辑器、邮箱、DevTools 面板、工作区、pi-web、dsh 等能力，**该线已事实失守**——超出只告警，不假装达标。
- **回归线 750MB**：单线，超出即红。

2026-11-10 实测：**本机 707.7 / 711.0 / 715.9 / 740.2MB**（多次全量运行区间），**CI 567.4MB**。本机运行值距 750MB 单线只剩 10~42MB；而本机与 CI 的环境差约 150MB（同代码、不同宿主负载/GPU/杀毒扫描），已经**超过单线的全部余量**。

后果：单线会把「宿主环境噪声」判成代码回归，逼着开发者反复重跑到绿，或者干脆开始忽略这条用例——两种结果都让回归线失效。

## 2. 决策

**ES2 · 回归线按环境分线（MUST）**

- **目标线 500MB**：仅 `console.warn`，不判红；重校目标线仍属产品决策（需改 ADR-008），本用例不代替该决策。
- **回归线**：CI **750MB** / 本机 **800MB**（`process.env.CI` 判定）。显式 `URCHIN_PERF_BUDGET_MB` 可覆盖两者。
- 判定仍取 3 次采样的**最小值**（降低瞬时噪声），不做「连续 3 次超线」之类的跨运行累积——那需要持久化状态，且会把反馈推迟到第三次运行。

**ES2.1 · 文档口径**

选择表与 README 必须写成「500 是目标线（告警）、750/800 是回归线（判红）」，并注明本机/CI 实测值；不得把 750/800 描述成「达标线」。

## 3. 否决方案

| 方案 | 否决理由 |
| --- | --- |
| 保持单线 750MB | 本机正常值已到 740MB；环境噪声 ~150MB > 余量，误红概率高（2026-11-10 单次已测到 740.2） |
| 单线 800MB（不分环境） | 等于把 CI 的回归线也放宽到 800，CI 567 → 800 的恶化空间过大，丧失预警意义 |
| 连续 3 次超线才红（单线 750） | 需要跨运行持久化样本；反馈被推迟到第三次；且不解决「本机噪声 > 余量」的根因 |
| 直接把目标线改成 800 | 属产品决策（ADR-008 验收标准），不能由测试用例单方面改；且会抹掉「目标已失守」这个事实 |

## 4. 影响

- 只改 `perf.spec.ts` 的判定表达式与注释，不改采样方法与用例数量。
- 本机默认回归线 800MB，CI 默认 750MB；两者都保留 `URCHIN_PERF_BUDGET_MB` 覆盖口，便于临时对照。
- 目标线 500MB 的告警保持原样，文档继续如实记录「已事实失守」。
