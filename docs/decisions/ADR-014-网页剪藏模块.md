# ADR-014 · 网页剪藏模块（M26 Clipper）：多格式快照 + 深度抽取 + MHTML 查看器

> 状态：Accepted · 决策日：2026-11-01 · 关联：M26 / CL1-CL10
> 关联文档：[网页剪藏功能规划](../网页剪藏功能规划.md) · [新模块接入约束声明](../新模块接入约束声明.md) · [AGENTS.md §一/§九](../../AGENTS.md)

## 1. 背景

用户需求：地址栏截图按钮之后增加「剪藏（Clipper）」按钮，参考 Obsidian Web Clipper 的机制，把网页保存到 `<用户数据目录>/documents/clipper`；设置页在「通用」与「操作」之间增加「剪藏」页。

讨论后追加要求：

1. 保存格式除 Markdown 外增加 MHTML，用于图文网页存档；
2. 能自动解除的前端复制限制要自动解除；登录/付费/验证码不做绕过；只提供 MHTML/PDF/截图级别快照；
3. 截图 + OCR 先占位、延后开发；
4. PDF/截图本期一起做；
5. MHTML 需要浏览器内只读查看器；GenOffice 打开 MHTML 需要分阶段实现（A 过渡、B 转换、C 原生）；
6. MHTML/PDF/截图默认先剔除正文外内容（广告、导航、侧栏等）。

## 2. 决策

### CL1 · 独立剪藏面板，而不是点击即保存

- 点击地址栏按钮 → 独立无边框子窗口（`?view=clipper&tabId=<id>`），复用收藏夹面板/状态栏模式。
- 面板支持文件名、属性、正文预览/编辑；MHTML/PDF/截图显示只读快照说明。
- 否决「直接保存」：无法预览/修正标题与属性，也看不到抽取质量。
- 否决「主窗口 React 模态」：BrowserView 永远在 React 之上，必须隐藏网页或另开窗口；独立窗口更符合参考插件交互。

### CL2 · 四种实际格式 + OCR 占位

| 格式 | 扩展名 | 实现 |
|---|---|---|
| Markdown | `.md` | Defuddle 正文 + 模板 + frontmatter |
| MHTML | `.mhtml` | `webContents.savePage(path, 'MHTML')` |
| PDF | `.pdf` | `webContents.printToPDF()` |
| 截图 | `.png` | CDP `Page.captureScreenshot` 整页；超过 16000px 自动分段 |
| OCR | — | 面板禁用占位，延后实现 |

- 面板每次可选格式；设置项 `clipper.defaultFormat` 提供默认值。
- 否决「只做 Markdown + MHTML」：用户明确要求 PDF/截图作为受限页面的兜底。
- 否决「本期做 OCR」：OCR 依赖（Windows OCR 语言包 / Tesseract 模型）与准确率问题未定，先占位。

### CL3 · 抽取与 Markdown 使用 Defuddle（与参考插件同源）

- 渲染进程 `defuddle/full`：`Defuddle` 抽正文，`createMarkdownContent` 转 Markdown。
- 主进程只负责执行页面脚本取 HTML，不解析 DOM；避免主进程 CPU 阻塞。
- 依赖：`defuddle`（MIT）+ `turndown`（MIT）。
- 否决自研 HTML→Markdown：复杂表格/公式/代码块/脚注质量差，维护成本高。

### CL4 · 深度抽取自动解除前端复制限制

自动化、无用户开关：

- 直接读 DOM，不经过页面 `copy/selectstart/contextmenu` 事件；
- 忽略 `user-select:none`；
- 开放 Shadow DOM 递归收集；
- 闭 Shadow DOM 通过 CDP `DOM.getDocument({pierce:true})` 兜底（调试器被占用则降级）；
- 跨域 iframe 通过 `webFrameMain.framesInSubtree` 逐帧执行脚本；
- 可选快照前滚动加载懒加载资源。

边界：不破解登录、付费墙、验证码、DRM；只保存用户可见内容。否决「站点特判脚本」：规则易腐烂且维护成本高。

### CL5 · 快照清洗默认开启

- `clipper.cleanSnapshot=true` 默认：用 Defuddle 正文重新构建阅读模式 HTML，再导出 MHTML/PDF/截图，去掉广告/导航/侧栏/评论。
- 面板可临时切换「原页完整」。
- 否决「对 MHTML 事后编辑」：MHTML 是 MIME 包，事后清洗需要重写资源映射；生成前清洗更可靠。
- 否决「在原页 DOM 临时删广告再保存」：容易误删正文且污染当前页面。

### CL6 · MHTML 只读查看器

- 新增 `FileKind='mhtml'`，识别 `.mhtml/.mht`。
- 专用 BrowserView 加载 `file://...`：`javascript:false`、`sandbox:true`、无 preload；链接跳转改为新标签打开。
- 否决「用 React iframe 直接 render MHTML」：自定义协议下 multipart 资源还原不可靠。
- 若 Electron 43 实测无法渲染 file MHTML，启用自研 MHTML→HTML 兜底（解析 `multipart/related`），或外部浏览器打开。

### CL7 · GenOffice 打开 MHTML 分三阶段

| 阶段 | 方案 | 状态 |
|---|---|---|
| A | GenOffice Home `.mhtml` → 宿主只读 MHTML 阅读器 | 本期 |
| B | MHTML→自包含 HTML → GenOffice HTML 编辑器（保存语义另行定义） | 后续 |
| C | vendor/genoffice 原生 MHTML 编辑器（打开/编辑/保存） | 最终方向 |

- 否决「本期直接改 vendor/genoffice 增加 MHTML kind」：改动大、上游同步成本高，先以宿主阅读器过渡。

### CL8 · 保存目录固定为 `documents/clipper`

- 不开放路径设置，避免路径穿越、迁移与跨平台复杂度。
- 文件名净化、扩展名归一、重名追加 ` (2)`。
- 否决「用户自定义目录」：首版无必要，后续如需再加。

### CL9 · 前端复制限制与访问控制的边界

- 可解除：客户端复制限制、遮罩、开放/闭 Shadow DOM、跨域 iframe（用户可见内容）。
- 不解除：登录、付费墙、验证码、DRM；不引入绕过访问控制的技术。
- 质量低时提示改用 MHTML/PDF/截图，而不是静默换格式。

### CL10 · OCR 占位

- 面板格式下拉保留「OCR 文本（即将支持）」禁用项。
- ADR 记录后续候选：Windows.Media.Ocr（Windows 优先）或 Tesseract.js；OCR 结果必须标注可能有错字。
- 否决本期引入 OCR：依赖体积/语言包/准确率问题未评估完毕。

### CL11 · Markdown 剪藏图片本地化

- **决策**：剪藏为 Markdown 时默认下载远程图片到本地 `assets/` 目录，md 中改为相对路径 `assets/<name>`，使 GenOffice 打开剪藏 md 时离线可见图片。
- **复用 GenOffice owned-asset 生命周期**（不重新发明 manifest 格式）：
  - 通过 urchin-embed re-export `writeImageIntoOwnedAssets` / `reconcileOwnedAssets` / `extractMarkdownImageSources`（`vendor/genoffice/apps/urchin-embed/src/main/index.ts`）。
  - 剪藏调 `writeImageIntoOwnedAssets` 落盘图片 + 自动注册 `.genoffice-assets.json` 清单（files + pending）。
  - 保存后调 `reconcileOwnedAssets` 把 pending 转 documents + GC 无引用文件。
  - GenOffice 打开剪藏 md 时 `md-asset://` 协议自动服务 `assets/` 图片（无需 genoffice 侧改动）。
- **删除时自动清理**：修改 `vendor/genoffice/apps/shell/src/main/index.ts` 的 `deleteFiles` handler，删除 `.md` 后调 `reconcileOwnedAssets(path, [])`——传空 imageSources 会删除该 docKey，siblingMarkdownReferences 扫描存活 md 算引用集，GC 清理独占图片，共享图片保留。
- **失败回退**：下载失败（防盗链/超时/404/SSRF/超 50MB）保留原远程 URL + 面板展示 warning；不阻断保存。
- **设置项** `clipper.localizeImages`（默认 true）；embedApi 不可用时（GenOffice 加载失败/旧版产物）自动跳过，保留原行为。
- **否决方案**：
  - 剪藏自己写 manifest 文件（不通过 urchin-embed）：需复制 genoffice 的 manifest 格式 + sanitize + sha256 + lock 逻辑，维护成本高且无法与 genoffice 的 `withManifestLock` 互斥。
  - 剪藏不写清单（图片游离在 manifest 外）：GC 不会误删（安全），但删除 md 时也不会清理（磁盘孤儿）。
  - data URI 嵌入 md：膨胀 md 文件体积，不利于编辑。

## 3. 后果

- 新增模块 M26（main + renderer），IPC 域 `clipper.*`；设置项 `clipper.*`。
- 新增 `.mhtml/.mht` 文件类型与只读查看器；文件关联文档组扩展。
- 新增依赖 `defuddle` / `turndown`（MIT）；`node-pty` / `ssh2` 补入 desktop 依赖只为修复 pi-web-host utilityProcess 运行时解析，不改变 M26 进程边界。
- **CL11 新增**：`apps/desktop/src/main/clipper/image-localizer.ts`（图片下载 + 路径重写）；`clipper.saveMarkdown` 入参加 `pageUrl`、返回加 `warnings`；`clipper.config` 返回加 `localizeImages`。
- **CL11 vendor 改动**（⚠ vendor 升级时须合并）：
  - `vendor/genoffice/apps/urchin-embed/src/main/index.ts`：re-export 三个 asset-lifecycle 函数。
  - `vendor/genoffice/apps/shell/src/main/index.ts`：`deleteFiles` handler 加 `reconcileOwnedAssets` GC 调用。
  - **改 vendor 源码后必须跑 `node scripts/genoffice-build.mjs shell` 重建 urchin-embed 产物**，否则运行时加载的旧产物没有新 API。
- 覆盖率：新增代码纳入现有 v0.2 门槛（≥65%），并补单元/E2E。
- 风险：MHTML 原生渲染已实测可用但需随 Electron 升级复测、清洗快照可能缺防盗链图片、闭 Shadow DOM 与 DevTools CDP 冲突、超长截图自动分段。
