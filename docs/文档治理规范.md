# 文档治理规范

> 状态：已生效 · 建立：2026-11-11 · 最近更新：2026-11-11
> 关联：[文档治理报告-2026-11-11](./文档治理报告-2026-11-11.md)（首轮审计与处置清单）· [事实登记表](./事实登记表.md)（登记事实与 R 规则）· [文档索引](./文档索引.md)（导航与文档体系版本）
> 定位：本文是项目文档体系的**常驻治理规范**——命名、格式、分类、生命周期、版本、责任与门禁。一次性审计结论不落本文（见治理报告）；与 [事实登记表](./事实登记表.md)、[ADR-012](./decisions/ADR-012-发布通道与版本号治理.md) 冲突时以后者为准。

## 1. 目的与适用范围

- **适用**：根目录 4 份（`AGENTS.md` / `README.md` / `CHANGELOG.md` / `RELEASE_NOTES.md`）+ `docs/` 全部文档（含 `contracts/`、`decisions/`、`archive/` 子目录）。
- **不适用**：`vendor/**`（上游引入，其锚点由 [打包核查清单](./打包核查清单.md) 管理）；本地未跟踪产物（`tmp/`、`.workbuddy-ai/`、`.zcode/`、`test-results/` 等）；第三方包内 README。
- **上位约束**：AGENTS.md §三「事事有记录」、§〇.3 修改红线（本文不触碰 AGENTS.md 架构性条款；涉及 AGENTS.md 的改动一律走 §〇.4 授权）。

## 2. 命名规则

1. **目录即分类**：文档归属由所在目录承载（`contracts/` = 契约、`decisions/` = 决策、`archive/` = 归档），文件名不再重复分类词。
2. **设计主线编号冻结**：`docs/00-07` 编号已占用且被 40 处 `AGENTS.md §X` 式引用与既有链接依赖，**不重排、不复用**；新增设计主线文档接续编号。
3. **一次性文档命名**：`主题-类型-YYYY-MM-DD.md`，类型词 ∈ `评估 / 调研 / 报告 / 清单 / 台账 / 交接`。存量不合规文件**不单独批处理重命名**，在归档迁移（§6）时顺带执行。
4. **语言**：中文主题为命名主选；技术专名与既定英文术语可保留英文（如 `ADR-`、`pi-web-`、`E2E`）。
5. **字符**：统一半角连字符 `-` 分隔；文件名禁止全角标点、空格、下划线混用。
6. **日期后缀只用于一次性文档**：常驻文档的时间信息记录在头部状态行「最近更新」，不进文件名（否则每次更新都改名、断链）。

## 3. 格式标准

1. **头部状态行四要素**（blockquote，紧随一级标题）：`状态` / `建立`（日期）/ `最近更新`（日期）/ `关联`（真源、决策 ADR、执行脚本）。
2. **状态词表**：常驻文档 `草稿 → 已生效`（设计主线定稿后用 `已定稿`）；一次性文档交付即 `已冻结`；归档后由索引标注。**历史事实不回改**（与 `check-doc-drift.mjs` 的 `HISTORY_EXEMPT` 口径一致）。
3. **标题层级**：一级标题唯一；章节从二级 `##` 起；编号章节保持全文一致风格。
4. **跨文档链接**：一律相对链接（`./` 与 `../`）；引用 AGENTS.md 章节写作「AGENTS.md §X」文本并附相对链接。
5. **表格优先**：枚举性内容用表格，一行一事实；避免在段落里复述表格已有数值。

## 4. 复述禁令（登记事实单一真源制）

登记事实**只允许在真源出现**；其他文档只描述用途并链接真源，不复述数值或组成。改真源即全链生效，从机制上杜绝「改一处、漏七处」。

| 事实                 | 唯一真源                                         |
| -------------------- | ------------------------------------------------ |
| verify 链组成        | `package.json` 的 `scripts.verify`               |
| 覆盖率门槛阶梯       | [03-技术栈 §4.1](./03-技术栈.md)                 |
| 决策计数口径         | [decisions/决策索引.md](./decisions/决策索引.md) 头部口径行 |
| 模块清单与编号       | [04-模块全景 §1](./04-模块全景.md)               |
| E2E spec 清单        | `apps/desktop/tests/e2e/manifest.json`           |
| 版本号规则           | [ADR-012](./decisions/ADR-012-发布通道与版本号治理.md) + `scripts/build-version.mjs` |
| 文档清单与分类       | [文档索引](./文档索引.md)                        |
| ADR 存量与缺号说明   | `docs/decisions/` 目录 + 决策索引                |

- **豁免**：历史文档（`CHANGELOG.md`、`ADR-008`）记录当时事实，不回改；本规范与事实登记表为规则手册自身。
- **演进方式**：需要新增「登记事实」时，先在 [事实登记表](./事实登记表.md) 登记（F 系列），再回填本表——顺序不可反，防止规范先于台账空转。

## 5. 分类体系（8 类）

| 类别             | 位置                 | 收录标准                                                     | 现有代表                                                       |
| ---------------- | -------------------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| 根目录文档       | 仓库根               | 项目级门面与规范、全局版本记录                                | AGENTS.md、README.md、CHANGELOG.md、RELEASE_NOTES.md           |
| 设计主线         | `docs/00-07`         | 愿景/架构/技术栈/模块/路线/需求的定稿设计文档                  | 00-设计总览 … 07-立项准备                                      |
| 接口契约         | `docs/contracts/`    | A-K 跨进程/跨模块契约（zod schema 设计态真源）                 | A-提供方接口 … K-主题系统                                      |
| 决策             | `docs/decisions/`    | ADR 深度决策文档 + 全项目决策索引                              | ADR-001…019、决策索引.md                                       |
| 功能规划         | `docs/`              | 单模块交付前的规划文档（需求/架构/分波计划）                    | 网页翻译、邮箱、网页剪藏功能规划等                             |
| 约束与登记       | `docs/`              | 约束性基线与登记事实台账                                        | 新模块接入约束声明、事实登记表、E2E用例选择表、本文            |
| 运维手册         | `docs/`              | 可重复执行的操作手册与速查表                                    | 打包核查清单、vendor-pi-升级核查清单、共存注意事项、开发避坑清单等 |
| 一次性报告与台账 | `docs/`（后续部分入 `archive/`） | 时点性评估/调研/报告/交接；状态分「活跃 / 已冻结」两级          | pi-web-评估、pi-web-重建台账、code-review-progress 等          |

归档区 `docs/archive/` 为第 9 个位置（一次性文档的终态），建立于 P2 结构批（见治理报告 §4），启用后本表更新。

## 6. 生命周期

```
草稿 → 已生效/已定稿（常驻） ──────────────────────→ 持续更新（改头部「最近更新」）
     ↘ 已冻结（一次性：交付即冻结）→ 归档（git mv docs/archive/）
```

- **归档操作**（四步，缺一不可）：`git mv` 至 `docs/archive/` → 头部追加「已冻结」行 → [文档索引](./文档索引.md) 同步 → `pnpm verify`。归档时顺带按 §2.3 修正命名。
- **废弃**：先在索引标「拟废弃」并保留一个批次，确认无链接引用后删除（git 历史可追溯）；禁止跳过标注直接删。
- **禁止**：归档区文档再被更新——需要演进时另起新文档并在旧文头部留指针。

## 7. 版本管理

- **文档体系版本与代码版本分离**：文档体系版本号（`v0.0.x`）记录在 [文档索引](./文档索引.md) §版本；代码版本走 [ADR-012](./decisions/ADR-012-发布通道与版本号治理.md) 的 dev 通道，两者互不联动。
- **必须 bump 索引版本并留变更行**：新增 / 移动 / 重命名 / 废弃文档、分类调整、真源迁移（即一切「集合与结构」变更）。
- **不必 bump**：纯内容修正（数值更新、措辞、格式）——只改该文档头部「最近更新」。

## 8. 更新频率与责任人

单人项目口径：执行责任人为当次会话 AI Agent，验收责任人为用户；下表「责任人」指执行方。

| 文档类别             | 更新时机                                   | 责任与验收         |
| -------------------- | ------------------------------------------ | ------------------ |
| 设计主线（00-07）    | 对应模块/架构变更的**同一批次**内同步       | 执行 AI + 用户验收 |
| 契约（A-K）          | 契约边界变更同场；配套契约测试同步          | 执行 AI + 用户验收 |
| 决策（ADR + 索引）   | 决策发生当场（附否决方案理由）              | 执行 AI + 用户确认 |
| 执行台账             | 每次执行后立即（如重建台账、打包核对记录）  | 执行 AI            |
| 运维手册             | 流程变化当场（如 verify 链扩容、打包步骤变）| 执行 AI            |
| 一次性报告           | 交付即冻结；后续演进另起新文档并留指针      | 执行 AI            |
| 文档索引             | 一切集合/结构变更**同场**更新               | 执行 AI            |
| 登记事实真源         | 事实变更当场 + 事实登记表同步登记           | 执行 AI + 用户确认 |
| AGENTS.md 修订留痕   | 方案被后续决策推翻时回改标注（走 §〇.4）    | 执行 AI + 用户授权 |

## 9. 门禁集成

- **现状**：`pnpm check:docs`（AGENTS §九.4 G13）由 `scripts/check-doc-drift.mjs` 执行，规则 R1-R4（错误命令 / pre-commit 描述 / 覆盖率阶梯一致性 / CHANGELOG 版本行格式），规则手册见 [事实登记表](./事实登记表.md) R1-R3 与脚本头注。
- **待授权扩展**（提案见 [治理报告 §4 P1 批](./文档治理报告-2026-11-11.md)）：R5 verify 组成复述检测、R6 决策计数口径检测、R7 索引完整性（零孤儿零死链）。任何新规则**先登记事实登记表再进脚本**，未登记不生效。
- **执行协议**：一切文档集合/结构变更 → `prettier --write` → `pnpm verify` → 提交（AGENTS §五.6 顺序）；纯文档提交按既有先例不加 CHANGELOG 版本行。
