# ADR-020 · 文件关联注册模型（非侵入 Capabilities 模型 + 命令行打开链路修复）

> 状态：Accepted · 决策日：2026-11-11 · 关联决策：FA1 / FA2 / FA3
> 关联：[ADR-009 GenOffice 编辑器融合](./ADR-009-GenOffice编辑器融合.md) · [04-模块全景](../04-模块全景.md) · [开发避坑清单 §九](../开发避坑清单.md) · 代码：`apps/desktop/src/main/file-association/`、`apps/desktop/src/main/files/`

---

## 1. 背景

设置页「默认应用」自 v0.1 起就能把本浏览器登记为音视频 / 文档 / 图片的打开方式，但用户实测「右键 → 打开方式 / 双击」基本不可用。2026-11-11 只读诊断（`reg query`，未改本机注册表）定位到六个独立缺陷：

| 编号 | 现象 | 根因 |
| --- | --- | --- |
| R1 | 用本浏览器打开任何图片/视频都报错 | 注册命令是 `"<exe>" "<appDir>" "%1"`，启动后 `argv[1]` 是**应用目录**；旧解析只跳过 `argv[0]`，于是把目录当文件交给查看器 |
| R2 | 系统「默认应用 → 按文件类型」里选不到本浏览器 | 只写了 ProgID，**没有** `Applications\<exe>` + `Capabilities\FileAssociations`（Win10/11 按**应用**分组，仅 ProgID 不认为它是一个应用） |
| R3 | 双击 `.bat` 不再执行、`.js` 被浏览器接管 | 旧模型直接改写 `HKCU\Software\Classes\.ext` 的**默认值**，且「文档」组按 kind 全量登记 42 个 text 扩展 |
| R4 | 登记了一堆浏览器根本打不开的格式 | 白名单缺失：`wma/mid/avi/mpeg/3gp` 等 Chromium 不解码的类型也宣称可作默认 |
| R5 | PDF 标签页空白/触发下载 | 主窗口 `webPreferences.plugins` 未开，Chromium 内置 PDF 查看器不生效 |
| R6 | 状态显示「已关联 n/m」但实际并没有关联 | 判定读 `.ext` 默认值：既忽略 `UserChoice`（真实默认由系统按 hash 写入），也没有「登记项指向旧 exe」的检查；每查一个扩展名起一次 `reg.exe` |

同时确认了本机参考实现（Quark 浏览器）的注册模型：`Capabilities\FileAssociations` + `Applications\<exe>` + ProgID `Application\ApplicationName`，**不写 `.ext` 默认值**。

## 2. 决策

**FA1 · 采用非侵入注册模型（MUST：不得写 `.ext` 默认值）**

- 应用级（一次写全）：`HKCU\Software\Classes\Applications\<exe>`（默认值 + `FriendlyAppName` + `DefaultIcon` + `shell\open\command`）、`HKCU\Software\Clients\StartMenuInternet\UrchinBrowser\Capabilities`（`ApplicationName/Description/Icon`）、`HKCU\Software\RegisteredApplications`。
- 扩展名级：`HKCU\Software\Classes\UrchinBrowser.<ext>`（默认值 + `Application\ApplicationName` + `DefaultIcon` + `shell\open\command`）、`.ext\OpenWithProgids`、`Capabilities\FileAssociations` 的 `.ext = ProgID`。
- **禁止**写 `HKCU\Software\Classes\.ext` 的默认值：等于静默劫持系统行为、无备份不可回滚，且存在 `UserChoice` 时本就被忽略（写了也不生效）。默认值由用户在系统「打开方式 / 默认应用」确认后由 Windows 写入。
- 单元测试以「不得出现 `Classes\.<ext>` 的 `/ve` 写入」为硬断言。

**FA2 · 可注册格式白名单（MUST：单一真源 `ASSOCIABLE_EXTENSIONS`）**

- 只登记本浏览器确实能渲染的格式：音频 8（mp3/wav/ogg/oga/m4a/flac/aac/opus）、视频 6（mp4/m4v/webm/ogv/mov/mkv）、文档 17（pdf/docx/pptx/xlsx/md/markdown/mdx/txt/log/csv/tsv/json/jsonc/xml/yaml/yml/toml）、图片 10（png/jpg/jpeg/gif/webp/svg/bmp/ico/avif/apng）。
- 移除 `wma/mid/avi/mpeg/3gp` 等 Chromium 不解码的类型；`js/ts/bat/cmd/ps1/sh/py/css/sql/ini` 等代码/脚本/配置类**不登记**（仍可在应用内「打开文件 / 拖放」打开，分类表不受影响）。
- `html/htm/mht/mhtml` 不进入「文档」组，归「默认浏览器」能力（`UrchinHTML`），避免同一扩展出现两个 ProgID 在「打开方式」里重复。

**FA3 · 打开链路以 `app.getAppPath()` 过滤（MUST）**

- 新增 `parseOpenArgs(argv, appPath)`，首启与 `second-instance` 共用 `openFromCommandLine`：跳过 `argv[0]`、开关、`.`/`..`、**与 `appPath` 等值的参数**；URL 与文件分离、保序去重；多个文件 → 多标签。
- 媒体/图片统一落到 `urchin://file-viewer`（内联渲染 + 失败可提示 + 「用系统程序打开」出口），不再 `file://` 直开标签页（旧实现用 `encodeURI` 拼 URL，文件名含 `#`/`?` 会截断，且失败无任何反馈）。
- 打开失败可见化：`routeLocalFile` 返回 false 时 `dialog.showErrorBox`（文件关联启动时没有浏览器窗口上下文，静默失败表现为「双击没反应」）。

**FA3.1 · 状态与治理**

- `file-association.getStatus` 改按 `Capabilities\FileAssociations` 一次查询（固定 2 次 `reg.exe`，与扩展名数量无关），返回 `exePath / devMode / appRegistered / exeMatches`。
- 新增 `file-association.unregister`（幂等清理：只删本应用写的 ProgID / `OpenWithProgids` 值 / 能力值；`.ext` 默认值仅在确认等于本应用 ProgID 时才清）、`file-association.openSettings`（只唤起系统设置页）。
- 设置页显示登记目标路径，并对「开发实例（未打包）」「登记指向旧位置」给出显式警示 + 确认后「清除本应用关联」。

**FA3.2 · 兜底出口**

- 新增 `file.openExternal`（`shell.openPath`，失败回传原因不抛错）；查看器在媒体/图片解码失败、`binary`/`html` 类型时提供「用系统程序打开」按钮，不再是一片空白或死胡同。
- 主窗口 `webPreferences.plugins: true` 以启用 Chromium 内置 PDF 查看器（Flash/PPAPI 已从 Chromium 移除，无第三方插件加载面）。

## 3. 否决方案

| 方案 | 否决理由 |
| --- | --- |
| 继续直接写 `.ext` 默认值（旧模型） | 静默劫持、不可回滚；有 `UserChoice` 时被忽略，用户会认为「点了没用」；会改坏 `.bat`/`.js` 等系统关键关联 |
| 直接写 `UserChoice`（含 hash） | 需要复刻 Windows 私有哈希算法，属未公开协议；被系统判定为篡改，风险高 |
| 只写 ProgID（不写 `Applications\<exe>`） | Win10/11 的「默认应用」按应用分组展示，仅 ProgID 时选不到本浏览器（R2 的根因） |
| 登记全部 `EXT_KIND` 扩展名 | 浏览器打不开的格式被宣称可作默认，用户选了仍是空白页；且抢走代码/脚本类关联 |
| 「设为默认」时静默失败 | 文件关联启动没有窗口上下文，用户只会看到「双击没反应」，无法自助排查 |
| 媒体继续 `file://` 直开标签页 | 与 Ctrl+O / 拖放行为不一致（无法上/下一个切换），`encodeURI` 不转义 `#`/`?` 导致打开错误路径，且失败无反馈 |
| 由程序代用户清理本机历史错误关联 | 属用户机器上的不可逆注册表写入；改为提供功能入口（设置页按钮 + 确认弹窗），由用户自己决定 |

## 4. 影响

- 用户侧：登记后需在系统「打开方式 / 默认应用」确认一次（Windows 强制），之后双击即可用；「已登记」≠「已是默认」，设置页文案已明确。
- 已有旧登记（含把 `.ext` 默认值改成 `UrchinBrowser.<ext>` 的残留）可用设置页「清除本应用关联」+「设为默认打开方式」重建；`.ext` 默认值只在确认属于本应用时才清理。
- 开发模式（`electron <appDir>` / `pnpm start`）登记的是 `node_modules` 里的开发可执行文件，仅供测试；设置页对此显式警示。
- 测试：`file-association.test.ts` 重写为 24 例（含「不得写 `.ext` 默认值」「`parseOpenArgs` 全形态」），handler 18 例（新状态语义 / unregister / devMode / openSettings），白名单 5 例，`file.openExternal` 3 例，查看器兜底 4 例，设置页 12 例。
