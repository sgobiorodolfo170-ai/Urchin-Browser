# ADR-021 · 打开文件职责划分（外部入口归浏览器、GenOffice 入口归编辑器）

> 状态：Accepted · 决策日：2026-11-11 · 关联决策：FA4 / FA5 / FA6 / FA7 / FA8 / FA9
> 取代：[ADR-009](./ADR-009-GenOffice编辑器融合.md) 的 **GF1**（「打开文件模块以 GenOffice 为框架，Urchin 查看器仅作保底」）
> 关联：[ADR-020 文件关联注册模型](./ADR-020-文件关联注册模型.md) · [04-模块全景 §7](../04-模块全景.md) · [开发避坑清单 §九](../开发避坑清单.md) · 代码：`apps/desktop/src/shared/file-routing.ts`

---

## 1. 背景

ADR-009 GF1 把「打开文件」整体交给 GenOffice：md / pdf / html / docx / pptx / xlsx 六类文件无论在哪个入口打开，都先构造 `urchin://genoffice` 伪地址、创建编辑器 `WebContentsView`，浏览器内置查看器只作产物缺失时的保底。

落地后出现三类问题：

| 现象 | 根因 |
| --- | --- |
| 从资源管理器双击 `.md` / `.pdf` / `.html` 也要起一个完整编辑器视图（启动慢、脏状态与关闭守卫介入），而用户多数只想**看**一下 | 「打开文件」不分入口，全部按「编辑」处理 |
| 同一个文件从侧栏打开进查看器、从文件关联打开进编辑器 | 主进程 `main/index.ts` 与渲染层 `App.tsx` 各维护一份 kind→通道映射，靠人工同步 |
| 在 GenOffice 主页「打开本地文件」选 `.txt`，结果落在浏览器查看器 | GenOffice 内部入口复用了「外部路由」，与 GenOffice 自己的帮助说明（txt/json 进 Markdown 源码视图）不符 |

2026-11-11 用户口径：**GenOffice 主打编辑、副阅读，入口收敛到它自己的主页**（文档目录 / 「打开本地文件」卡片）；**浏览器本体主打阅读、兼简单编辑，面向外部文件**（在系统里选择「用顽童浏览器打开」→ 直接进网页标签通道）。

## 2. 决策

**FA4 · 分界线是入口，不是格式（MUST）**

| 入口 | 目标通道 |
| --- | --- |
| 外部：Windows 文件关联 / 命令行 `%1`、Ctrl+O、拖放 | **浏览器**（内置查看器；html → `file://` 网页标签；MHTML → 只读视图） |
| 外部例外 | **Office 三类 docx / pptx / xlsx 直进 GenOffice**（用户明确要求：默认应用里继续登记，双击即用编辑器打开） |
| GenOffice 主页：文档目录 / 最近 / 收藏 / 「打开本地文件」 | **GenOffice 编辑器**（阅读=同一编辑器只读态） |

**FA5 · 路由单一真源（MUST）**

`apps/desktop/src/shared/file-routing.ts` 提供 `resolveOpenTarget(kind, nameOrPath, origin)`，主进程（`routeLocalFile` / `openInGenOffice` / `openLocalEntry`）与渲染层共用；渲染层不再自己 `file.stat` 判类型或拼标签 URL（统一走 `file.openPath` IPC，由主进程 `openLocalEntry` 处理目录/文件）。

**FA6 · GenOffice 可编辑能力表（MUST：单一真源）**

`GENOFFICE_EDITABLE_EXTENSIONS`（扩展名 → 编辑器 app）同时决定：

1. GenOffice 内部入口是否直进编辑器（未命中 → 转交浏览器通道）；
2. 是否记入「最近打开」。**不用 kind 判定**：`kind='text'` 同时覆盖 `.txt/.json/.csv`（该记）与 `.js/.sh/.ps1/.css`（不该记），粒度太粗。

为后续留空间：GenOffice 上线图片/音视频等新编辑器时，只在该表追加扩展名（如 `['mp4','video']`），路由与 recents 同时生效。

**FA7 · GenOffice 内部选中不支持格式 → 转交浏览器通道（MUST NOT 静默/拒绝）**

GenOffice 主页打开图片/音视频/二进制/脚本时，回落 `routeLocalFile`，用户不丢操作。

**FA8 · 「最近打开」单一存储（MUST）**

`genoffice-home.json` 由 `GenOfficeHomeStore` 单例持有（`ctx.genofficeHomeStore`）；浏览器通道打开文档类文件时也调用 `recordRecent`，两个入口写同一份列表。

**FA9 · 外部例外集合保持窄（SHOULD）**

`EXTERNAL_GENOFFICE_KINDS` 仅 `{docx, pptx, xlsx}`。GenOffice 将来新增图像/音视频编辑器时，**不自动**把对应 kind 加入该集合（否则图片会从浏览器阅读通道被抢走）；需要另行决策。

## 3. 否决方案

| 方案 | 否决理由 |
| --- | --- |
| 维持 GF1（全部入口都进 GenOffice） | 外部「看一眼」也要起编辑器视图（慢、脏状态/关闭守卫介入）；与用户「浏览器主外、主打阅读」的定位冲突 |
| 全部归浏览器（Office 也不进 GenOffice） | 双击 .docx 只会看到「不支持预览」，把已交付的编辑器藏在二级点击里，体验明显退化；用户明确保留例外 |
| 按格式而非入口分流（如「文档类全部进 GenOffice」） | 同一格式（.md/.pdf）既想阅读又想编辑，按格式分无法表达两种意图；入口天然携带意图 |
| 保留两套 kind→通道映射（主进程 + 渲染层） | 已有漂移风险（本轮即发生：文件关联与侧栏行为不一致）；双真源无法靠评审长期维持 |
| recents 用 kind 判定 | `text` 粒度太粗，脚本/配置类会污染「最近打开」；且未来新编辑器无法只改一处 |
| GenOffice 内选到不支持格式时静默忽略/报错 | 用户操作丢失，且不知道发生了什么 |

## 4. 影响

- **行为变化**：外部双击 `.md` / `.pdf` / `.html` 从「GenOffice 编辑器」改为「浏览器阅读通道」（md/txt/json 可简单编辑、pdf 用 Chromium 内置查看器、html 作为网页标签）。Office 三类不变。
- **代码收敛**：删除 `main/index.ts` 与 `App.tsx` 两份 `genofficeAppByKind`；新增 `shared/file-routing.ts`、`file.openPath` IPC（`file.openPath` 取代渲染层的 `file.stat` + `tab.create` 组合）。
- **recents 连通**：浏览器侧打开的文档类文件出现在 GenOffice 主页「最近打开」，可从那里一键转入编辑器。
- **测试**：新增 `file-routing.test.ts`（external / genoffice 两个 origin × 全 kind/扩展名矩阵 + recents 判定 + URL 编码）；`file-handlers.test.ts` 补 `file.openPath` 4 例；`App.test.tsx` 补「Ctrl+O → file.openPath」1 例。
- **文档**：ADR-009 GF1 标注 superseded；[04-模块全景](../04-模块全景.md)、[开发避坑清单](../开发避坑清单.md) §九 同步。
- **遗留待评估**：`.doc/.xls/.ppt` 旧二进制格式（GenOffice 帮助页声称支持，但 Urchin 分类表未收录、未实测）暂不声明能力；脚本/配置类是否进 recents 保持现状（不入）。
