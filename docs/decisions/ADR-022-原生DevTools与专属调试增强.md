# ADR-022 · 原生 DevTools 与专属调试增强

> 状态：已生效（Accepted，路线已确认，产品迁移尚未实施）· 建立：2026-11-15 · 最近更新：2026-11-15
> 关联：[需求文档](../开发者工具需求文档.md) · [开发规划](../开发者工具开发规划.md) · [契约 G](../contracts/G-开发者工具增强.md) · [决策索引](./决策索引.md)
> 授权来源：用户明确要求「沿用 F12，放弃文档规划」，随后接受原生基线与专属增强建议，要求先固化决策、落盘需求和开发规划。本次授权落实文档，不代表已完成产品代码迁移。

## 1. 决策

**F12 采用 Electron 随附的 Chromium 原生 DevTools；停止将自研通用面板作为替代路线。Urchin 专属 Agent 调试能力只在有可验证收益时投入。**

| ID   | 决策         | 选定方案                                                                                                    | 否决方案及理由                                                                             |
| ---- | ------------ | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| DT14 | 通用调试基线 | Elements、Console、Network、Sources、Performance、Memory、Application 等交给随 Electron 分发的原生 DevTools | 继续自研全套面板：长期追赶浏览器协议与交互，现阶段没有已验证的差异化收益                   |
| DT15 | 入口与目标   | 沿用 F12；目标为所属浏览器窗口的当前网页；原生工具打开后绑定该网页，不随标签切换漂移                        | 补侧栏图标、绑定当前标签按钮、命令面板入口：用户已取消，不作为待办；另增快捷键不是本轮范围 |
| DT16 | 自研投资范围 | 停止通用面板和自定义 Panel API 路线；候选投入限于页面、Provider、Agent、工作区之间的调试证据与修复验证      | 重做 Network 瀑布图、Elements、Sources 或只加聊天按钮：原生与市场工具已覆盖大量能力        |

## 2. 为什么现在调整

### 2.1 本项目事实与证据边界

2026-11-15 对 `e32ab3b2`（dev.234）源码、现有构建及隔离测试配置进行审计；落盘前快进同步至 `c052a9fb`（dev.236），确认两版本间主进程与渲染层 DevTools 目录无差异。下表运行结果属于前述审计构建，不能用作未来实现的验收。

| 证据                     | 观察结果                                                                                                             | 对路线的影响                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| F12 实际入口             | 打开自研 React 第三列，提供 Network、Console、表达式求值；没有侧栏调试按钮与重新绑定按钮                             | 现有面板不是完整 Chromium DevTools；缺失的两个按钮已取消，不能再登记为待修复功能 |
| 采集数据与状态           | 网络耗时混用 epoch `wallTime` 与单调 `timestamp`；合法合成事件可产生负耗时并被 schema 拒绝；前端缓存未随后端上限裁剪 | 不宜继续在这条基础上扩大通用功能；若复用采集器，必须先修正确性与有界存储         |
| 真实 UI 生命周期         | 关闭自研面板后后台仍 attached；重开显示 detached；拖宽把手位置异常                                                   | 必须建立主进程权威状态和明确退出策略；修补旧 UI 不等于完成原生迁移               |
| 既有测试                 | 管理器与 handler 的 38 个单测通过，隔离 headless 配置下既有 3 个 E2E 用例通过                                        | 既有用例主要覆盖旧 IPC，未证明 F12 完整交互正确；默认有界面 E2E 曾受显示服务限制 |
| 原生独立窗口探针         | 对真实网页 webContents 调用 `openDevTools` 成功；可见原生主要面板                                                    | 原生基线具有实现可行性，但尚未接入产品 F12                                       |
| 原生与 debugger 共存探针 | 先附加自研 debugger 再开原生后，本次 evaluate 和事件接收仍可用                                                       | 不能把「必然抢占」写成事实；也不能由一次成功推导所有版本可靠共存                 |
| 原生嵌入探针             | `setDevToolsWebContents` 后出现打开事件与 DevTools 标题，但 `isDevToolsOpened()` 仍返回 false                        | 嵌入状态与生命周期未验证闭环，不得据此宣布可直接交付第三列原生工具               |

上述原生探针在 Linux 环境完成；Windows 10/11 产品验收仍待执行。依赖版本以 package.json 与 lockfile 为准，升级策略沿用 [ADR-017](./ADR-017-Electron版本升级策略.md)。

### 2.2 市场状态与预期结果

以下为截至 2026-11-15 的官方资料与产品能力观察，**不是市场份额、收入或用户需求调查**。厂商效果描述未经本项目独立验证。

| 路线 / 代表                     | 已公开的能力与商业状态                                                                              | 对 Urchin 的含义                                                          |
| ------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Chrome / Edge 原生工具          | 完整页面诊断工具持续迭代；Chrome AI assistance、Chrome/Edge DevTools MCP 已将调试信息接入 AI 工作流 | 「内置面板 + AI 解释错误」正在成为基础能力，不能单独构成长期研发理由      |
| Polypane 专用浏览器             | 商业订阅产品，以多视口、响应式、无障碍等任务能力为重点，同时保留原生 DevTools                       | 专属任务工具有市场，但成功形态不要求替代原生通用调试器                    |
| Cursor 浏览器工具 / Design Mode | 将页面、截图、控制台与代码编辑置于 Agent 工作流                                                     | 竞争焦点转向定位问题到修改、验证的完成效率，通用 Agent 已是必须对比的基线 |
| Replay                          | 商业产品公开强调录制、复现、Agent QA 与根因分析                                                     | 可复现证据和跨步骤追踪是差异化候选；不能据此认定 Urchin 用户已有付费需求  |

从未来结果衡量，两条路线都可以服务「发现错误 → 定位原因 → 修改 → 验证」。区别在于投入方向：原生路线快速获得完整、持续维护的页面诊断能力；自研路线只有解决原生不知道的 Urchin 上下文、权限、Provider 调用链和修复验证问题，才可能取得额外收益。界面风格统一、字段更少或支持多个模型，本身不足以证明研发必要。

**研发必要性判断**：原生 F12 接入属于必要基础建设；通用面板替代没有当前立项必要；专属证据与 Agent 闭环值得小规模验证，尚不足以承诺完整产品。未来 12–24 个月原生 AI 与协议接入继续普及是规划假设，不是确定预测；试验时必须重新检查竞争基线。

## 3. 能力与责任边界

- 「原生」指 Electron 所带的 DevTools 前端与 Chromium 调试能力，不等于安装了完整 Google Chrome。Google 账号、Gemini 云服务、Chrome 专属 AI 功能不会因打开 DevTools 自动获得。
- 不承诺所有 Chrome DevTools 扩展可用。扩展加载、session 隔离和权限仍受 Electron 与本项目兼容层约束，另按真实扩展验证。
- 原生 UI 的页面诊断能力由上游提供；窗口归属、F12、焦点、目标选择、关闭清理和隔离由 Urchin 负责。
- 原生基线不要求 Urchin 自动附加 `webContents.debugger`。未来采集服务按需附加；必须监听被断开与目标销毁，禁止争抢式自动重连。
- 增强使用现有 Provider / Agent 能力边界；不得为便利新增无鉴权的全局调试端口、向普通网页暴露任意 CDP，或默认上传完整页面和日志。

## 4. 被取代的规划与后果

1. [一期规划](../开发者工具增强一期实施规划.md) 冻结为历史；侧栏调试入口、「绑定当前标签」、自研 Elements/Sources/瀑布图以及按版本开放 Panel API 均不进入新待办。
2. [契约 G](../contracts/G-开发者工具增强.md) 保留旧实现记录与协议背景；当前需求以[需求文档](../开发者工具需求文档.md)为准，实施与状态以[开发规划](../开发者工具开发规划.md)为准。
3. 原生迁移通过后移除旧面板入口、布局占位与无调用方代码。共享采集器是否保留必须列出真实调用方；不为想象中的未来复用永久保留。
4. 原生嵌入验证失败时交付原生独立窗口，记录差异；不得退回「继续补齐自研通用面板」。原生方案本身不可用时应保留已可用版本并记录阻塞，不能宣称任务完成。
5. 本决策不变更现有 Agent/Provider/扩展隔离架构，不要求本轮升级 Electron 或修改版本治理。

## 5. 重启评估条件

只有出现可复现的高频用户任务，证明原生加通用 Agent 仍无法有效完成，且受限原型改善定位或修复成功率/耗时，才进入专属增强产品化。具体对比协议和退出条件见开发规划；失败则保留原生基线、停止该增强方向。重新启动通用面板或 Panel API 需要新的需求证据与替代本 ADR 的明确决策，不能把历史规划当授权。
