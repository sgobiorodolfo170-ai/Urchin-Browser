二丫建议采用“可替换的模型服务商接口＋一个主模型”的起步方式。先把工具执行、权限检查和结果验证做可靠，再增加便宜的辅助模型与本地模型。模型会提出调用建议，浏览器宿主负责真正执行和授权。本文为选型准备报告 v0.5，日期 2026-11-17；候选尚未完成项目实测，不指定未经验证的优胜型号。

## 已有基础与接入缺口

仓库基线为 `7f9f59af29c641ae5900849ee685dc3570a443b6`。`packages/ai-provider-contract/src/provider.ts` 已有流式、非流式接口，`tools()`、`embed()` 是可选接口。内置 `openai-compatible.ts` 只声明聊天与流式能力，不能据此判断二丫已经具备工具执行。

实现前需要补齐四件事：工具请求与结果的完整往返标识；结构化参数校验；真正取消网络请求；逐次用量与预算记录。当前消息角色只有 system/user/assistant，工具调用类型没有调用 ID；内置 Provider 的 `abort` 分支只记日志。协议兼容性要通过契约测试验证，不能仅更换 `baseUrl` 就宣称所有模型可用。

二丫与 pi 分离，模型设置、凭据、会话和记忆分别管理。pi 已使用的模型不自动成为二丫的配置或授权。

## 候选路线与分工

| 路线         | 候选与依据                                                                                                                                                                                                   | 项目评估重点                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 在线通用模型 | OpenAI 支持工具调用与结构约束，工具由应用执行并返回结果。[官方说明](https://developers.openai.com/api/docs/guides/function-calling)                                                                          | 中文任务完成率、工具参数准确度、端点兼容、账单与数据设置 |
| 在线通用模型 | Claude 的客户端工具通过 tool_use 和 tool_result 往返。[官方说明](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)                                                                     | 多步计划、证据引用、适配成本与账户可用性                 |
| 在线兼容模型 | DeepSeek 提供工具调用；严格模式及不同 API 格式有各自约束。[官方说明](https://api-docs.deepseek.com/guides/tool_calls/)                                                                                       | 中文指令、工具往返、重试费用、协议差异                   |
| 本地模型     | Qwen 文档给出 Qwen3 工具调用方式；Ollama 提供工具往返接口。[Qwen 文档](https://qwen.readthedocs.io/en/latest/framework/function_call.html)、[Ollama 文档](https://docs.ollama.com/capabilities/tool-calling) | 实际电脑内存/显存、冷启动、量化后准确率、部署维护        |

上述官方文档于 2026-11-16 查询，仅证明接口路线存在，不代表所有型号、量化版本或账户均可使用，也不构成性能排名。实施时记录实际模型 ID、快照或服务版本、接口版本、区域、许可和价格日期，避免用会漂移的名称作为唯一基线。

建议主模型承担理解目标、规划、证据比较和工具选择。低成本辅助模型在主链通过后用于标题、标签和候选记忆整理，不能批准操作、提升权限或直接提交关键记忆。嵌入模型用于语义检索，首版可以先用结构化字段与全文检索，证明有价值后再加入向量索引。

| 使用方式 | 对用户的意义                                 | 建议适用条件                               |
| -------- | -------------------------------------------- | ------------------------------------------ |
| 在线为主 | 起步较容易；允许发送的内容会到选定服务商     | 用户明确允许指定数据外发，并设费用上限     |
| 本地为主 | 可在断网时处理本地任务；速度和能力取决于电脑 | 用户优先本地处理，接受硬件与维护成本       |
| 混合     | 普通内容在线，敏感内容本地或拒绝处理         | 完成逐类数据路由后再开放，不能静默云端兜底 |

用户尚未选择数据路线时，文档推荐在线方案以降低起步难度，产品不能默认上传网页。选定网页读取权与向模型外发权分别控制；“本地模式”也要验证运行时没有远程回退和遥测正文外发。

## 如何选出首发模型

先排除不可用候选：账户和区域可用、数据用途设置符合用户选择、工具往返和取消可验证、用量可计量、有明确服务条款。再用同一套页面快照、工具白名单、提示词、预算和软件版本比较，禁止为某候选额外增加权限。

| 评分项             | 权重 | 计分依据                                   |
| ------------------ | ---- | ------------------------------------------ |
| 工具选择与参数准确 | 30%  | 正确工具、资源、参数和顺序的比例           |
| 端到端完成         | 25%  | 浏览器实际状态达到预设结果的比例           |
| 中文理解与证据决策 | 20%  | 独立评分人核对目标、引用、冲突与不确定性   |
| 延迟与稳定性       | 10%  | 同一网络/硬件下 p50、p95 和超时率          |
| 成本               | 10%  | 全部调用、重试、整理记忆后的每成功任务成本 |
| 适配维护           | 5%   | 协议、版本固定、错误可诊断性               |

各项先按预先定义的 0–100 分评分表归一化再加权。权限绕过、跨工作区泄露、未经批准外发与删除后记忆复活采用独立硬门槛；发生一例即不能发布，不能用高总分抵消。结构化输出通过只说明格式正确，内容与执行仍需验证。

开发阶段使用 PRD 的 30 个固定闭环任务，成功不少于 27 个（≥90%），另外运行安全隐私反例集。候选定版使用 120 个未参与调提示的独立任务，每任务运行 3 次，共 360 次；建议总体成功≥90%，四个任务类别各≥85%，同时报告首次成功、允许有限重试后的成功和实际失败原因。120 个任务分为读取理解、方案比较、授权写入、异常恢复各 30 个；安全测试另计，详见测试方案。所有阈值是拟定验收目标，结果栏保持“待测”。

首发决策记录应包括候选名称、日期、每项得分、硬门槛结果、失败清单、费用、主模型与备用模型。备用模型先经过同样测试，故障切换仍遵守数据外发范围；无法满足时暂停并告知用户。

## 成本和预算

单任务费用 = 各调用输入 token 费用＋输出 token 费用＋缓存/工具/嵌入费用；每成功任务成本 = 全部任务实际费用 ÷ 实际成功任务数。被取消的调用也可能已经产生费用。记忆整理、失败重试与主动建议纳入同一账本。

纯算术示例：假设每任务总输入 20,000 token、输出 2,000 token，假设单价分别为每百万 2 元和 8 元，则一次约 0.056 元，1,000 次约 56 元；这不是任何供应商报价，不含额外工具费和失败重试。

预算应有单任务、每日、每月三个层级。宿主在发起下一调用前预留预计最大费用，结束后按真实用量结算；价格或用量缺失时显示估算并采用保守上限。金额上限由用户在设置中决定，模型不能更改。用量 token 限制、步骤数和时间限制即使无法精确计价也要生效。

## 新增模块的模型评测要求

B/C批在原模型评测外加入：中文相对日期转绝对日期、IANA时区与DST、全天排他结束日、重复修改范围、冲突候选；笔记事实/建议区分、任务拆解与画布对象选择；邮件诉求提取、收件人/附件核对与邮件注入。日期和ID由schema及服务核验，不能依赖模型自评。画布媒体理解须单独声明模型能力，初期只承诺文字便签。

每个新增批次单列完成率、错误参数率、费用与延迟；原30/120任务基线不直接代表日历或邮箱通过。DeepSeek作为候选模型提供方与DeepSeek Harness工作台是不同接入事项：模型候选继续评测，Harness与二丫联动仅FUT-DSH远期待办。

## 人设 时间与记忆上下文的调用要求（v0.4）

借鉴dsh-pet的集中组装方式，来源见00。二丫只保留一个受控组装入口：产品与安全规则、表达风格、当前时间/IANA时区、当前任务与带来源资料分别管理。语气可亲切，不能把二丫描述为已经看过未授权页面、持续监控未运行时段或具备未接入工具。修改人设不修改工具白名单、风险、外发或记忆许可。

当前时间由宿主在每次调用时生成；历史消息保留真实时间，模型不得把历史标注当作输出格式或把旧事实视为刚发生。相对日期仍由日历schema和领域服务校验，提示词时间不能替代验证。网页、邮件及检索记忆属于不可信证据，不拼入系统规则。

记忆检索、可选查询改写及后台整理分别计入任务或用户开启的维护预算；主任务已经完成也不能无限生成。召回条数、证据字节和token按10限制，超时或缺失时记录降级，不用更宽的数据范围或新云端模型兜底。评测追加：历史时间跨度、用户当前要求与旧偏好冲突、检索注入、人设诱导越权、无记忆情况下的任务质量。

后续形象可使用白名单表情或动画ID作为纯表现输出，服务端校验并允许忽略；不能把回复中的“动作”文字标记解释为收藏、发信等业务工具。语音的录音、识别、合成及其数据提供方需独立开启和评估；不随形象或对话默认启用，模型评测不因动画更生动而提高任务成功评分。

## 选型完成条件

ER-011 的完成依据是：首发模型与备用路线有完整评测记录，用户能看到预算、实际用量与数据去向，停用模型后不再发起新调用。ER-012 要求记录提示词、模型、工具和记忆策略版本；升级重跑独立评测并保留上一版本。模型选择不会替代二丫的权限、记忆和执行系统。

下一轮只需用户回答：是否接受所选网页内容发送给在线 AI，以及希望每月最多花多少费用。具体模型 ID、协议和参数由开发者依据评测填写，不要求初学者凭品牌猜选。

## 全能力模型与工具协议评测（v0.5）

[13 全能力接入设计](./13-二丫全能力接入设计.md)扩展的是工具与适配范围，不能靠模型升级替代模块接入。ALL-02前定稿完整assistant工具调用、callId、tool结果角色/内容、并行调用顺序、错误/取消和usage协议；若沿用M12必须补齐上述缺口。模型返回工具参数经schema校验后仍走网关，模型不能定义风险或跳过核验。

WEB评测增加语义控件定位、歧义拒绝、文档失效、表单字段与副作用识别、多步等待、登录接管和提交未知；只读文本模型不自动获得截图/媒体理解能力。视觉模型单列输入许可、截断/遮挡及误定位成本，不因能看截图就假定能可靠执行坐标动作。

按原生、网页、工作台与系统类分别统计任务正确率、误操作、用户介入、费用、延迟和取消效果。不支持某类能力的模型/适配器在manifest禁用，不静默换成更大权限、更多数据或新在线提供方。现有30/120集仍用于原闭环，新增类别另建未参与调参的独立集，不以原成功率证明全浏览器能力。
