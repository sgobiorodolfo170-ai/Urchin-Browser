# 开发测试与安装版共存注意事项（本机已装安装版日常使用）

> 建立：2026-11-09 · 性质：环境防呆约定（事实对照 + 操作规则，不是新的事实真源——进程/数据目录/锁机制以所引源码为真源）
> 关联：[打包核查清单](./打包核查清单.md)（§1 E5 文件占用 / §8 F1 EBUSY / §1 E10 安装版共存核对项）· [决策索引 DD1](./decisions/决策索引.md)（数据目录）· [事实登记表](./事实登记表.md)
> 触发背景：本机已安装顽童浏览器安装版并**日常使用**，开发测试（启动应用、E2E、打包验收）中三类实例并存，曾具备产生「误判应用故障 / 误读写日常数据 / 误杀进程」假信号的全部条件（2026-11-09 用户指令排查落盘）。

## 一、适用范围

凡涉及以下操作，先读本表再动手：启动应用验收（`pnpm start` / 双击产物）、E2E 编写与运行、打包与装包验证、进程排查与清理、日志/数据排障。

## 二、三类实例对照表（身份判定的唯一依据）

| 维度 | 安装版 / win-unpacked（真打包） | `pnpm start`（品牌 dev exe） | `pnpm dev` / E2E（electron.exe） |
| --- | --- | --- | --- |
| 进程名 | `顽童浏览器.exe` | `UrchinBrowser.exe` | `electron.exe` |
| exe 位置 | 安装目录 / `apps/desktop/release-*/win-unpacked/` | `node_modules/electron/dist/UrchinBrowser.exe`（由 `scripts/electron-binary.mjs` 复制改名 + 注入图标） | `node_modules/electron/dist/electron.exe` |
| `app.isPackaged` | `true` | `false`（`index.ts:96-102` 按文件名强制纠正回 dev 语义） | `false` |
| userData | `%APPDATA%\@urchin\desktop`（**与开发实例同一目录**，2026-11-09 实测） | `%APPDATA%\@urchin\desktop`（同一目录） | 同左；E2E 经 `URCHIN_TEST_USER_DATA` 重定向临时目录 |
| DD1 数据根 | `<userData>\data`（即 `%APPDATA%\@urchin\desktop\data`） | 仓库内 `apps/desktop/data` | 同左（E2E 未设 `URCHIN_TEST_DATA_DIR` 时） |
| 运行日志 | `%APPDATA%\@urchin\desktop\data\logs\` | `apps/desktop/data/logs\` | 同左 |
| 单实例锁身份 | `%APPDATA%\@urchin\desktop`（与 `pnpm start` / `pnpm dev` **互斥**） | `%APPDATA%\@urchin\desktop`（与安装版**互斥**） | E2E（`PLAYWRIGHT=1`）不申请锁 |
| 自动更新 | dev 通道启用 | 禁用（`update-service.ts:148`，未打包 → `disabled`） | 不涉及 |

真源：`apps/desktop/src/main/index.ts:90-102`（isPackaged 纠正）、`:127-139`（userData 覆盖顺序：`URCHIN_TEST_USER_DATA` → `portable.dat` → 默认）、`:145-158`（单实例锁按 userData 身份建立，`PLAYWRIGHT` 跳过）、`:168-189`（数据根 / sessionData / 日志）、`:580`（AppUserModelId）、`src/main/portable.ts`（便携模式）。**userData 身份的根因**：Electron 运行时 userData 默认取 `%APPDATA%\<app.name>`，而 app.name 来自打包进 asar 的 package.json——其中**没有 productName 字段**，`"name": "@urchin/desktop"`（2026-11-09 实测安装版 `resources/app.asar`，版本 0.3.0-dev.159）。因此安装版、win-unpacked、`pnpm start`、`pnpm dev` 全部落到 `%APPDATA%\@urchin\desktop`（实测：该目录 lockfile 活跃写入、`%APPDATA%\顽童浏览器` 不存在）；`electron-builder.yml:6` 的 `productName: 顽童浏览器` 只决定 exe / 安装包 / 快捷方式命名与 NSIS 行为，**不进入运行时身份**。⚠ **更正（2026-11-09）**：2026-11-07 登记的「卸载不删真实数据」是**推断错误**，2026-11-09 探针实测已推翻——NSIS 除 productName 派生目录外还会删 `APP_PACKAGE_NAME`（包名 `/`→`\`，即 `@urchin\desktop`），卸载**确实会删**真实 userData；机制证据链、探针结果与删除范围见 §2.1。

**要点**：单实例锁只认 userData 身份（`index.ts:148` 注释原文）。本机所有非 E2E 实例——安装版、win-unpacked、`pnpm start`、`pnpm dev`——**共用 `%APPDATA%\@urchin\desktop` 这一个身份，共用同一把锁**：安装版运行时，其余实例一律丢锁秒退并聚焦安装版窗口（见误判点 1），反之亦然。**可并行安全组合**：E2E（`PLAYWRIGHT=1` 不申请锁 + userData 已重定向）× 任意实例；以及按 §四.1 双环境变量启动的测试档案实例 × 任意实例。

### 2.1 卸载实际删除范围（2026-11-09 探针实测，更正 2026-11-07 登记）

**机制**（真源：`app-builder-lib@26.15.3`，版本由 `pnpm-lock.yaml` 锁定，2026-09-20 dev.90 起）：

- `templates/nsis/uninstaller.nsh:237-244`：`deleteAppDataOnUninstall: true` 时依次 `RMDir /r` 三个目录——`$APPDATA\${APP_FILENAME}`、`$APPDATA\${APP_PRODUCT_FILENAME}`、**`$APPDATA\${APP_PACKAGE_NAME}`**。
- `out/targets/nsis/NsisTarget.js:171` 定义 `APP_PACKAGE_NAME = getWindowsInstallationAppPackageName(appInfo.name)`；`out/targets/targetUtil.js:44-46` 实现为 `name.replace(/\//g, "\\")`。
- 代入本仓库：`APP_FILENAME = @urchindesktop`（不存在）、`APP_PRODUCT_FILENAME = 顽童浏览器`（不存在）、**`APP_PACKAGE_NAME = @urchin\desktop`（命中真实 userData）**。
- 更新不删数据：`uninstaller.nsh:224` 的 `${ifNot} ${isUpdated}` 守卫；`include/installUtil.nsh:205-206` 明确「always pass `--updated` flag - to ensure that if DELETE_APP_DATA_ON_UNINSTALL is defined, user data will be not removed」。
- 上游背景：scoped 包名导致该删除失效的 issue [#6747](https://github.com/electron-userland/electron-builder/issues/6747) 已由 PR #6772（22.14.x，2022）修复，26.15.3 含该修复；该版本早于本机安装版 dev.159（2026-11-07 打包）。

**探针实测**（2026-11-09；同版本 electron-builder 26.15.3，独立 `appId: com.urchin.installprobe` / `productName: UrchinProbe`，只操作 `%APPDATA%\@urchin\probe-*`；真实 `desktop` 目录未参与，前后均 10,424 文件）：

| 探针 | 包名 | 卸载参数 | 结果 |
| --- | --- | --- | --- |
| P1 | `@urchin/probe-del` | `/S`（手动卸载） | `%APPDATA%\@urchin\probe-del` **被删除**（canary 文件消失） |
| P2 | `@urchin/probe-keep` | `/S --updated`（自动更新路径） | canary 文件**保留** |

**删除范围（本机 2026-11-09 实测；默认布局与自选数据目录不同）**：

| 路径 | 内容 | 手动卸载 | 自动更新 |
| --- | --- | --- | --- |
| `%APPDATA%\@urchin\desktop`（479.5 MB / 10,422 文件） | `pi/ai.db`（AI 会话）、`deepseek-harness` 473.8 MB、`providers`、`ai-settings.json`、`app-settings.json`、`data-location.json`（数据目录指针）、`.updaterId` | **删除** | 保留 |
| 自选数据目录（本机 `C:\Users\Administrator\Documents\ub`，约 1.8 GB：`cookies` 1.26 GB、`downloads` 551 MB、`favicons`、`urchin.db`、`logs`） | 书签 / 历史 / cookies / 下载 / 页面保存 | **保留，但指针被删 → 重装后「看不见」**，需在设置里重新指定原目录 | 保留且指针保留 |

> 结论：默认布局下「卸载即全卸」成立；**改过数据目录的用户**，卸载不会删主数据，但会删掉指向它的唯一指针（`data-location.json`），重装后表现为「数据消失」——这是本节最容易误判的一条。

## 三、误判点清单（现象 → 真相 → 正确姿势）

1. **`pnpm start` / 双击 win-unpacked「启动即退出 / 没窗口」（2026-11-09 实测复现）**
   真相：安装版与开发实例共用 userData（§二），即共用同一把单实例锁。安装版在运行时，新实例在 `index.ts:151-154` 丢锁即退（startup.log 打点 `main:lock-lost`），并触发安装版 `second-instance` 聚焦旧窗口；进程退出前还会留下 GPU cache「拒绝访问」类报错噪音——三层假象叠加，极易误判为新构建崩溃。实测：安装版（0.3.0-dev.159）运行期间 `pnpm start` 连续 3 个实例 lock-lost 秒退。
   正确姿势：先按 §四.1 验收方式启动；确需排查启动问题时先完全退出安装版，或给 win-unpacked 放便携标记（便携模式 userData 独立，不受锁影响）。

2. **直接跑 win-unpacked 会读写日常真实数据**
   真相：安装版未运行时，win-unpacked 以 `isPackaged=true` 把数据根落到 `%APPDATA%\@urchin\desktop\data`——这正是安装版日常使用的**同一份**书签 / 历史 / cookies / pi 数据（安装版 userData 即 `%APPDATA%\@urchin\desktop`，见 §二）；且 DB 迁移可能把日常库升级到 dev 结构，安装版再打开存在不兼容回退风险。
   正确姿势：验收真打包产物时在 exe 旁放空 `portable.dat` 走便携模式（`portable.ts:34-38`，userData 重定向到 exe 旁 `userdata/`，不分打包与否均生效）；或将 win-unpacked 复制到仓库外目录再便携运行。

3. **覆盖安装 dev 安装包 = 日常安装版被原地升级**
   真相：NSIS 覆盖安装不删数据（自动更新走 `--updated` 守卫），但日常使用的浏览器从此变成 dev 版。另注：**手动卸载会删** `%APPDATA%\@urchin\desktop`——`deleteAppDataOnUninstall: true` 除 productName 派生目录（`%APPDATA%\顽童浏览器`，不存在）外，还会删包名派生目录 `@urchin\desktop`（=真实 userData）；2026-11-07 登记的「卸载不删用户数据」已于 2026-11-09 被探针实测推翻（见 §2.1）。
   正确姿势：验收安装包走便携 win-unpacked 或临时环境，不装进日常环境；**不要为了「清环境」而卸载**（会删 AI 数据与设置）；确需卸载时先按 §四.6 备份。

4. **按进程名杀进程会误杀日常浏览器**
   真相：安装版进程名就是 `顽童浏览器.exe`；`taskkill /IM 顽童浏览器.exe`、`Stop-Process -Name 顽童浏览器` 一类命令杀的是用户正在用的浏览器。当前全仓 scripts/ 与 package.json **没有任何按映像名杀进程的代码**（2026-11-09 核实），唯一带进程操作的 `tests/e2e/perf.ps1:56,109` 严格按自身 spawn 的 PID 树收集与停止——这是安全范例。
   正确姿势：需要清理测试进程时按 PID / 进程树操作；禁止引入按名清理逻辑（见 §四.2）。

5. **任务栏归组相同，不能按任务栏判断实例身份**
   真相：三类实例 `setAppUserModelId('com.urchin.browser')` 相同（`index.ts:580`），Windows 任务栏归为一组，图标也相似（品牌 exe 注入了应用图标）。
   正确姿势：按进程可执行文件路径区分（任务管理器详情页右键「打开文件位置」，或 `Get-Process | Select-Object Id, Path`）。

6. **排障看错日志 / 数据目录，或按名找不到进程**
   真相：两套日志与数据位置并存（见 §二对照表）：安装版在 `%APPDATA%\@urchin\desktop\data\logs`，开发实例在 `apps/desktop/data/logs`；看错目录会得出错误结论。另注意进程检索的**编码坑**：`顽童浏览器.exe` 是中文进程名，Git Bash `grep` / `tasklist | grep` 因 GBK/UTF-8 失配会漏检，ASCII 关键字（urchin / electron）也命不中它——2026-11-09 实测连续多轮漏检一个正在运行的安装版。
   正确姿势：排障前先确认报告问题的是哪个实例；找中文进程名一律用 PowerShell 导出 UTF-8 清单再检索：`Get-Process | Where-Object {$_.Path} | Export-Csv $env:TEMP\procs.csv -Encoding UTF8`，然后在 CSV 文件里 grep。

7. **E2E 验证的是旧 dist**
   真相：E2E 用 Playwright 启动仓库 electron.exe 加载磁盘上的 `dist/` 产物，而 `e2e` 脚本只有 `playwright test`，**不会先 build**（`apps/desktop/package.json:24`）——改完源码直接跑 E2E，验证的是上一次构建的代码。
   正确姿势：跑 E2E 前先 `pnpm run build`（工作流约定 #2 的既有流程已含此前置）。

8. **E2E 隔离双变量，只配一个等于没配全**
   真相：E2E 隔离靠两个环境变量配对——`URCHIN_TEST_USER_DATA` 隔离 Electron userData（SQLite/cookies），`URCHIN_TEST_DATA_DIR` 隔离 DD1 数据目录（书签/历史/设置/日志）。只设前者时，书签库仍写进开发共享数据目录 `apps/desktop/data`（2026-11-06 书签库污染实证，见 `bookmark-folder-delete.spec.ts:44-48` 注释）。
   现状（2026-11-09 晚间复核，第二版）：21 个 spec 全部有 `URCHIN_TEST_USER_DATA`，**双变量已全量配齐（2026-11-09 修复）**——旧态「仅 9 个配齐双变量、12 个漏网写进 `apps/desktop/data`，`devtools-panel.spec.ts` 三处 launch 块（:29/:55/:84）缺 `PLAYWRIGHT: '1'` / `NODE_OPTIONS: ''`」已于当日逐 spec 补齐并单跑验证（清单与验证记录见 §五）。
   正确姿势：新增 spec 复制完整 env 块（见 §四.3）；跑旧基线产物前注意 §三.7（旧 dist 误判）。

9. **perf.ps1 的环境变量泄漏**
   真相：`tests/e2e/perf.ps1:39-41,99-101` 直接设置 `$env:URCHIN_TEST_USER_DATA` / `PLAYWRIGHT` / `NODE_ENV` 且**不恢复**——同一 PowerShell 会话内后续启动的任何程序都会带上「userData 重定向 + 跳过单实例锁」状态。
   正确姿势：跑过 perf.ps1 的会话中启动其他程序前注意 env 残留；需要时手动清除或换新会话。

10. **端口疑虑（排除项）**
    真相：无固定端口冲突面——vite 5173 仅 dev 实例访问（安装版走 file://，永不连 5173）；pi-web-host / pi-server 以 `--port=0` 随机端口、DSH 探测随机空闲端口，URL 从 stdout 回传。两实例（含安装版）并行不抢端口。

11. **data-location.json 指针与 pi/DSH 数据两实例共用（非理论面）**
    真相：DD1 指针文件落 userData 根（`%APPDATA%\@urchin\desktop\data-location.json`）——安装版与开发实例**共用同一个指针文件**：任一实例在设置里改数据目录，另一实例下次启动会解析到同一目录，SQLite / cookies 双写互扰，代码无跨实例防护。pi / DSH 数据同理共享：`<userData>/pi`、`<userData>/deepseek-harness` 固定挂 userData（`index.ts:165`），开发实例测试 AI 功能会读写安装版的日常 AI 会话库（实测 `pi/ai.db` 正被安装版持写）。
    正确姿势：开发实例测试涉及数据写入的功能时，用 §四.1 双环境变量启动（userData 整体重定向，指针 / pi / DSH 全部隔离）；不要在开发实例里改数据目录设置。

## 四、防呆规则（约定级，按 AGENTS.md §〇.6 不登记 MUST）

1. **验收新构建用 `pnpm start`（工作流约定 #3/#6 既有口径），但注意它与安装版共用单实例锁**：安装版运行时 `pnpm start` 会丢锁秒退（§三.1）——先退出安装版，或加双环境变量启动**测试档案实例**：`URCHIN_TEST_USER_DATA=<临时目录> URCHIN_TEST_DATA_DIR=<临时目录>\data pnpm start`（userData / DD1 数据 / pi / DSH / 锁身份全部隔离，可与安装版并行，与 E2E 同款机制）。确需验收真打包产物（安装版行为差异、asar / 资源路径问题）时，按 §三.2 用便携模式，禁止把 win-unpacked 当「更真实的 pnpm start」随手双击。
2. **禁止新增按映像名杀进程的脚本或命令**；清理测试进程一律按 PID / 进程树（`perf.ps1` 范例）。
3. **新增 E2E spec 必须复制完整 env 块**（参考 `launch.spec.ts:41-42` + `bookmark-folder-delete.spec.ts:44-48`）：`URCHIN_TEST_USER_DATA` + `URCHIN_TEST_DATA_DIR` 双变量、`PLAYWRIGHT: '1'`、`NODE_OPTIONS: ''`、`NODE_ENV: 'production'`；经 `helpers/pi-agent-driver.ts` 启动的 spec 在 helper 内统一维护。
4. **排障先定实例身份**：按进程路径，不按任务栏、不按窗口图标。
5. **改动进程标识相关配置时复核本文**：`productName` / `executableName` / AppUserModelId / userData 决定链（`index.ts:127-139`）/ 单实例锁——任何一项变化都可能使本表失真，须同步更新。
6. **卸载前先备份**：手动卸载会删 `%APPDATA%\@urchin\desktop`（pi 会话 / DSH / providers / 设置 / `data-location.json` 指针，见 §2.1）；改过数据目录的用户，卸载后主数据仍在原地但**失去指针**，重装需在设置里重新指定。自动更新不受影响（`--updated` 守卫）。

**「卸载不删数据」已澄清：不是缺陷，是登记错误（2026-11-09 结案）**：`deleteAppDataOnUninstall: true` 的删除目标是三个 define 派生目录，其中 `APP_PACKAGE_NAME`（包名 `/`→`\`）恰好命中真实 userData `%APPDATA%\@urchin\desktop`——**卸载会删**，探针实测与机制证据链见 §2.1。2026-11-07 的登记（当时未实测）与 2026-11-09 的「根因对齐」均建立在「只删 productName 目录」这一错误前提上。决策留痕 **DD2**（维持现状 + 文档化，否决「NSIS 自定义卸载段」与「打包态身份带 productName」）见 [决策索引](./decisions/决策索引.md)。可选改进（未排期）：① 卸载前提示备份；② 自选数据目录在卸载后失去指针的问题，可评估「保留指针」或「重装后引导重新指定」。
