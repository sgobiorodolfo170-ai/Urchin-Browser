## 1. 背景与定位

为 Urchin Browser 新增**网页翻译**能力：将当前标签页的网页内容翻译为目标语言（默认中文），并支持划词翻译。定位：

- **基础浏览体验**：与地址栏摘要、截图并列的地址栏高频动作；
- **零配置优先**：内置免费翻译接口，用户**无需注册、无需配置任何 API Key** 即可整页翻译（评审结论：不引入 LLM 引擎，不要求用户自备模型配置）；
- **隐私自觉**：仅用户显式触发，设置页披露文本外发去向；v2 规划本地离线引擎方向（零外发）。

## 2. 现状勘察结论（决定方案形态的三条事实）

1. **标签页 = BrowserView，无 preload 且明令禁止**。`apps/desktop/src/main/tabs/create-browser-view.ts` 文件头固化教训（TP1）：给 BrowserView 配 preload 会阻塞网页加载。webPreferences 为 `sandbox:true / contextIsolation:true / nodeIntegration:false`。⇒ 翻译的一切页面内行为只能走 `webContents.executeJavaScript` / `insertCSS`。
2. **注入三模式均有现成先例，直接复用**：
   - 采集：`src/main/page-context/extractor.ts`——`executeJavaScript + Promise.race 超时`模式，且已抽取 `documentElement.lang`；
   - 常驻脚本：`src/main/zoom/index.ts`——`did-finish-load` 注入长期存活脚本 + `window.__ub*` 幂等守卫（pi-web 系列同法）；
   - 样式：`src/main/tabs/ad-block-css.ts`——`insertCSS` 注入。
3. **翻译功能零现存代码**（全仓 grep 仅 CSS `translateY` 误报）；IPC zod 单一真源在 `packages/ipc-contract/src/schemas/ipc-schema.ts`；设置键走 `settings-manager.ts`（敏感键 `SECRET_KEYS`）；主→渲染事件走 `webContents.send` + preload `on(channel)`；测试栈含 jsdom 30（注入脚本逻辑可单测）。

| | 内容 |

## 4. 总体架构

```
渲染层（主窗口 React，有 preload）                主进程 translate 模块（权威源）            页面（BrowserView，无 preload）
┌──────────────────────────┐   IPC(zod)   ┌─────────────────────────────┐  executeJavaScript  ┌──────────────────┐
│ omnibox 翻译按钮          │ ──────────► │ register-handlers           │ ──────────────────► │ 采集脚本          │
│ 右键菜单回调              │              │   └─ TranslateManager       │ ◄────────────────── │ (TreeWalker→segments)
│ 划词结果卡 / 状态提示      │ ◄────────── │       ├─ 批处理/并发/缓存    │  分页拉取 pending   │ 应用/恢复/暂存脚本 │
│ 设置页·翻译区             │  send 事件   │       ├─ Engine 注册表      │  insertCSS(排版)    │ MutationObserver  │
└──────────────────────────┘              │       │   ├ microsoft(国内优先)│                     └──────────────────┘
                                          │       │   └ google(代理优先) │  ◄─ 翻译 HTTP 请求在主进程发起（页面零网络请求）
                                          └─────────────────────────────┘
```

数据流（整页翻译）：按钮触发 → `translate.start` → 主进程注入采集脚本拿回 segments → 分批并发调引擎 → 逐批注入应用脚本替换文本节点 → 进度事件回渲染层 → 完成态；再次点击或右键「恢复原文」→ 注入恢复脚本还原。

**通信模型——拉取而非推送**：`webContents.postMessage` 需要 preload 接收端（被禁止），故动态内容采用**页面内 MutationObserver 暂存 pending + 主进程定时轮询分页拉取**（活动期间 ~1.5s 间隔，停止/恢复即停轮询）。翻译请求全部在主进程发起，页面脚本零网络请求 ⇒ 严格 CSP 站点（如 github.com）不受影响。

**引擎自动选择与互为兜底**：`translate.engine` 默认 `auto`——经 `session.resolveProxy` 判定网络环境（直连 ⇒ 微软优先；走代理 ⇒ 谷歌优先），任一引擎失败自动降级另一个并提示，判定误判不影响正确性（failover 兜底）。详见 §7.5。

## 5. 关键决策（含否决方案）

| # | 决策 | 内容 | 否决方案与理由 |
|---|---|---|---|
| TD1 | 页面交互 | `executeJavaScript` 注入 + 拉取模型（Observer 暂存 + 轮询） | ① preload 注入——TP1 教训：阻塞网页加载，仓库明令禁止；② MessagePort 推送——接收端必须 preload，同样被禁 |
| TD2 | 翻译后端 | **谷歌/微软双免费接口引擎内置、互为兜底**：`translate.engine` 默认 `auto`——直连（国内）微软优先、系统代理翻墙（国外）谷歌优先（`resolveProxy` 判定，§7.5）；可手动锁定微软或谷歌；任一引擎失败自动降级另一个并提示；调研与选型见 §6 | ① LLM 引擎（复用 ai.* 配置）——**2026-08-30 评审否决**：不使用自备 LLM；② 官方额度引擎（腾讯/百度等）作默认——需注册取 Key，违背零配置目标，转 v2 自定义引擎；③ DeepL Web 逆向端点——风控强、稳定性差，不内置 |
| TD3 | 替换策略 | v1 就地替换 + 一键恢复（原文逐节点留档） | 双语沉浸对照（v2）——需逐站点排版处理，复杂度不成比例，先以替换模式验证链路 |
| TD4 | 触发方式 | 默认**仅显式触发**（按钮/右键）；**自动翻译为开关制**（`translate.autoTranslate`，opt-in 默认关）：开启后导航完成且页面语言（`documentElement.lang`）≠ 目标语言时自动翻译为默认目标语言；开启时设置页强化披露「页面文本将自动外发」 | ① 无条件自动翻译——隐式外发隐私风险，否决；② 按页提示条——交互更重，列 v2（§12.2）供逐页选择场景 |
| TD5 | 网络位置 | 翻译 HTTP 请求在主进程发起（node https） | 页面脚本直接 fetch——被页面 CSP 与跨域拦截；utility 子进程——翻译请求逻辑是我们自己的代码，无第三方代码隔离收益，单次文本批调用开销不值（区别于 Provider 插件场景） |
| TD6 | 引擎扩展架构 | 统一 `TranslateEngine` 接口 + 注册表，设置下拉切换内置引擎；接口保持稳定，v2 按此挂载官方额度引擎与本地引擎 | 硬编码单引擎——失去备选与演进空间；引擎插件化（第三方引擎包）——v2 评估（对齐 Provider 插件形态），v1 不做 |
| TD7 | 语言检测 | 以引擎响应的 `detectedLang` 为准 + `documentElement.lang` 预判；检测语言与目标一致 ⇒ 返回 skipped 不发请求 | 引入本地语言检测库（franc 等）——包体积与准确率收益不成比例，两家引擎免费带检测 |
| TD8 | 划词翻译 | 文本取 `params.selectionText`（右键菜单参数），主进程直接调引擎，结果以**结果卡浮层**展示（复用右键菜单的 BrowserView 坐标补偿） | 结果注入页面内气泡——站点样式冲突面大；剪贴板/系统通知——体验差 |

## 6. 免费翻译接口调研与选型（2026-08-30 检索核实）

按接入成本分三类。**v1 只内置第一类（零 Key 免费接口）**；第二类（官方额度制）转 v2「自定义引擎」；第三类（本地离线）为 v2 隐私方向。

### 6.1 第一类：免 Key 免费接口（零配置，v1 内置候选）

| 接口 | 端点 | 免费 | 限制与风险 | 国内可达 | 质量/速度 | v1 定位 |
|---|---|---|---|---|---|---|
| **微软 Edge 翻译接口** | `edge.microsoft.com/translate/auth`（取 JWT，约 10 分钟有效）→ `api-edge.cognitive.microsofttranslator.com/translate` | 完全免费，无需 Key | **非官方**：无 SLA、无配额承诺，存在限流/变更风险；token 需缓存与过期重握手 | ✅ 直连 | 好（与 Azure Translator 同引擎）；批量数组请求，速度快 | **默认引擎** |
| **谷歌 GTX 接口** | `translate.googleapis.com/translate_a/single?client=gtx` | 完全免费，无需 Key | **非官方**：无文档配额，高频按 IP 出 429；GET URL 长度受限需小批分片；ToS 灰色 | ❌ 被墙 | 优；单小批速度快 | **国际场景备用引擎**（非默认） |

**微软 Edge 接口**是 Edge 浏览器内置翻译使用的端点，也是沉浸式翻译等主流翻译扩展的默认免费通道：先向 auth 端点免 Key 换取短效 JWT，再以 Bearer 头调用翻译端点，支持一次请求传入字符串数组（天然适配整页分批）。社区已多年广泛使用，稳定性实践良好，但须按非官方接口对待——这正是保留引擎抽象与备选引擎的原因。

**谷歌 GTX 接口**是 Google 翻译网页端自用的免 Key 端点（`client=gtx`），社区库（如 google-translate-api-x）均基于它；无官方配额文档，重度使用会按 IP 触发 429，且 2022 年曾出现区域性封锁先例。因其国内网络不可达，仅作为国际用户的备用引擎内置，不作默认。

*不内置的免 Key 接口*：DeepL Web 逆向端点（`www2.deepl.com/jsonrpc`）——风控强、频率限制明显、ToS 风险最高；Lingva 等谷歌公共镜像代理——社区实例存活率低。

### 6.2 第二类：官方免费额度制（需注册取 Key → v2 自定义引擎）

| 服务 | 免费额度 | 限制 | 备注 |
|---|---|---|---|
| **腾讯云机器翻译 TMT** | **500 万字符/月**（当月有效不累积） | 超额约 58 元/百万字符（有意外扣费风险，接按时余额提醒） | 国内网络友好，通用质量好；[计费文档](https://cloud.tencent.com/document/product/551/35017) |
| **小牛翻译** | 每日 20 万字符（≈每月 600 万），新用户另赠 100 万 | 在线 API 有 QPS 限制 | 国内 NMT 专精厂商；[价格方案](https://niutrans.com/Price) |
| **Azure Translator（F0 层）** | 200 万字符/月 | 官方免费层，需 Azure 订阅 | 与微软 Edge 接口同引擎，官方 SLA 版本；[Translator v3 参考](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/reference/v3/reference) |
| **阿里云机器翻译** | 100 万字符/月 | 超额 50 元/百万字符 | 国内友好 |
| **百度翻译开放平台** | 标准版 5 万字符/月（QPS=1）；个人认证高级版 100 万字符/月（QPS=10） | 标准版单次请求限 1000 字符 | 2022 年曾下调额度，额度政策历史波动需注意；[接入文档](https://api.fanyi.baidu.com/doc/13) |
| **DeepL API Free** | 50 万字符/月 | 无需信用卡；超额当月停用 | 质量顶级（尤其中欧语言）；国内对 `api-free.deepl.com` 可达性一般；[API plans](https://support.deepl.com/hc/en-us/articles/360021200939-DeepL-API-plans) |

**v2 形态**：设置页「自定义引擎」区——用户填入 Key（进 `SECRET_KEYS` 加密），按上表实现适配器；浏览器侧不做任何注册引导，仅放文档链接。整页翻译月字符量估算：按单页 1 万字符、日均 20 页计算约 600 万字符/月，与腾讯云/小牛免费档匹配。

### 6.3 第三类：本地离线（零外发，v2 隐私方向）

| 方案 | 说明 | 代价 |
|---|---|---|
| **Bergamot / Firefox Translations 同款** | Mozilla 开源的浏览器本地翻译栈：[firefox-translations-models](https://github.com/mozilla/firefox-translations-models) CPU 优化 NMT 模型 + [Bergamot WASM 引擎](https://firefox-source-docs.mozilla.org/toolkit/components/translations/resources/03_bergamot.html)（[browser.mt](https://browser.mt/)，EU 资助项目），Firefox 官方翻译功能即基于此 | 单方向模型每语言对数十 MB（需按需下载）；WASM 推理速度弱于云接口；模型覆盖语种有限 |

价值：翻译全程零网络外发，与本项目隐私定位最契合，适合「隐私模式翻译」「完全离线场景」。v2 以可选下载形式引入，不随安装包分发。

### 6.4 选型结论

**v1 内置微软与谷歌双引擎、互为兜底**（评审第二轮确认）：自动模式下国内直连微软优先、翻墙代理环境谷歌优先（质量更优），也可手动锁定；官方额度引擎与本地引擎按 §12 v2 路线演进。风险对冲：双引擎互为备选 + 引擎接口抽象（TD6）+ failover（§7.5）。

### 7.2 注入脚本要点

- **采集过滤**：跳过 `script/style/noscript/template`、表单控件（`input/textarea` 值）与 `contenteditable` 子树（防误翻用户输入）、`aria-hidden`、不可见节点（`getClientRects` 空/零尺寸）、长度 < 2 的节点；属性类（`title/alt/placeholder`）v1 不翻。
- **恢复一致性**：采集时为每个文本节点建立索引，原文存于管理器状态（内存 `Map<tabId, Segment[]>`），恢复按索引回写；页面跳转即状态丢弃。
- **分页拉取**：页面脚本内 pending 队列，主进程每次拉取 ≤N 段，带游标防重复。
- **性能**：应用替换按 `requestAnimationFrame` 分帧；大页面采集单次 TreeWalker（万级节点 <50ms 量级）；采集结果**分批**回传主进程，避免单个巨型 JSON 返回。

### 7.3 IPC 契约（`ipcSchema` 新增）

| 通道 | req | res |
|---|---|---|
| `translate.start` | `{tabId, targetLang?, engine?}` | `{status:'started'\|'skipped', detectedLang?, segmentCount?}` |
| `translate.stop` | `{tabId}` | `{status:'restored'}` |
| `translate.getStatus` | `{tabId}` | `{active, engine?, resolvedEngine?, targetLang?, segmentCount?}` |
| `translate.translateSelection` | `{tabId, text, targetLang?}` | `{result, detectedLang?}` |

事件：`translate:progress` `{tabId, phase:'collecting'|'translating'|'done'|'error', done?, total?, message?}`（`webContents.send`，渲染层经 preload `on()` 订阅）。

### 7.4 隐私与进程隔离合规（§六审查点对照）

- 页面文本外发仅发生于**用户显式触发**的翻译；随所选引擎在设置页披露外发去向（微软/谷歌）；v2 本地引擎将提供零外发选项；
- 日志只记段数/耗时/错误码，**原文与译文不落日志**（INFO 及以上级别约束）；
- 不新增第三方代码进主进程（引擎请求为自有代码），翻译计算为轻量字符串批处理，主进程可承载，无需 utility 进程。

### 7.5 引擎自动选择、互为兜底与自动翻译触发

- **auto 引擎解析**（仅 `translate.engine:'auto'` 时）：首次翻译时调用 `session.defaultSession.resolveProxy('https://translate.googleapis.com/')`——返回 `DIRECT` ⇒ 微软优先（国内直连场景）；返回任何 `PROXY/SOCKS` ⇒ 谷歌优先（翻墙/代理环境，谷歌可达且质量更优）。判定结果按会话缓存；双引擎均失败时清除缓存重判定一次。
- **互为兜底（failover）**：优先引擎请求失败（网络错误/超时/token 重握手后仍失败/429 退避后仍限流）⇒ 自动降级另一引擎完成剩余批次，进度事件注明「已切换至 ×× 引擎」；单批失败重试策略（§8.1）在 failover 之后执行。
- **自动翻译触发规则**（`translate.autoTranslate:true`）：`did-finish-load` 且为 http(s) 页面 ⇒ 读 `documentElement.lang`；该值存在且非目标语言 ⇒ 自动 `translate.start`（目标语言取 `translate.targetLang`）；**缺失或无法判定 ⇒ 不自动翻译**（保守策略：避免误翻，也避免逐页发检测请求）；内部页 `urchin://`、`file://` 不自动翻译。手动触发不受此限制（仍用引擎响应的 detectedLang 跳过同语言页面）。

## 12. v2 规划详述

### 12.1 引擎扩展

- **自带 Key 官方额度引擎（§6.2 清单）**：设置页「自定义引擎」区，推荐优先级——腾讯云 TMT（500 万/月，国内最宽裕）> 小牛（每日 20 万）> Azure F0（200 万/月，微软官方 SLA）> DeepL Free（质量顶级）> 百度/阿里云。Key 一律进 `SECRET_KEYS`（safeStorage 加密）；额度余量与异常扣费风险在设置页提示。
- **本地离线引擎**：Bergamot WASM + Mozilla 模型按需下载（§6.3），隐私模式与离线场景的零外发翻译；先支持 en↔zh 高频对。
- **引擎插件化**（评估项）：对齐 Provider 插件形态，第三方翻译引擎包跑 utility 进程——仅当出现真实需求（§十一 Graph Engineering 同款「触发重启评估」思路）。

### 12.2 配置体系

- **站点级记住偏好**：每站点「总是翻译 / 从不翻译」，存 SQLite（settings 库 site_rules 表）；地址栏翻译按钮下拉菜单提供入口，命中规则的站点自动执行或静默跳过。
- **翻译缓存持久化**：SQLite `translate_cache(text_hash, lang_pair, result, created_at)`，跨会话复用——二次访问同一页面零延迟零流量；配 LRU/TTL 淘汰与设置开关。
- **目标语言策略**：按源语言记忆偏好（如「日语→中文、英语→中文」）；若未来引入界面 i18n 则与界面语言联动。
- **自动提示条**（Chrome 式「检测到外语页面，是否翻译？」）：与 v1 的自动翻译总开关互补——总开关全有全无，提示条提供逐页选择；依赖本地启发式语言预判（不发请求），**默认关闭**，开启后命中「总是翻译」规则的站点免提示。

### 12.3 体验增强

- **双语沉浸对照**：原文/译文同屏（段落后插入译文行），逐站点排版策略 + 三态切换（原文/双语/仅译文）；采集与恢复的原文索引结构（§7.2）可直接复用，增加「双写模式」。
- **快捷键与命令面板**：翻译/恢复原文快捷键归入命令面板（OM10）统一管理。
- **覆盖增强**：open Shadow DOM 遍历；iframe 全覆盖（`framesInSubtree` 逐帧执行）；`title/alt/placeholder` 属性翻译；超长页视口优先（IntersectionObserver 先翻可视区）。

## 13. 评审记录与遗留确认项

**2026-08-30 评审结论（均已采纳）**：
1. 第一轮：**不使用自备 LLM 引擎**——移除原方案的 LLM 引擎（复用 ai.* 配置）及其设置、测试项；翻译只用免费接口。
2. 第一轮：**采用免费接口**——按 §6 调研选定免 Key 双引擎；官方额度引擎与本地离线引擎列入 v2。
3. 第二轮：**谷歌/微软双引擎内置、互为兜底**——自动模式国内直连微软优先、翻墙代理环境谷歌优先（`resolveProxy` 判定，§7.5），可手动锁定。
4. 第二轮：**自动翻译为开关制**——`translate.autoTranslate`（默认关），开启后外语页自动翻译为默认目标语言（`documentElement.lang` 触发规则见 §7.5）；原「仅显式触发」决策（TD4）据此修订。

**遗留确认项（已全部确认，2026-08-30 第三轮）**：
1. 目标语言清单：**zh-CN（简体，默认）/ zh-TW / en / ja / ko / fr / de / ru / es**——评审确认「需要有中文简体」；单一真源为 ipc-schema `TRANSLATE_TARGET_LANGS`。
2. 划词翻译结果卡：采用**鼠标位置浮层**（复用右键菜单的 BrowserView 坐标补偿），实现时按效果微调。
