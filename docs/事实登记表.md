> 关联：[AGENTS.md](../AGENTS.md) §九.4 硬门禁清单 G13 · [03-技术栈](./03-技术栈.md) §4 · [文档索引](./文档索引.md)

## 为什么要有这张表

第二轮审计（2026-10-27）发现：同一个规范事实在仓库里平均存在 4~7 个副本，且没有任何机制阻止副本漂移。实测分布：

| 事实 | 副本数 |
| --- | --- |
| 覆盖率阶梯数值 | 7 个文件 |
| `pnpm test --coverage`（不存在的命令） | 5 个文件 |
| pre-commit 含 `tsc --noEmit`（错误描述） | 3 个文件 |
| 测试约定表（命名 / mock / 命令） | 2 个文件 |

**漂移是必然发生的，不是偶然疏忽**：只要一个事实有 N 个副本，任何一次修改就有 N-1 个副本变成谎言。典型实例——2026-10-27 修正 AGENTS.md §九.2 后，`03-技术栈 §5` 立刻变成与它矛盾的旧描述。

本表的作用：**给每个高频事实指定唯一真源，其余位置降级为引用**，并用脚本把「降级」变成可执行的检查。

## 二、自动检查（R1-R3）

`node scripts/check-doc-drift.mjs` 扫描 `docs/**/*.md` + 根目录 4 份 md，执行三条规则：

| 规则 | 检查内容 | 对应事实 |
| --- | --- | --- |
| **R1** | 禁止出现 `pnpm test --coverage`（该 script 不存在，正确写法 `pnpm test:coverage`） | F2 / F3 |
| **R2** | 禁止把 pre-commit 描述为含 `tsc --noEmit`（实际钩子只跑 `lint-staged`） | F2 |
| **R3** | 成串出现的覆盖率阶梯序列必须与 `03-技术栈 §4.1` 一致（真源**现场解析**，脚本不存副本） | F1 |

设计约束：

- **真源现场解析**：脚本从 `03-技术栈` 的「整体单元覆盖率」表格行读取阶梯，不在脚本里硬编码数字——否则脚本自己就成了第 8 个副本。
- **豁免历史文档**：`CHANGELOG.md`、`ADR-008` 记录的是当时的事实，不应回改；豁免名单在脚本的 `HISTORY_EXEMPT`。
- **只查阶梯陈述，不查单点引用**：允许「v0.1 ≥60%」这类局部引用，只校验成串的阶梯（避免误判分层目标表）。

**自测方式**（改动脚本后必做）：

```bash
# 1. 正常态应通过
node scripts/check-doc-drift.mjs

# 2. 注入漂移应失败——新建临时文件写入错误阶梯，确认报 R3 后删除
printf '| 版本 | v0.1 | v0.2 | v0.3 | v0.4 | v0.5 | v1.0 |\n| --- | --- | --- | --- | --- | --- | --- |\n| 覆盖率 | ≥60%% | ≥68%% | ≥70%% | ≥75%% | ≥75%% | ≥80%% |\n' > docs/_drift-selftest.md
node scripts/check-doc-drift.mjs   # 应退出码 1
rm docs/_drift-selftest.md
```

## 三、新增一个登记事实的流程

1. 判断该事实是否**已存在 2 个以上副本**，或**预计会被反复引用**——不满足则不登记（避免台账膨胀）。
2. 指定唯一真源：优先选**已经有完整论证的文档**（如 ADR、技术栈），其次选**代码配置**。
3. 把其余位置的完整复述改为「一行引用 + 锚点」。
4. 若该事实可机械判定，在 `check-doc-drift.mjs` 增加一条规则（R4、R5…），并在 §九.4 硬门禁清单登记。
5. 在本表补一行。
