## 1. 接手约定

**先交付原生 F12，再决定是否开展专属增强。不得继续补齐旧通用面板。**

1. 先读 AGENTS.md、ADR-022 和需求文档，再检查当前分支、用户改动、依赖与实现；使用 `git fetch` 按仓库规则同步，不覆盖用户未提交内容。
2. ADR-022 决策、需求验收、本文实施顺序分别作为各自真源。旧一期规划与契约 G 的历史伪码仅用于理解现状，不能作为实现授权。
3. 初始 D0 仅落盘文档；后续已获用户实现及继续推进指令，当前实施进度见 §7。已确定的 F12 与原生路线无需重新征询。
4. 把实际结果填入阶段台账。未运行、环境阻塞和测试失败分别记录，禁止将「代码看起来可行」或「单测已过」替代产品验收。
5. 不顺手修改 Provider、pi、扩展体系或 Electron 版本。若运行版本出现实质阻塞，提供最小复现并按 ADR-017 处理，不能靠无范围升级掩盖问题。

### 2.1 原生控制能力建议

新增或改造的控制器放在现有 `main/devtools/` 边界内；具体文件名由实现确定，不在本文冻结类名或新 IPC。主进程维护 owner window、target tab/webContents、原生 tool webContents 的对应关系，生命周期从实际事件与存活状态归并。

- 壳/网页收到 F12：解析所属窗口的当前可检视网页，幂等 toggle 该目标。
- 原生工具收到 F12：关闭该工具绑定的目标工具，而不是去查询另一个窗口的当前标签。
- 每个目标独立管理；创建中/关闭中重复请求合并，失败回收未完成实例；销毁不再向 renderer 发送无效通知。
- 初始优先验证 `target.webContents.openDevTools({ mode: 'detach' })`。确认工具窗口真实可见、标题归属和焦点后再考虑嵌入；不能因为调用不抛错就判成功。
- 若采用 `setDevToolsWebContents`，必须为原生承载创建独立、适当隔离的 webContents，不能把应用主 renderer 当承载。结合事件、原生工具实际可操作性、绑定目标与销毁结果判断状态；解释 `isDevToolsOpened()` 异常的原因，不能仅用手工状态覆盖。
- 工具默认使用原生主题/设置；不把旧 React 设计令牌注入 Chromium DevTools 页面。嵌入壳的尺寸与配色适配不得变成维护 DevTools fork。

### 3.1 P0-A 必须解决的问题

- [ ] 记录锁定 Electron 与实际运行 Chromium，先验证独立窗口的显示和操作，再处理窗口归属与关闭。
- [ ] Windows 实测 F12 在网页、地址栏、原生 Console 输入框中触发；headless 或 Playwright 键盘模拟无响应时，核实焦点和事件通路，不能只调用内部 toggle 代替。
- [ ] 对嵌入方案复现「opened 事件已到但布尔状态 false」；明确 host、open mode、事件顺序及关闭语义。限本阶段时间，未解决即采用原生独立窗口，不阻塞 P0。
- [ ] 验证原生单独运行；若确有采集复用需求，再测试 attach→open 与 open→attach、关闭、刷新、崩溃和意外 detach。Electron 文档的 detach 说明和一次共存成功都不足以代替矩阵。

2026-11-15 执行进度：已记录实际 Electron/Chromium 版本，在真实 Linux 桌面验证独立窗口、DOM 显示、Console 求值；无 Playwright/采集器的最小探针完成 20 轮开关；嵌入异常已复现，首版选择独立窗口。上述清单保持未勾选，因为 Windows 与完整产品行为尚未验证。详见[本轮原生验证记录](./开发者工具原生验证-2026-11-15.md)，含可复现步骤、旧链路调用方清单及未测项。

### 3.2 旧采集代码的去留

对 `DevtoolsManager`、旧 IPC、事件、hook、布局字段分别记录调用方。原生 F12 无需采集器；没有实际调用方的代码在 P0-C 删除，可从 Git 历史恢复。若有已启用调用方，保留为隔离服务并明确所有者，不能默认随 F12 常驻。

任何被保留或在 P1 重新引入的采集代码必须先处理：

1. **时间语义**：耗时只用同一单调时钟域；`wallTime` 只用于展示时间。覆盖成功/失败/重定向/缺失事件，不用 `Math.max(0, ...)` 掩盖时钟混用。
2. **有界数据**：后端、前端/消费端、去重集合、请求索引均有条数与字节上限；报告丢弃、截断，不能只给后端加 ring buffer。
3. **会话同步**：订阅、快照与增量有明确顺序及 session/序列标识；重连不重复、不漏状态；UI 关闭与任务取消按所有权释放采集。
4. **边界与取消**：navigation、tab/owner 销毁、debugger detach 后停止计时器与任务；先清理再允许新会话。不得通过无限重试抢占原生。

上述修复仅在代码继续被使用时执行；计划删除的旧面板拖宽样式等不必先投入修复。

## 4. 验证矩阵与执行方式

| 类别     | 必测场景                                                                     | 证据                                                       |
| -------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 功能     | 原生主要面板、DOM 检视、Console 求值、Network 请求、Sources 断点、短性能录制 | 真实原生 UI 与 fixture 结果；不是只检查方法被调用          |
| 键盘     | 壳、网页、DevTools 内焦点；单按/长按/快速连按；工具关闭后的焦点              | 每次动作的目标与开关次数；至少一次 Windows 真实键盘验证    |
| 所有权   | A/B 标签、两窗口、不同工作区、导航/reload、内部页与 GenOffice                | 没有串台、误开壳调试器；多实例独立关闭                     |
| 生命周期 | 20 轮开关、手动关闭工具、关标签、关 owner、崩溃、退出                        | 映射、监听、定时器归零；无残留空白、幽灵窗口或持续内存增长 |
| 共存     | 默认无 Urchin attach；若保留采集则覆盖两种打开顺序和被 detach                | 原生优先，采集明确失败与取消，无抢连                       |
| 非回归   | 网页 bounds、侧栏/书签栏尺寸、地址栏交互与多窗口                             | 与既有布局/导航场景一致                                    |

执行前读 package.json 的当前 scripts、[测试约定](./03-技术栈.md)、[E2E 选择规则](./decisions/ADR-018-E2E按需选择.md)及[测试与安装版共存注意事项](./开发测试与安装版共存注意事项.md)。不得复制过期测试数量作为目标。

```bash
# 基础门禁；组成以 package.json 为准
pnpm verify

# 单测示例：按实际新增/迁移文件调整，不能当作完整验收
pnpm --filter @urchin/desktop test -- tests/unit/devtools-manager.test.ts tests/unit/devtools-register-handlers.test.ts

# 根据当前改动按 ADR-018 选择 E2E；更新 manifest 后检查
pnpm check:e2e-manifest
pnpm e2e:select --help

# 产品代码改动后必须构建并启动；使用隔离用户数据配置
pnpm build

```

E2E 若仍沿用旧文件名，可运行 `pnpm --filter @urchin/desktop exec playwright test tests/e2e/devtools-panel.spec.ts`；正式范围以选择器和 manifest 为准。使用独立临时 profile 与数据目录；遵照现有 harness 的 `URCHIN_TEST_USER_DATA` / `URCHIN_TEST_DATA_DIR` 约定，不能接入真实账号或正在运行的用户实例。Linux 需要显示服务或明确记录 headless 配置；不得为得到通过结果关闭门禁、删断言或将 Windows 未测标成通过。

探针复现最小步骤：构建应用 → 隔离启动 → 创建可控普通网页 → 在主进程找到该 tab 的 webContents → 打开原生工具 → 等待真实窗口/面板出现 → 从三个焦点位置测试 F12 → 关闭目标检查资源。环境辅助脚本只放工作目录；需要长期回归的内容进入正式测试与 manifest，不依赖上一轮临时文件。

## 5. P1 对照协议与投入闸门

先从实际使用/缺陷记录选任务，未发现跨 Urchin 上下文的真实问题则不启动原型。实验开始前把任务、预期结果和判分方法写入带日期的调研/报告并登记索引，避免看到结果后挑选指标。

- 建议固定 **20 个任务**，同时覆盖普通网页诊断与 Urchin 特有的 Provider/Agent/工作区失败；普通任务检查是否退化，专属任务衡量增益。
- A 组：原生 DevTools + 当前可用通用 Agent/MCP。B 组：同一基线 + Urchin 专属证据。固定模型版本、权限、上下文预算、fixture；每题每组至少两次，交错顺序并重置会话，避免复用上一组答案。
- 成功由预先指定的行为断言或复现消失判定。报告总体与专属任务的成功率、完成时间中位数、人工介入次数、token/费用、采集开销与失败案例；未完成任务单独列出，不能从耗时统计中悄悄删除。
- 默认继续条件：成功率不下降，且专属任务完成时间中位数降低至少 **30%**，同时无越权/敏感信息泄漏与明显普通任务退化。该数值是本规划的工程筛选阈值，不是已有收益结论；如试验前有更合适口径，可记录理由后调整，不能事后降低标准。
- 每次原型与对照合计最多 10 个有效工作日。无真实任务、关联证据不可靠、收益不达标或成本不可接受则停止，记录结果并移除无使用价值的实验资产。通过也只证明值得下一阶段投入，不直接证明市场需求或商业回报。

## 6. AI 实施红线与交付清单

接手 AI 在每个实现阶段结束时提交：修改范围及理由、需求编号对应的验证证据、未测项/阻塞、去留代码清单、下一阶段条件。遵循仓库 Git、版本和发布规则；不得把文档落盘顺带变成发布操作。

- [ ] 没有补回已取消的侧栏调试按钮、重新绑定按钮、命令面板或额外快捷键。
- [ ] 没有继续实现自研 Elements/Sources/Network 瀑布图或 Panel API。
- [ ] 没有把 Chromium 原生能力误写成 Google 云 AI、全部 Chrome 扩展支持或正式多平台承诺。
- [ ] 没有按历史 DT13 假设无条件抢占，也没有根据单次探针假设永远共存。
- [ ] 没有让普通页面得到 app preload、任意 CDP、跨工作区访问或对外调试端口。
- [ ] 契约 B/G、主需求、模块/路线、README 与索引按真实完成状态同步；旧记录保留历史身份。
- [ ] 所有「通过」都有本轮版本、平台、命令和结果；旧 38 单测/3 E2E 结果不充当新功能验收。
- [ ] 提交符合 AGENTS.md 追溯要求；本地验证受阻时如实记录，不擅自修改门禁或无关模块。

## 7. 当前交付记录

### 2026-11-16 P0-B 执行增量

用户要求继续推进，基于 P0-A 的 Linux 独立窗口证据先接入产品 F12；Windows 退出条件继续保留，不因先实现代码而豁免。

- 主进程 `install-shortcuts.ts` 按 Urchin owner window 选择活动网页，原生工具绑定打开时目标；新增窗口/标签自动安装，独立悬浮地址栏由主进程显式登记 owner 后接入同一控制器；打开/关闭中合并请求，长按去重，10 秒超时回收，关闭/崩溃/销毁/退出清理监听与计时器。F12 不再发送旧 renderer toggle，也不调用采集器。
