# 开发者工具需求文档

> 状态：P0 已验收（本机 Windows 11）；Windows 10 延期候补；P1 未启动· 建立：2026-11-15 · 最近更新：2026-11-16

## 1. 目标与范围

用户按 F12 即可使用完整原生工具诊断当前网页；需要 Urchin 专属上下文时，后续以按需、可控的证据支持 Agent 完成定位与验证。第一优先级是可用、稳定的原生基线。

| 层级         | 范围                                                                                                           | 本轮状态                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| P0：必须交付 | 原生 F12、正确目标与窗口归属、焦点与生命周期、旧 UI 退出、Windows 验收                                         | F12 已接入；原生与旧链路退出完成；本机 Win11 已验收，Win10 候补 |
| P1：限定试验 | 页面 → Provider/Agent/工作区的关联证据、明确目标的诊断和修复后验证                                             | 仅批准验证方向；不承诺正式功能、入口或发布日期 |
| 不做         | 全套自研通用面板、侧栏调试图标、绑定当前标签按钮、额外快捷键、命令面板入口、自定义 Panel API、自动后台全量采集 | 已取消或不在范围，不得当作遗留欠账补回         |

## 2. 用户场景与交互约定

1. 用户在网页或所属浏览器地址栏按 F12，打开该窗口当前网页的原生 DevTools，能检查 DOM、执行表达式、查看请求、断点调试与录制性能信息。
2. 用户在同一网页再次按 F12，关闭该网页的工具；焦点处于原生工具内部时，F12 关闭该工具并回到所属网页。
3. 从网页 A 切到 B，不改变 A 工具的目标；在 B 按 F12 打开 B 的工具。A 的独立工具可以继续存在，标题/归属必须可辨认；不能偷偷把 A 的工具切到 B。
4. 不支持检视的内部页、GenOffice 视图或无有效网页目标时，给出简短原因。不能为了响应 F12 转而打开浏览器壳、其他工作区或其他窗口的调试器。
5. 用户关闭原生工具、目标标签或所属浏览器窗口后，相应资源与监听被回收；重新打开不出现幽灵窗口、旧目标或残留第三列空白。

## 3. P0 功能需求与验收

以下 FR-DT 编号为本阶段新增，不复用总需求的历史 FR-DEV 编号。

| 编号     | 要求                                                                  | 验收要点                                                                                                                                                |
| -------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-DT-01 | F12 打开/关闭原生 Chromium DevTools，完整工具由当前 Electron 版本提供 | 真实 UI 中可见 Elements、Console、Network、Sources、Performance、Memory、Application；检查一个 DOM 节点、执行表达式、捕获请求、命中断点、完成短性能录制 |
| FR-DT-02 | 快捷键在网页、浏览器壳输入框、原生工具拥有焦点时行为一致              | 每次按键只执行一次切换，长按不连续开关；不把 F12 发送给页面；关闭后焦点回到所属网页，目标已不存在则回所属浏览器窗口                                     |
| FR-DT-03 | 主进程确定目标与所有者                                                | 覆盖两窗口、不同工作区、两个网页；工具始终绑定打开时目标，后续标签切换不改绑；新窗口初始化与销毁均正确                                                  |
| FR-DT-04 | 同一目标最多一个原生工具实例；网页刷新与导航保持目标一致              | 连续开关、切页、页面 reload 和同 tab 导航无重复实例；清缓存/重载行为沿用原生工具设置，不叠加 Urchin 隐式规则                                            |
| FR-DT-05 | 明确支持范围                                                          | 普通网页 tab 为首批支持对象；内部页与 GenOffice 暂不支持且有原因；测试用页面允许隔离 fixture；不得以 app 主 renderer 作为兜底目标                       |
| FR-DT-06 | 生命周期与状态真实一致                                                | 关闭工具、关闭 tab、关闭 owner、渲染进程崩溃、应用退出后无失效监听或幽灵工具；失败可重试且不显示假成功                                                  |
| FR-DT-07 | 首批允许原生独立窗口；嵌入仅在等价行为验证后启用                      | Windows 上原生窗口可操作、可关闭、可恢复焦点；若嵌入，额外验证布局、缩放、resize、焦点、销毁和打开状态，不依靠单个布尔值验收                            |
| FR-DT-08 | F12 不再依赖自研采集器或手动「开始检视」                              | 基础模式无 Urchin debugger 自动 attach、无旧 React 面板；原生诊断可独立完成                                                                             |
| FR-DT-09 | 原生工具优先可用，采集冲突透明处理                                    | P0 不要求双客户端共存；若仍有实际采集调用方，被 detach 时状态明确、取消相关任务，不反复抢连；不能关闭原生工具以维持采集                                 |
| FR-DT-10 | 原生交付后退出旧第三列链路                                            | 页面有效宽度恢复；无旧侧栏/绑定按钮待办；未使用的组件、布局字段、IPC、监听按调用方审计清理；共享能力保留需说明实际用途                                  |

## 4. 非功能要求

| 编号      | 要求                                | 验收方法                                                                                                                            |
| --------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| NFR-DT-01 | 不降低页面与工作区隔离              | 尝试从普通网页触达调试控制、跨窗口/工作区目标，均不能越权；不新增对外调试端口或任意 CDP 透传                                        |
| NFR-DT-02 | 不打开工具时没有额外调试采集成本    | 无后台 attach/批处理定时器；开关至少 20 轮后 owner/target/tool 映射、监听与计时器回到基线，内存无持续线性增长；内存门槛沿用项目真源 |
| NFR-DT-03 | 面向 Windows 首发，记录真实平台证据 | 本轮仅验收本机 Windows 11，记录系统、Electron/Chromium 版本与结果；Windows 10 延期候补；Linux headless 不替代 Windows UI 验收           |
| NFR-DT-04 | 调试失败可诊断                      | 错误含明确阶段与目标标识；默认日志不记录凭据、完整请求体或表达式内容；不无限重试                                                    |
| NFR-DT-05 | 测试覆盖行为而非仅内部调用          | 单测验证生命周期与目标选择；E2E 实际按键并观察原生工具及页面行为；旧 IPC 用例通过不等于本阶段通过                                   |

## 5. P1 专属增强试验需求

仅在 P0 达标后开展，实施时保持关闭/不启用状态为默认。试验不得拖延原生基线交付。

| 编号      | 候选需求                                       | 成立标准                                                                                                                             |
| --------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| EXP-DT-01 | 对用户明确指定的网页与时间段生成有来源的证据包 | 每项证据标明目标、时间/导航或会话标识、类型、截断与脱敏情况；Agent 能引用来源而非只得到一段解释                                      |
| EXP-DT-02 | 关联 Urchin 特有上下文                         | 至少解决一个原生工具无法直接表达的 Provider/Agent 调用或工作区问题；缺少关联标识时明确缺失，不虚构完整调用链                         |
| EXP-DT-03 | 支持诊断、复现、修复后再验证                   | 能比较修复前后的同一失败判据；解释合理不等于修复成功，必须有请求/断言/行为证据                                                       |
| EXP-DT-04 | 采集与发送可控                                 | 限定 tab/工作区/时间/条数/字节预算；用户能取消；过滤凭据与敏感头、参数；原始正文默认不发，发送复用既有 Provider 权限流程             |
| EXP-DT-05 | 接受对照试验                                   | 对比原生 DevTools 加可用的通用 Agent/MCP，固定模型、任务、工具权限与上下文预算；报告成功率、耗时、人工介入和成本，而非仅演示成功案例 |

本阶段不预设新聊天入口、协议名称或 UI 面板。应先用最小原型验证证据是否有价值，再决定产品形态。
