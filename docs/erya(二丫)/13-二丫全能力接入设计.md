## 1. 目标与完成含义

目标分为原生功能操控、外部网页操作、独立工作台协作三层。用户在当前浏览器能完成的业务动作都需要有接入决定；已存在的内部IPC、上游桩接口、计划模块和浏览器实际可用功能分别登记。完整操控允许逐次审批和用户接管，但“只打开原生界面让用户做完”只能算辅助覆盖，不能算自动执行覆盖。

沿用CUT-01和A/B/C批次，D批诊断仍按既有闸门试验；新增E批原生补全、W批网页操作、F批系统集成。GenOffice/Pi/Harness未来G批仅补设计合同，仍需FUT专项立项才实施，不因此继承它们的会话、密钥、工具或权限。A/B/C完成不能称全浏览器完成；整个目标只有在全量分母登记、缺口关闭且逐动作验收后才能宣称。

“全能力”以产品支持范围为边界，不承诺操纵任意操作系统应用、不承诺任意网站永远成功，也不绕过验证码、支付/系统凭据界面。遇到人工环节返回可恢复交接；功能本身尚未实现（如规划中的M16）不列为现有可用动作，单独列未来增量。不能把模型拥有Shell或原始CDP当作覆盖全部功能的替代方案。

## 2. 动作登记和证据来源

登记过程：固定应用提交/平台 → 扫描RPC总表与独立IPC → 复核菜单、快捷键、设置页、侧栏、右键菜单、查看器和工作台 → 按业务效果去重 → 展开参数分支 → 逐项绑定工具、策略、适配器和验证器 → 与产品界面进行人工反查。一次点击和快捷键触发同一业务动作只计一次；同一通道若可执行多种业务动作须展开，不按通道数计覆盖率。

证据入口：[RPC总表](../../packages/ipc-contract/src/schemas/ipc-schema.ts)、[日历合同](../../packages/ipc-contract/src/schemas/calendar.ts)、[handler装配](../../apps/desktop/src/main/bootstrap/handlers.ts)、[笔记本状态](../../apps/desktop/src/renderer/notebook/types.ts)、[笔记本界面](../../apps/desktop/src/renderer/notebook/NotebookView.tsx)、[设置界面](../../apps/desktop/src/renderer/settings/SettingsPage.tsx)、[右键菜单](../../apps/desktop/src/main/context-menu/index.ts)、[原生F12](../../apps/desktop/src/main/devtools/install-shortcuts.ts)、[GenOffice Home方法](../../apps/desktop/src/main/genoffice/home-handlers.ts)、[扩展加载器](../../apps/desktop/src/main/extensions/extension-loader.ts)。应用动作的事实仍以模块源码和原合同为准。

本轮下表是基线RPC的逐通道接入决定，并补充非RPC动作；不是已经验收的运行时清单。INT-00/ALL-01须完成参数分支和界面反查，未确定项标unknown并阻止全覆盖结论。后续稳定actionId一经分配不因排序或重命名重排，删除保留deprecated与替代关系。本轮N编号仅标识基线记录；展开后的动作使用父ID加稳定语义后缀，例如N-settings.set/translate.targetLang，而不是下标。

每个动作登记：actionId、名称、证据位置、平台/应用版本、真实资源归属、能力状态、toolId、合同版本、策略、前置条件、结果判据、取消/补偿、依赖与负责任务、测试ID、最近验证记录。能力状态为unknown/planned/implemented/verified/unsupported/deprecated；调用模式为auto/approval/handoff/internal。文档中的计划不直接将状态置implemented或verified。

### 2.1 策略与核验模板

R：L1范围读取；不自动授予云端外发。N：明确导航/界面意图与目标范围；可能提交、下载或启动外部应用的行为不能沿用普通导航许可。W：L2逐次确认具体变更；H：高风险逐次确认或原生可信界面接管，不向模型暴露凭据。I：内部协议，不注册模型工具；其用户效果由另一业务动作覆盖。

| 核验模板      | 前置条件与资源身份                                                        | 后置证据、取消与恢复                                                                  |
| ------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| V-T 标签/窗口 | profile/window/workspace/tab及导航版本；关闭/移动前检查未保存内容         | 管理器回读顺序、归属、URL或窗口状态；导航等到声明的阶段，取消不承诺回退已导航页面     |
| V-D 领域对象  | 对象ID、实际profile/workspace范围、revision；写入与回执同事务或可恢复日志 | 回读目标字段与数量；旧版冲突拒绝；未知写入按操作键对账，不盲重试                      |
| V-F 文件/产物 | 受控fileRef、真实路径/根目录、文件标识及内容版本；覆盖预览、空间与锁检查  | 回读摘要、格式、路径及大小；临时文件原子落地；不能将打开路径当文件读取许可            |
| V-J 异步任务  | jobId及所属任务、来源范围、提供方和预算                                   | 回读任务状态、实际产物；取消区分requested/cancelled/committed/unknown；断线后按ID查询 |
| V-S 设置/系统 | 明确允许键、类型、旧值及revision；系统级变更专门审批                      | 回读生效值，必要时检测重启后值；回滚也检查新版本，不恢复用户随后修改                  |
| V-M 邮件/日历 | 原合同稳定身份、账号/日历、版本、时区；附件及重复范围单独绑定             | 依10合同核验；SMTP接受不等于送达；备份恢复不能冒充单对象撤销                          |
| V-U 界面状态  | 可信窗口/面板、用户意图、视图revision；不以坐标定位内部功能               | 主进程或可信UI命令回执及状态回读；窗口销毁/切换后失效；不能只验证按钮被点击           |

所有写入遵循10的审批摘要、幂等和结果未知规则；表中H不能以L3豁免。V-U若目前只有渲染层状态，需先建立可回读、受控的语义命令和单一写入口，不注册任意React回调或整份settings写入。

## 3. 统一工具合同与原生适配

工具定义沿用10的ToolInvocation，新增设计清单字段：actionIds、schemaVersion、supportedPlatforms、availabilityProbe、resourceResolver、permissionPolicy、preconditions、postconditions、cancelMode、receiptLookup、compensation、handoffPolicy、adapterVersion、testRefs。能力查询返回机器可读的输入输出schema、限制、调用模式、不可用原因和版本；模型只看到本任务获准且当前可用的最小工具集合，不能用capabilities查询秘密资源。

原生调用链为运行时 → 主进程网关 → 模块领域服务/可信语义UI命令 → 独立核验 → 回执。BrowserHostApi只是现有有限合同，不承载全浏览器功能；新增能力按领域进入erya-contract，不扩成任意invoke代理。settings更新只接受已登记键、类型和值域；notebook.state、布局整树、密钥、Provider认证和审批记录不得通过通用settings.set写入。

每项前置验证绑定profile/workspace/window/tab/document/object及实际版本；不存在的版本字段先由领域适配补齐。参数合法不等于可调用，已有原生IPC的sender白名单不因二丫接入而放宽。只在本次操作拥有的会话、监听和租约内清理。目标系统没有事务/幂等时回执不能伪造“恰好一次”；明确不支持回查的写入结果未知即暂停。

## 4. 外部网页操作专项（W批）

### 4.1 观察与定位

新增受控WebAutomationService，主进程解析真实目标，按需接入Electron/CDP窄命令或专用网页适配器；不向网页加宿主特权preload，不向模型开放evaluate、原始CDP、任意SQL/Shell或全局调试端口。与DT证据、剪藏共用受控连接租约协调，不能attach/detach别人的会话。普通网页、内部壳、GenOffice和工作台使用不同适配器，W批不能穿透后者。

PageTarget含profileId/workspaceId/windowId/tabId、实际origin、frameRef、documentRevision及captureId。观察返回限量可访问角色、名称、可交互状态和元素引用；密码值、Cookie、存储、隐藏凭据不返回。ElementRef是不透明引用，绑定目标/文档/可选容器及失效时间；导航、reload、frame替换和目标元素身份改变后失效，不把旧nodeId或坐标当永久ID。DOM更新仍需重检角色、名称、可见、可用及唯一性。

优先语义角色/标签与受控选择器，必要时截图只限已授权区域且独立外发审批。封闭Shadow DOM、跨源frame、canvas和远程桌面等目标按能力探测明确unsupported或handoff；不能自动扩大frame/origin范围。坐标模式是另行评测的候选，不作为首个W批的可靠兜底。

### 4.2 拟工具与最小schema

所有请求外围含ToolInvocation、targetRef及expectedDocumentRevision；返回observationRevision/receipt和状态，不接受模型传入任意webContentsId。原生模块工具与下列web.*命名分离。

| 动作ID/拟工具                   | 专用输入与返回                                                 | 权限与核验                                    |
| ------------------------------- | -------------------------------------------------------------- | --------------------------------------------- |
| W-observe / web.observe         | frameRef、范围、maxNodes/maxBytes → 语义树/元素引用、截断标志  | R；限域/限frame，外发单独授权                 |
| W-locate / web.locate           | role/name/受控selector、容器引用 → 唯一ElementRef或AMBIGUOUS   | R；多目标不选第一个猜测                       |
| W-click / web.click             | elementRef、预期效果 → 操作回执和新观察                        | N/W/H依实际后果；点击提交/付款不能归普通导航  |
| W-fill / web.fill               | elementRef、明确文本或秘密代理引用、replace模式 → 脱敏字段状态 | W；逐字段类型、值与表单范围审批，敏感值不回显 |
| W-select / web.select           | elementRef、选项引用 → 当前选中项                              | W；选项仍在目标文档内                         |
| W-scroll / web.scroll           | 容器、方向、限量距离 → 位置及观察                              | N；滚动可能加载数据，范围及请求预算仍生效     |
| W-wait / web.waitFor            | 条件白名单、timeoutMs → satisfied/timed_out及证据              | R；无任意JS，使用任务总deadline，禁止无限等待 |
| W-dialog / web.handleDialog     | dialogRef、明确accept/dismiss及prompt输入 → 关闭结果           | W/H；匹配当前对话，不能自动同意系统权限弹窗   |
| W-upload / web.upload           | elementRef、用户选定attachmentRefs及内容摘要 → 字段/提交状态   | H；文件读取与向站点上传分别授权，无任意路径   |
| W-download / web.expectDownload | 明确触发步骤、目标目录引用 → downloadId                        | W/H；通过下载管理器核实际文件，不执行下载内容 |
| W-submit / web.submitApproved   | formRef、字段摘要、最终目标/账号、审批引用 → submissionReceipt | H；确认后改参失效；网络响应不独自证明业务完成 |
| W-verify / web.verify           | 已声明的域名、可见结果/业务对象判据 → passed/failed/unknown    | R；确认结果与目标身份，不能凭模型一段文字完成 |
| W-handoff / web.requestHandoff  | 原因、任务快照、允许的后续范围 → 交接引用                      | 用户完成后重新观察及重授权，不自动接收凭据    |

浏览器导航仍优先用原生tab工具；点击后打开新标签由主进程关联opener与操作键，确认目标origin是否获准，再继续，不能追随无关弹窗。URL变化和DOM显示均可能滞后，工具必须声明等待dom-ready、特定元素或业务结果中的哪一种，超时保留证据缺口。不能把所有GET视为无副作用。

### 4.3 执行 恢复与用户接管

网页写入按观察 → 规划效果 → 确认最终字段与目标 → 执行单步 → 有界等待 → 重观察/业务回查核验循环。导航许可不包含任意站点写入，工具风险由宿主及站点适配规则决定，模型不得给click自填低风险。无法判定副作用的点击先暂停确认。幂等仅采用站点实际支持的操作键；没有支持时提交超时为outcome_unknown，禁止刷新/再点自动重试。

网页登录、验证码、系统授权或支付确认进入handoff，任务使用paused+handoff_required，不新增第十种任务状态。handoffRef绑定任务/目标/版本，暂停后停止自动输入和页面采集；恢复时用户明确继续，重新校验登录账号、origin/frame、文档、许可、预算和待提交字段。秘密由可信输入代理或用户直接填写，不能放入普通模型消息、任务事件、记忆或截图。网页中“已授权”等文字不能产生批准。

取消阻止后续动作并尽力停止等待/网络；已经提交的请求保留unknown或已核验结果。弹窗关闭、窗口关闭、会话过期、休眠唤醒都需新观察；恢复任务不恢复失效ElementRef。上传或提交后的外部内容无法靠本地取消撤回。任务队列按目标资源协调，用户手动编辑优先触发版本冲突，不用一把全局浏览器锁阻塞普通浏览。

W批先支持可重复的静态表单与同源动态站点，再按站点/能力矩阵扩大；每项记录OS/Electron/站点测试版本与最近验证时间。没有“任意网站100%成功”的发布声明，未测frame/控件类型在能力查询中明确不可用。

## 5. 独立工作台与系统集成边界

GenOffice、Pi、Harness各自提供版本化能力探测、只取选中内容的读取、提出变更/任务、可信审批交接、提交、取消、状态查询和结果收集协议。交接引用含sourceTaskId、目标工作台/会话、允许资源、预算、expiresAt、argsHash及操作键；两侧分别授权，不沿用某一侧“最高权限”。返回产物稳定引用、版本和真实结果；普通聊天回复不算执行回执。

GenOffice按六编辑器分别列读取/修改/保存/导出/撤销矩阵；未提供保存回执/版本锁时只能预览建议或打开原生编辑器。Pi/DSH生命周期已有启动基础不代表已有任务API；任务提交需新增专属协议，不恢复ai.*别名，不从它们的数据库直接读会话。工具执行权只有一个实际所有者，跨工作台调用需trace和调用深度预算，禁止二丫与工作台相互递归派单。部分完成逐产物恢复，不能跨库假装原子回滚。

更新安装、文件关联、数据迁移、退出、Cookie导入、账号认证等F批操作先形成可信确认/原生交接；安装与迁移前有恢复点，执行中停止新任务，回读实际结果，重启后对账。凭据、系统权限和原生对话框的人工动作标handoff，不算自动已覆盖。不能用“全能力”要求模型读取明文密钥或操作操作系统任意应用。

## 7. 全局覆盖口径与变更维护

设U为基线版本/平台全部现有用户业务动作（去重并展开分支），A为已登记支持自动或审批执行的目标子集，V为其中已通过本版本验收的动作，H为仅可人工交接的动作。规划、unsupported、unknown及尚未验收动作仍留在U并可见，不能因本期没做而移除。仅真正内部协议、重复入口别名和源码确认的未实现供应商桩不进U，排除需逐项理由与证据。未来新增功能另记录新增项后纳入新基线。

- 全浏览器自动执行覆盖率 = |V| / |U|，同时公布H、unknown、unsupported、未实施及未验收清单；人工交接不计入V。
- 本期承诺覆盖率 = 本期验收动作 / 本期承诺动作，仅表示阶段完成，不能冒充全局覆盖率。
- 有界目标达成率 = |V| / |A|，说明明确支持范围内的完成度；A的缩小须有版本化产品决定，不能为提高指标临时缩分母。
- 场景成功率继续按12固定集统计，动作全覆盖不保证任意多步场景成功，反之场景高分也不证明动作全覆盖。

完整接入设计的退出条件是每项有接入决定、合同模式、任务与验收；完整运行能力的退出条件则是U中目标动作实际实现并验证。若仍保留H或unsupported，产品只能说明“已覆盖列明范围，部分操作需接管”，不能无条件宣称全部自动操控。当前manifest尚待ALL-01实施核验，覆盖率为待测，不填0或100等猜测值。

实施时新增 `erya-action-manifest`（最终路径由ALL-01确定）与源码入口反查检查，检查actionId唯一、工具/策略/验证器/测试引用存在、别名归属、阶段状态和平台证据；动态菜单/供应商方法人工复核，不以静态正则证明完整性。每次浏览器功能新增/删除/改合同，同批更新manifest和回归集；新动作默认unknown并阻止“全覆盖”发布，不阻断普通浏览器发布。检查脚本是待实施要求，不能写成当前verify已有门禁。

## 8. 验收设计与本轮交付记录

每个展开动作至少覆盖正常结果、拒绝/撤权、资源版本变化、超时/未知和取消；读工具无写入，写工具回读真实领域结果，补偿也需授权。内部入口验证不能被模型直接调用；特殊人工动作验证不会被计入自动覆盖。WEB使用本地可控站点和独立真实站点样本，覆盖导航、frame、SPA、弹窗、上传/下载、恶意页面、手动编辑、会话到期与接管恢复；稳定CI与真实站点结果分别报告。系统集成在隔离Windows档案测试，不能以Linux单测代替真实系统行为。

产品级故事至少包含：跨窗口整理标签并保存书签；下载暂停恢复后核文件；翻译和剪藏后回读产物；编辑本地文件遇到外部修改；设置更新与撤销；画布媒体和日历恢复；网页筛选并填表确认提交；登录接管后继续；工作台交接后收集产物。每个故事关联具体actionId与正常/拒绝/故障出口，禁止仅断言模型说“成功”。
